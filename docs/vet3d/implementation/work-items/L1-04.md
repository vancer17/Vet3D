本期支持 **单资产不可变登记**。多文件逐件提交，允许部分完成；不建立批次身份、成员预留、未完成登记意图、批内派生图、报告声明仓储或跨文件事务。报告仅可作为普通文件字节保存和登记，不解析报告内容，不写入业务验收事实。

Blender 工作场景、日常保存、自动保存、临时导出及调试截图属于后续执行的可变工作文件。只有选定并冻结的候选才进入受信接收与不可变登记；`store_new` 不是 Blender Save API。当前没有执行器、模型版本发布、current/latest 指针、BFF API、租户权限、多进程文件服务或自动清理平台。

## 3. 输入、输出与权威事实

| 事实或输入 | 唯一含义 |
| --- | --- |
| ArtifactIdentity | 原 ArtifactId 及所属 WorkspaceId；文件接收前由调用方生成并保留。 |
| LocatedArtifact | 既有身份、确切 FileReference 和相对位置的组合；不新增另一份资产描述。 |
| ImportOrigin | 可选的原出处文本；未知与已提供说明不同，不由标签推断真实照片、合成视图或派生关系。 |
| 资产行存在 | 单件事务已提交；没有 pending／registered／ready 等镜像字段或额外登记时间。 |
| resolve 返回 None | 对指定身份成功查询但没有登记；文件存在不能改变此结果。数据库异常不能降级为空。 |
| FileObservation | 本次实际读取结果；文件丢失或内容改变不回写原登记。 |

仓储实例固定工作区。首次登记必须关联已提交的工作区；拒绝只有创建意图的工作区。已知产物属于其他工作区时明确拒绝，不作为本工作区“未登记”处理。相对位置在同一工作区不能重复绑定多个产物。

同一 ArtifactId、归属、内容、位置及可选出处全部相同才允许读回。任何改参拒绝覆盖，包括后补或删除出处；修改后的内容应使用新的产物身份。原登记重放只核对已提交字段，不重新证明文件存在；使用前仍需独立观察并核对内容。SQLAlchemy 表模型是 Schema 的唯一来源，字段均有中文说明，业务不能直接访问表或 Session。

现有 L0 的 AttemptOutput、Derivation、ModelVersionIdentity、ReportAssessment 继续保持各自语义；本项没有持久化它们，也不从来源文本、文件名或登记成功推导这些事实。

## 4. IoC 与公开入口

| 公共入口 | 归属与行为 |
| --- | --- |
| artifacts.ArtifactRepository | 同步窄 Protocol：get、register、get_origin；只保存元数据，由 artifacts 拥有，不接收文件观察布尔值。 |
| artifacts.validate_registration | 无副作用的固定归属及出处关联检查，复用已有校验。 |
| artifacts.ArtifactRegistrationConflict | 同身份登记字段不一致的契约错误；不产生另一套状态。 |
| adapters.SqliteWorkspaceRepository.artifacts(workspace_id) | 在控制线程绑定 SqliteArtifactRepository；共享原 Engine、短 Session 事务及关闭寿命。 |
| adapters.SqliteArtifactRepository | 显式继承 ArtifactRepository；不读取文件，不拥有另一个根或线程。 |
| bootstrap.initialize_workspaces／open_workspaces | 在原 root 参数外接受 `max_file_operations=2`，非布尔正整数；这是实际部署配额，不是业务模式或架构开关。 |
| await runtime.artifacts(workspace_id, *, max_file_bytes) | 核对已提交工作区并绑定固定文件范围，返回具体 WorkspaceArtifacts。 |
| await catalog.register(artifact, reference, *, origin=None, timeout_seconds=5.0) | 原登记精确读回；首次登记先实际观察文件，再提交一条记录。位置由已有适配器派生，不接受任意主机路径。 |
| await catalog.resolve(artifact_id) | 返回原 LocatedArtifact 或明确未登记；实现已有 ArtifactAccess。 |
| await catalog.get_origin(artifact_id) | 返回原出处；空值不能独立判断是否登记。 |
| await catalog.observe(location) | 先核对已登记位置，再读取实际字节；返回既有 FileObservation，不比较或改写原摘要。 |

WorkspaceArtifacts 显式实现 ArtifactAccess，并由 Bootstrap 注入 ArtifactRepository、ArtifactFileStore 和资源所有者；ReconstructionService 继续只依赖原 ArtifactAccess，不导入数据库或宿主。其可信登记入口不直接开放给 LLM；Tool 和 BFF 接入以后按调用方权限提供范围受限的消费者。跨包调用仅使用 `__init__.py` 公共导出。

控制线程只运行工作区创建／读取、根验证、绑定及短数据库操作；一个控制调用在途，无内部排队。文件复制和哈希使用独立有限线程，每次独立打开描述符，起止核对冻结的根及工作区对象。文件配额占满时新文件调用立即报 WorkspaceBusyError，仍可进行短元数据操作。单个长文件操作不会使其他工作区的全部存储调用报忙；此配额也不限制未来 Blender 任务并行数。

根所有权仍由唯一宿主持有；第二个根所有者被 flock 拒绝。等待取消不释放实际在途名额。关闭停止两类新调用，排空全部实际操作，再在原控制线程关闭库和根。没有将 SQLite Session 或根的可变目录观察字典交给文件线程；文件作用域不构成不可信代码执行沙箱。

注册等待期限覆盖读回检查、实际观察和短提交；None 由调用方管理期限。ArtifactAccess 的 resolve／observe 沿原协议无额外超时字段，可由上层整体期限取消等待。日志沿现有 Bootstrap 有界输出，关联工作区、产物和固定操作；晚期异常由宿主观察一次，不建立独立日志系统。

## 5. 正常流程与副作用

| 步骤 | 校验与操作 | 副作用和交接 |
| --- | --- | --- |
| 1 | 可信装配打开根及已提交工作区，固定文件预算和端口范围。 | 不建立资产记录或业务任务。 |
| 2 | 沿 L1-02 用原身份接收确切字节；保留原引用及位置。 | 文件不可覆盖；保存成功只形成文件事实。 |
| 3 | register 校验原身份、内容、归属与出处，查询已有记录。 | 相同登记只读回；改参拒绝；未登记才继续。 |
| 4 | 在文件线程重新观察原位置，用 require_matching_file 核对内容。 | 不持有数据库事务，缺失／不匹配不登记。 |
| 5 | 控制线程用单件短事务再次核对工作区和原身份，提交唯一记录。 | 已提交资产可由 resolve 读取；没有批次可见性门槛。 |
| 6 | 上层解析确切资产并重新观察，按自己的输入规则使用。 | 生成服务逐项核对请求文件后才登记生成意图并提交；部分资产登记不会绕过输入守卫。 |

文件接收与元数据事务没有跨系统原子性。当前依赖受信服务独占管理不可变目标；文件在登记之后仍可能因外部故障失效，使用方必须再核对。报告文件走同一路径，文件登记不写入 ReportAssessment，也不自动放行版本发布。

## 6. 失败、取消与恢复

| 情况 | 当前处理和恢复出口 |
| --- | --- |
| 关联、预算、归属或原字段错误 | 拒绝，不修改已有记录或字节；仓储异常继续传播。 |
| 文件未写完或内容不匹配 | 首次登记失败；已保存的候选保留，不替换预期指纹。 |
| 文件已写而从未登记 | resolve 仍为空。调用方保留原身份和引用时，可重新观察后显式登记；不会重复制或自动认领。 |
| 等待在文件观察阶段取消／超时 | 实际只读 I/O 继续至终结，但协程不会随后自动提交数据库；关闭仍排空该操作。 |
| 短数据库操作已提交到控制线程后取消／超时 | 实际操作可能提交；用原 ArtifactId 查询，不依据等待结果判定没有登记。 |
| 数据库提交失败、提交结果或回执不明 | 保留已接收文件，按原身份查询；没有行才显式重验并登记。禁止改用新身份掩盖未知提交。 |
| 已提交登记后文件丢失或改变 | 原登记与出处不变，observe 返回实际事实；原登记重放仍可读回，但不证明当前可用。 |
| 同根多文件及同目标竞争 | 文件线程有限并行，短元数据操作独立；同目标始终禁止覆盖，多件允许部分完成，不回滚其他已登记资产。 |
| 进程退出／重启 | 重新装配同根同库，仅读回已提交记录；保留确切原引用后可显式处理未登记文件，不恢复未完成批次或执行作业。 |
| 丢失原身份、未知临时文件或陌生目标 | 不扫描认领、不自动清理，不以名称或最新文件猜测原登记。 |
| 整个工作区目录缺失或原对象被替换 | 原数据库行保留；新 `artifacts()` 绑定沿文件作用域核对而拒绝，不能借重新装配创建空目录。已绑定消费者仍可解析原行，但实际观察失败；此限制不等于记录丢失。 |
| 缺库、损坏、布局或 Schema 不符 | 保留原现场并拒绝打开；不自动建空库、补表或迁移。 |

本期初始化建立工作区和资产表，重开严格核对同一 SQLAlchemy 元数据，包括真实外键及约束；每条连接启用并回读外键设置。仅有旧工作区表的库会被明确拒绝，不修改其中原数据。实施时在当前仓库与可见配置中没有发现需保留的产品数据库，不将此结论扩大至外部机器；以后发现真实保留数据再单独设计迁移，不能直接清空旧根。

本项没有未完成资产意图可供重启续做，也没有持久化任务、会话、执行关联、版本指针或验收声明。它不扩大 L0-05 的外部提交恢复能力。普通进程退出和 fsync 测试不能替代断电、设备故障或不可信执行隔离实测。

## 8. 完成与上层放行

本期接口、真实存储、恢复、并行及公开消费者已完成第 7 节验证。放行对象是按确切身份读取持久资产及实际字节的上层消费者；L2-03 可在此基础上定义执行账本所需的真实记录，L3-02／L3-04 可组合导入、查询、候选接收与后续发布契约。没有自动获得那些条目的任务恢复或发布能力。

[L1-05](L1-05.md)已完成其限定的配置、诊断与 Docker 范围。Blender／动态脚本执行、LLM、BFF 接入及 M1 仍未放行。首次开放不可信执行继续满足 [L1-01 联合条件](L1-01.md#开放不可信执行的必需条件)，不能把整个工作区、注册库、配置或凭证挂入执行环境。资源限制不得反向改变业务动作或验收资格。
