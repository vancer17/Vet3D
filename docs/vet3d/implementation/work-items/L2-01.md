## 3. 输入、输出与权威事实

### 原资源与要求

可信调用方传入一个原 `ResourceReference(snapshot, key)`。Bootstrap 沿同一固定快照收集根资源的完整依赖闭包，服务在启动进程前拒绝缺失、重复、混合快照、成环或无关声明。闭包没有任何脚本要求时拒绝检查，不把空集合当作环境通过。

`InterpreterRequirement` 仍是唯一要求类型。L1-03 接受描述文本；本消费者只解释以下有限子集，不升级或重写旧清单：

| 声明 | 当前核对语义 |
| --- | --- |
| `runtime = Python` | 精确名称；检查对应配置路径启动的 Python。固定依赖名仅 `sqlite3`。 |
| `runtime = Blender Python` | 精确名称；检查配置 Blender 内嵌的 Python。固定依赖名仅 `bpy`、`mathutils`。 |
| `version = X.Y` | 非负十进制规范版本，无前导零；主、次版本相同，允许补丁差异。 |
| `version = X.Y.Z` | 三段精确匹配。Blender Python 的该值始终指内嵌 Python，Blender 程序版本独立观察。 |
| 空依赖元组 | 没有声明额外依赖，仍须取得版本和 CPU 自检证据。 |
| 其他名称或文本 | `indeterminate`，保留 `unsupported_runtime`、`unsupported_version` 或 `unsupported_dependency:原值`；不启动该声明的探针。 |

`未执行`、`标准库`、版本范围、pip 约束或大小写别名均不自动解释。依赖文本不能变成 import、shell、安装或任意脚本参数。产品内置固定探针随 wheel 发布，不属于用户可替换的资源入口。

### 单次证据和关联

- `EnvironmentObservation` 保存实际 Python／Blender 三段版本、固定检查成功的依赖名、CPU 观察、平台、机器架构及本次实际启动的绝对候选路径。路径不构成二进制指纹，也不证明未来同路径仍是同一程序。
- `ResourceEnvironmentCheck` 只存原脚本 `ResourceDescription` 和证据：实际观察、`ProbeFailure(reason)` 或无法解释声明时的空值；不重复存快照、要求或结果状态。
- `issues`、`status` 由这些原事实单向派生：`satisfied`、`mismatch`、`indeterminate`。没有有效观察不能判版本不符，更不能通过。
- `EnvironmentReport` 保留调用根引用、L1-05 原 `runtime_id`、本次完成时的 UTC 时间和逐项证据。汇总状态同样派生：已知不满足优先，其次不可判定。具体缺口不会被汇总抹掉。
- 同一检查闭包内，相同 runtime 共用本次一次观察；下一次检查重新探测。无跨检查缓存、TTL、latest 指针、持久 ready 或新 Job／Attempt。

资源已安装、解释器已配置、有效环境观察、资源文件当前字节可读是不同事实。本项 pin 核对清单，不执行或逐个重新读取所有资源文件；交接受管资源时仍按 L1-03 的读取契约核对所需内容，不将本项报告作为永久可读保证。这项资源完整性要求不覆盖 Agent 临时脚本和逐次工具调用，报告时间也不是有效期、授权或发布资格。

## 4. IoC 与公开入口

| 所有者 | 接口和装配 |
| --- | --- |
| `operations` | 唯一 `ProbeLimits`、观察／失败／核对记录、`EnvironmentProbe.observe(runtime)` 和具体 `EnvironmentCheckService`。服务不导入 Settings、Bootstrap、路径定位器或具体进程实现。 |
| `adapters` | `LocalEnvironmentProbe(candidates, limits=...)` 显式实现端口，只支持产品固定探针；提供原所有者 `aclose()`。 |
| `bootstrap` | 从 Settings 一次注入候选和预算，组合实际资源宿主、探针、检查服务及原运行关联；不把配置容器交给业务模型。 |
| `host` | 复用 `vet3d-operations-probe`，默认仍是有限存储装配；显式参数才进行环境核对，完成后退出。 |

跨包只使用 `__init__.py` 公共导出。稳定的检查服务和装配对象直接实现，不创建第二套镜像接口。业务动作、生成计划、验收和发布守卫均不消费环境配置或核对状态。

配置仍遵循 [L1-05](L1-05.md) 的来源和路径规则。新增 `environment_probe` 直接解析成唯一 `ProbeLimits`：`timeout_seconds=30`、`terminate_grace_seconds=2`、`max_output_bytes=65536`、`max_concurrency=2`，均为非布尔正整数。这些值只限制部署资源，不在每轮 Command 重复声明，不提供内部架构开关。

已安装快照的有限命令：

```bash
vet3d-operations-probe --config /path/to/config.yaml \
  --check-environment RESOURCE_KEY \
  --snapshot-sha256 MANIFEST_SHA256 --snapshot-size MANIFEST_BYTE_SIZE
```

三项资源身份参数必须一起给出，不能与 `--initialize` 组合；没有隐式安装、latest 或自动修复。有效报告输出 JSON；满足且诊断交付成功时退出 0，缺口或基础设施故障为 1，参数错误为 2，取消遵循既有 130／143。JSON 是有限运维回执，不是已选定的 BFF API。诊断失败不改写报告中的真实观察，但命令可以报告交付故障。

## 5. 正常流程与副作用

| 顺序 | 行为与门槛 | 实际副作用 |
| --- | --- | --- |
| 1 | 打开既有存储和诊断；明确原资源身份并 pin，收集和校验闭包。 | 有界诊断；不创建空库修复失败。 |
| 2 | 检查声明是否可解释，按精确 runtime 查固定候选。 | 不搜索 PATH、不 fallback、不下载或安装依赖。 |
| 3 | 有空闲实际额度才准入；每次使用独立临时目录。 | 写入产品固定 payload；没有用户素材或资源脚本进入该目录。 |
| 4 | `create_subprocess_exec`、无 shell；Python 使用隔离参数；Blender 后台、factory startup、关闭 autoexec、固定线程及 Python 异常退出码。 | 最小环境不继承凭据、用户 Python 路径或代理；不构成操作系统隔离。 |
| 5 | 同时读取双管道、累计总输出限额；在实例期限内核对唯一结构化记录和进程退出。 | 输出仅在内存限额内保存，不把任意 stdout/stderr 转储到日志。 |
| 6 | 沿原进程组清理并确认终止、排空管道，再释放临时目录及额度。 | 正常退出也清理同组残留子进程；清理完成前不交付观察。 |
| 7 | 以原要求和真实证据派生逐项及汇总结论。 | 返回有限报告，记录关键关联；不登记资产、验收或发布。 |

Python 自检包括微型整数计算与内存 SQLite 查询；Blender 自检包括临时内存网格和向量运算，不保存 `.blend`、不渲染、不测试 GPU。部署使用官方 Blender 4.5.16 LTS Linux x64 固定归档及 SHA-256，实际程序和内嵌 Python 版本仍由探针观察。

## 6. 失败、取消与恢复

| 情形 | 当前行为与恢复边界 |
| --- | --- |
| 身份或闭包错误 | 启动前拒绝；修正输入后显式重新检查，不改变原快照。 |
| 候选未配置／无法启动 | 保留具体失败原因，没有有效观察；不换宿主 Python、不安装、不重试。 |
| 未支持声明 | 明确不可判定，不执行该声明；资源维护方必须在新快照明确可核对的要求。 |
| 版本、依赖或 CPU 不符合 | 保留实际观察及具体缺口，返回不满足；不放宽原要求。 |
| 非零退出、输出超限或协议错误 | 不交付有效观察；清理原组。退出码 0 不能替代唯一合法结构化记录。 |
| 创建进程期间取消／超时 | 保留原创建操作直到取得原句柄或明确启动失败，再沿该句柄清理；不启动替代探针。 |
| 已运行时取消／超时 | 原组 TERM、有限宽限、必要时 KILL，并确认原组无运行成员、管道排空；实际清理完成才释放额度。 |
| 清理失败 | 保留现场及句柄，实例拒绝新准入，关闭明确失败；仍关闭探针从未使用的独立存储和诊断，避免遗留无关根锁或非守护线程。不把未停止的进程标为已取消或已释放，需要部署侧处理原进程现场。 |
| 并发 | 每个探针独立进程／输出／临时目录；超出额度直接报忙，无无界队列。资源存储短操作不覆盖整个探测时长。 |
| 诊断故障 | 有界记录损失仍归 L1-05，不能跳过进程清理或改写真实观察；日志不是执行账本。 |
| 正常关闭／SIGTERM | 先停止探针准入，取消并排空原探针，再关闭存储和诊断；取消关闭等待不会取消实际关闭。 |
| SIGKILL、宿主断电 | 不保证 Python finally 执行；裸宿主可能残留进程／临时目录，需部署方清理。容器终止事实仅适用于实测容器边界。 |
| 进程重启 | 新运行关联下显式重新探测；不从旧日志、版本字符串或报告恢复 ready，不续接旧进程。 |

本期 Linux `/proc` 观察仅确认原受信进程组没有仍可执行成员；僵尸已经终止但回收属于父进程／init。该机制不阻止不可信代码另建会话、访问宿主文件或网络，不能代替隔离。等待取消与真实 I/O 停止仍分别处理。

常规本机复验命令：

```bash

```

这些测试不会下载 Blender；真实 Blender 和两套部署环境的正向检查必须另外按本卡及 Docker 导航明确执行，不能只从测试数量推断。
