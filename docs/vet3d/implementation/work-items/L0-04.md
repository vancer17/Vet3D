## 3. 输入、输出与权威事实

以下记录均使用具体类型、`frozen=True` 和 `slots=True`。字符串诊断、章节、用途及策略引用要求非空白且可编码为 UTF-8，原文保留；集合使用指定的 tuple 或 frozenset，不隐式转换。校验错误保持所属包的 `ValueError` 子类，类型错误为 `TypeError`，已有下层异常不统一包装。

### 执行与独立诊断：`vet3d.execution`

| 公开类型 | 当前语义 |
| --- | --- |
| `AttemptActive(attempt_id)` | 执行端确认仍活动；不细分供应商队列和阶段。 |
| `AttemptSucceeded(attempt_id)` | 执行端确认成功，不确认其他六类事实。 |
| `AttemptFailed(attempt_id, reason)` | 执行端确认失败，不声明没有副作用或可以重试。 |
| `AttemptCancelled(attempt_id)` | 执行端确认已取消，不等于请求取消。 |
| `AttemptObservation` | 上述四种确认观察的唯一联合。 |
| `QueryUnavailable(attempt_id, reason)` | 此次查询没有取得可信新观察；不替换旧观察。 |
| `SubmissionUnconfirmed(attempt_id, reason)` | 已尝试提交但受理尚未确认；不能推导活动、拒绝或失败。 |
| `WaitEnded(attempt_id, reason)` | 等待结束；唯一 `WaitEndReason` 为 `DEADLINE` 或 `CANCEL_REQUESTED`，均不表示执行端终止。 |
| `CapabilityUnavailable(reason)`、`InputInsufficient(reason)` | 执行前不能满足能力或输入要求，不附加尚不存在的尝试。不构成能力配置，也不承诺永久不支持或自动重试。 |

所有 `attempt_id` 使用既有 `AttemptId`。`validate_attempt_fact(fact, *, attempt)` 只核对原尝试，不复制或解析全部祖先关系。执行前拒绝不属于此入口接受的事实。

L0-05 已扩展此关联入口以接受独立取消请求回执，具体类型和作用由 [L0-05](L0-05.md)唯一维护；回执不进入本卡的确认观察联合或终态对账。

`reconcile_observation(last, current)` 接受确认观察，`last=None` 表示尚无可信观察。调用方必须已经确认先后顺序；本函数不以墙钟、网络到达顺序或供应商字符串猜测新旧。活动可继续活动或进入终态；终态只接受同一具体终态类别，相同失败类别可更新诊断。错尝试、跨终态或终态回到活动均拒绝；成功返回 `current`。

`preserve_after_query_failure(last, *, failure, attempt)` 在核对关联后返回原 `last` 或 `None`。查询、等待和提交诊断不是确认观察，不能传给对账函数形成终态。`ExecutionContractError` 表达本包约束冲突。本项没有生成新尝试或批准重交的入口。

### 文件观察：`vet3d.artifacts`

`FilePresent(location, observed)` 保存 `WorkspaceFileLocation` 与实际观察的 `ContentFingerprint`；`FileMissing(location)` 表达已确认缺失；`FileUnavailable(location, reason)` 表达未能访问。三者构成唯一 `FileObservation` 联合，没有记录时不补造缺失事实。产物身份从位置取得，预期内容仍由已有 `FileReference` 唯一拥有。

`validate_file_observation(observation, *, reference, artifact)` 核对位置、文件引用及 `ArtifactIdentity` 的关联，允许记录观察与预期不符。`require_matching_file` 使用同一参数，只放行存在且指纹匹配的声明。两者不读取、刷新或解码文件；不提供“现在仍存在”或“图片有效”的保证，异常复用 `ArtifactContractError`。

### 报告和验收：`vet3d.assessment`

| 公开类型 | 当前字段及作用 |
| --- | --- |
| `ReportRequirements` | `contract_ref: str`、非空 `required_sections: frozenset[str]`，表达固定报告契约要求。 |
| `ReportAssessment` | `report_id: ArtifactId`、`contract_ref: str`、`sections: frozenset[str]`；章节声明可空，不重复保存完整标记或缺项。 |
| `AcceptanceScope` | `purpose: str`、`policy_ref: str`、非空 `required_checks: frozenset[str]`；表达当前交接的冻结业务要求。 |
| `AcceptanceOutcome` | `acceptance_id: AcceptanceId`、实际 `purpose`、`policy_ref`、`covered_checks: frozenset[str]`、`verdict: AcceptanceVerdict`、`explanation: str`；覆盖可空。 |
| `AcceptanceVerdict` | 唯一结论枚举为 `PASSED`、`REJECTED`、`INSUFFICIENT`、`UNSUPPORTED`；由生产者明确提供，不由证据数量或字段完整性计算。 |

`contract_ref`、`policy_ref` 是调用方提供的不可解析业务契约引用，须包含所需版本区分；不是运行时架构开关。本项不加载或认证这些契约，不验证同一个引用在跨调用中是否总能解析到相同规则。要求与生产者声明代表不同事实，允许不匹配。

| 入口 | 校验或派生范围 |
| --- | --- |
| `missing_report_sections(assessment, *, requirements)` | 先核对相同报告契约，再返回必需项与已声明章节的差集。 |
| `require_complete_report(assessment, *, requirements)` | 仅允许契约匹配且没有必需缺项，不附加验收通过。 |
| `validate_report_reference(assessment, *, reference, artifact)` | 关联确切报告内容引用和身份，不检查文件存在。 |
| `validate_attempt_report(assessment, *, output, attempt, job, task, reference, artifact)` | 进一步复用既有 `AttemptOutput` 和父链，不能拿另一尝试的同名报告替代。普通报告声明不被强制附加尝试字段。 |
| `validate_acceptance_outcome(outcome, *, acceptance, evidence)` | 精确关联 `AcceptanceIdentity` 和证据集合；允许不通过、覆盖不足或空证据。 |
| `require_accepted(outcome, *, scope, target, acceptance, evidence)` | 要求消费者的确切 `ReviewTarget` 匹配，实际用途和策略符合当前要求，显式声明通过、必需检查覆盖且有关联证据。 |

验收目标与证据引用仅由既有 `AcceptanceIdentity` 拥有，结果不再保存一份。`target` 是消费者本次要放行的对象，不是从结论反推的当前对象；文件子集、另一版本及不同目标类别都不能替换它。目标实体的归属解析仍使用 L0-02 的对应入口。

以上守卫只约束声明的必要条件，不认证报告解析正确、证据充分或模型评审正确；不会替调用方创建 `PASSED`。报告完整也可以伴随验收拒绝。`AssessmentContractError` 表达本包约束不满足。

### 发布、加载与保存：`vet3d.delivery`

| 公开类型 | 当前字段及作用 |
| --- | --- |
| `PublicationReceipt(attempt_id, version_id)` | 记录任务内发布操作和实际返回的 `ModelVersionId`；可为新版本或复用版本。 |
| `LoadReceipt(attempt_id, target)` | 记录本次加载操作与实际 `ReviewTarget`；不把选择、请求受理或旧画面当作加载完成。 |
| `SaveTarget(reference, destination)` | 指定源 `FileReference` 与接收端范围内唯一的目标关联文字。 |
| `SavedFile(artifact_id, destination, observed)` | 记录接收端确认的源关联、目标和实际 `ContentFingerprint`，允许观测内容不符。 |
| `SaveReceipt(attempt_id, saved)` | `saved: tuple[SavedFile, ...]` 是本次已确认项目，可空或部分完成，目标文字不可重复。 |

发布、加载和保存的 `AttemptId` 指各自实际操作，不能借用上游生成尝试。新执行才产生新尝试，查询、重复通知和同次操作进度不产生新身份。本项不定义无任务的独立桌面操作身份。

`validate_publication_receipt(receipt, *, attempt, job, task, version, family, files, artifacts)` 核对发布尝试的父链、实际版本、完整文件集合和任务工作区，不要求验收已经通过。发布复用时，调用方必须用实际返回版本重新核对适用结论，不能静默转移候选验收。发布确认不证明当前文件仍可访问。

`require_current_load(receipt, *, current_attempt_id, target)` 只进行操作与确切目标匹配。调用方负责在正确组件范围维护当前操作，并先解析目标归属；不能从回执反推活动指针。没有全局活动视窗、自动加载、截图或视觉证据生成，也不保证未来时刻仍保持该画面。

`validate_save_receipt(receipt, *, attempt, job, task, targets, artifacts)` 校验本次任务操作、源身份并集和已确认项目的对应关系；`targets` 为非空 tuple，目标关联唯一，同一源可以复制到多个不同目标，但同一产物不能绑定冲突的预期内容。允许空、部分确认和不匹配内容声明；要求之外的源或目标拒绝。

`require_complete_save` 使用相同参数，进一步要求全部目标均有确认，且实际指纹匹配预期。完整性由要求和已确认项单向判断，不另存总状态。`destination` 只是接收端的非空白 UTF-8 关联文字，不解析为路径、URL 或授权；真实目标安全及确认真实性由后续接收服务负责。下载链接、浏览器请求或 BFF 回包都不能替代接收端保存确认。错误使用 `DeliveryContractError`，下层异常保持原类型。

## 4. IoC 与暴露方式

各包只通过 `__init__.py` 暴露公共接口，跨包不导入内部方法。稳定结构和函数直接使用，不加镜像 Protocol、全局事实容器或服务定位器。依赖由调用参数传入；生产者和真实适配器在后续经 L0-05 端口与 Bootstrap 装配。

执行账本、文件访问服务、报告适配器、验收节点、发布服务及加载/保存适配器分别拥有真实事实。BFF、审计和日志只能投影这些事实，不反向决定动作协议或发布资格。既有纯校验异常、Demo 入口和退出码保持原语义，不增加兼容包裹。

## 5. 正常流程与副作用

1. 调用方提供具体事实、关联记录及冻结要求；构造时核对不可变结构。
2. 用对应校验核对原尝试、确切文件、验收身份或交接目标。
3. 消费方根据所需动作选择局部守卫，不要求所有事实组成一条成功链。
4. 守卫返回 `None`；缺项函数返回差集，对账函数返回明确观察。没有文件、状态库、通知或外部保存副作用。

执行失败但有产物、执行成功但报告缺失、候选不合格但已发布、旧版本后来不可访问均可以记录。只有声称某项交接已满足要求时才受对应守卫限制。正常 BFF 链路没有本项强制引入的人工审查或人工恢复状态。

## 6. 失败、取消与恢复

| 情形 | 当前边界及后续交接 |
| --- | --- |
| 参数或引用错误 | 抛出明确契约异常，不自动修正或创建替代身份。 |
| 活动、确认终态或查询失败 | 观察与诊断分别保留；调用方先确认先后顺序，再进行局部对账。 |
| 等待超时、取消请求 | 只结束等待事实，不确认执行停止，不撤销已知产物。真正终止确认由 L2 实现。 |
| 提交或交接回执不明 | 保留原关联及已知结果；没有自动重交入口。L2/L3 按真实幂等或查询能力对账，不能仅凭错误文字决定重提。 |
| 部分文件、报告或保存项目 | 独立保留已确认部分；完整守卫拒绝缺项，不删除已有记录。 |
| 终态矛盾、旧加载回执 | 明确拒绝用不匹配事实更新或放行；不使用墙钟猜测顺序或全局组件指针。 |
| 重启、并发或持久提交失败 | 本项没有账本或恢复句柄。后续 L1/L2 读回原身份和记录后再校验；新执行不是旧执行续接。 |
| 证据不足或验收不通过 | 不补造通过；后续节点按冻结业务策略修订或终止，保留诊断与候选。 |
| 预算耗尽但外部任务未决 | 后续编排停止等待时仍需保留未确认状态；本项不定义预算数值、轮询、成本计量或最终 BFF 状态。 |

本项不声称未知回执能够被找回、取消能够终止真实远端任务、文件替换是原子的或历史记录已经持久化。错误日志和堆栈由未来实际处理边界负责，纯契约不重复初始化或记录日志。


独立安装实际执行 `uv build --out-dir <临时目录>/dist`、`uv venv --python <本机解释器> <临时目录>/env`、`uv pip install --no-index --no-deps --python <临时环境解释器> <wheel>`，移除 `PYTHONPATH` 并从仓库外用 `python -I -B` 执行显式声明交接。外部 mypy 使用 `--strict --python-executable <临时环境解释器>` 核对公开类型；常规开发命令不替代这项验证。

测试只证明纯契约与声明交接，不证明真实文件、报告解析、执行停止、接收端保存、LLM 语义、动物质量或重启恢复。现有参考 CI 不能替代产品 Runtime 测试。不设置覆盖率门禁，不为镜像表示编写漂移测试。
