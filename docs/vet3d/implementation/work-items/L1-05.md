## 3. 输入、输出与权威状态

### 配置入口

`bootstrap.load_settings(config_file: Path, *, env_file=None, overrides=None)` 是唯一配置入口。必须显式选择一个存在的 YAML；dotenv 仅在显式选择时读取，不搜索 cwd 或父目录。使用标准 `YamlConfigSettingsSource`，依优先级合并：

**可信装配 overrides > 进程环境变量 > 显式 dotenv > YAML > 字段默认值。**

环境前缀为 `VET3D_`，嵌套字段分隔符为 `__`；例如 `VET3D_WORKSPACES__MAX_FILE_OPERATIONS=3`。来源按标准规则合并嵌套字段，未覆盖的同级值保留。YAML、dotenv、显式覆盖及预算中的未知字段拒绝；无关的普通进程环境变量按 pydantic-settings 行为忽略。没有启用文件凭证目录或 CLI 配置来源。

| 配置字段 | 实际消费者与语义 |
| --- | --- |
| `workspaces.root`、`max_file_operations` | 现有工作区存储根和文件线程准入；后者默认 2。 |
| `files.input_root`、`max_file_bytes` | 受信暂存输入根及文件消费者 I/O 上限；预算必填。 |
| `resources.root`、`source_root`、`limits`、`max_readers` | 安装位置、受信构建包来源、原 ResourceLimits 和读取准入；原四项预算必填，读取并发默认 2。 |
| `diagnostics.root`、`limits` | 独立诊断根和唯一 DiagnosticLimits；默认每条 16 KiB、每文件 8 MiB、3 个归档、512 个排队名额。 |
| `interpreters` | 不可变的 `{runtime, path}` 序列，默认空；同一 runtime 不可重复，不增设名称枚举或别名。 |

Settings 与嵌套配置冻结，预算直接复用原类型；允许环境变量十进制数字文本，拒绝布尔或浮点充当整数。相对数据及解释器路径统一相对 YAML 所在目录解析一次；相对 `env_file` 也相对该目录。禁止上级跳转、不展开 `~`、不跟随符号链接替换配置位置。五类数据根须词法独立、互不嵌套，不能覆盖配置文件或文件系统根。真实路径、权限和链接仍由各适配器核对；声明校验不是安全沙箱。

配置加载不创建目录、不回写 YAML／dotenv，不把值传入业务对象。仓库 `docker/config/*.yaml` 是用户可以另行复制和替换的维护模板，不是任务生成内容或 L1-03 的资源快照。业务结果继续使用原工作区与资产契约；诊断目录是独立的运行目录，不创建另一套业务 RunId 或任务输出树。

### 诊断与关联

`operations.DiagnosticReader` 拥有两个异步查询：`read_workspace(WorkspaceId, limit=100)`、`read_task(TaskIdentity, limit=100)`。`limit` 为 1～1000 的非布尔整数；任务查询同时按工作区和任务过滤。知道 ID 不构成授权，真实 BFF 授权尚未接入。

`DiagnosticRead` 返回最近匹配记录、是否超过请求上限、扫描窗口内损坏行数和当前 `DiagnosticStatus`。`DiagnosticRecord` 保存时间、日志级别、有界消息、不可解析的本次运行关联串，以及生产者实际掌握的原身份。身份由生产者结构化传递，不从消息、路径或 AttemptId 反查任务；工作区文件操作没有任务身份时保持为空。

`DiagnosticStatus` 仅含当前进程观察到的丢失数量与首次输出故障。它不是业务状态，也不是完整审计历史。空日志、无故障计数或日志中的成功文本均不能证明操作未发生、业务验收通过或版本已发布。日志记录 Schema 当前为 1；没有旧版消费者兼容分支。

`configured_interpreter(InterpreterRequirement)` 只按原 runtime 精确返回一个配置候选 Path 或 None，不搜索 PATH、不启动程序、不检查版本。宿主 Python 是实际进程自身，不另配置一份宿主解释器身份。资源存在、解释器位置已配置与真正可执行保持不同事实。

## 4. IoC 与暴露方式

| 所有者 | 当前职责与依赖方向 |
| --- | --- |
| Bootstrap | 加载 Settings、打开具体存储与诊断、注入预算和路径、安排关闭。`initialize_operations` 与 `open_operations` 是明确的存储操作，不是配置模式开关。 |
| Operations | 拥有诊断查询端口、记录和唯一诊断预算，不依赖 Pydantic、Docker 或文件适配器。 |
| adapters | LocalDiagnosticFiles 管理真实文件；沿用同包既有安全文件原语。没有诊断数据库、索引或第二个轮转者。 |
| application／领域包 | 继续消费原稳定端口，只记录已知事件；不导入 Settings 或 OperationsRuntime，不依据诊断反向决策。 |
| host | 非交互有限 CLI 加载配置、处理 SIGTERM／SIGINT、交付机器摘要，不提供模型工具或 HTTP。 |

跨包仅由 `__init__.py` 公共导出引用。稳定装配直接实现；可替换读取边界使用 DiagnosticReader，真实实现显式继承。现有 `configure_logging()` 仍服务两个有限演示命令，但活动持久诊断存在时拒绝替换其处理器；没有运行时新旧架构开关。

OperationsRuntime 持有已打开的 workspaces、resources、diagnostics；`files(workspace_id)` 和 `artifacts(workspace_id)` 将配置预算注入已有入口。取得这些入口前的授权由可信宿主负责。向生成服务注入的是原 ArtifactAccess，不是 Settings 或整个运行容器。

## 5. 正常流程与副作用

| 顺序 | 实际行为 | 副作用与交接 |
| --- | --- | --- |
| 1 | 显式加载并冻结配置。 | 无存储副作用，配置错误在打开资源前拒绝。 |
| 2 | 打开诊断根、取得唯一所有权并启动有限后台线程。 | 当前用户拥有的 0700 目录、0600 普通控制／日志文件；拒绝链接、不明内容和第二个写入者。 |
| 3 | 显式初始化或重开工作区与资源宿主。 | 消费原 L1-01～04 接口；重开失败不回退初始化。 |
| 4 | 可信调用方取得文件／资产端口、资源读取及诊断端口。 | 模板只读，素材和资产按原规则保存；日志不能创建业务记录。 |
| 5 | 事件有界编码后非阻塞入队。 | 默认记录 INFO 及以上；保留必要异常帧和身份，不格式化任意对象或转储 Settings。队列同时容纳有界读取请求，满时查询明确报忙，事件累计损失。 |
| 6 | 唯一线程追加、轮转及扫描固定保留窗口。 | 活动文件加固定数量归档，总字节上限由两者单向派生；单行包含换行且保持合法 UTF-8 JSON。后台镜像到 stderr，Docker local 驱动独立管理该输出。 |
| 7 | 停止上层生产者后关闭运行容器。 | 工作区、资源实际工作排空后记录停止事件，随后诊断停止准入并排空，再释放文件及锁。 |

文件日志使用固定 `events.jsonl`、有限编号归档和 `writer.lock`，没有按任务无限创建文件。日常轮转覆盖保留窗口内最旧归档，不删除未知内容。单个线程只管理自己的文件；应用不访问 Docker socket、注册库日志索引或外部收集服务。

开发、生产仅有 `docker/compose.dev.yaml` 与 `docker/compose.prod.yaml`，共用一个 Dockerfile。生产安装 wheel，开发使用镜像内虚拟环境和只读源码挂载；数据目录分别准备。用户配置只读挂载，服务不在入口递归 chown／chmod。当前默认命令有限运行后退出，没有常驻健康接口或自动重启循环。具体命令和绑定目录准备只在 [Docker 导航](../../../../docker/README.md)维护。

## 6. 失败、取消与恢复

| 情形 | 当前行为 |
| --- | --- |
| 配置字段、预算或目录关系无效 | 拒绝装配，不创建存储。CLI 不转储配置输入值或潜在凭据；已知敏感值不额外引入扫描框架。 |
| 诊断启动失败 | 不启动业务；失败原因在尚未接管日志的装配边界记录。不会放宽目录权限或绕过根锁。 |
| 两类存储部分初始化成功 | 已创建内容保留，资源所有者释放；没有跨根原子初始化。核对各根后，由可信部署端通过原条目入口补齐确实缺失的存储，再重开；不能盲目重跑整体初始化、删除现场或自动修复。 |
| 日志编码、队列或写出失败 | 当前状态明确报告损失／首次故障，使用独立可用的 stderr 提示；首次文件写入故障后停止该进程的文件追加，后续记录累计丢失，可用 stderr 仍接收镜像。不从业务调用抛出输出故障，不撤销登记、不取消生成、不重试外部提交。由 Operations 处理故障后关闭／重开，不在可能损坏的尾行继续盲目追加。 |
| 读取队列满、文件丢失、权限变化 | 分别明确报忙或读取故障；不是空结果。损坏／尾部不完整行在窗口中计数，不补造记录。 |
| 等待取消或超时 | 读取已提交时其有限 I/O 继续并被观察；关闭等待取消不提前解除所有权，仍可再次等待原关闭。期限由宿主等待者设置，不表示线程被杀死。 |
| SIGTERM／SIGINT | 有限 CLI 取消原等待，并在事件循环退出前等待实际关闭；分别返回 143／130。没有正在执行的 Blender 或远端任务可供本项取消。 |
| 正常关闭 | 尽力同步活动文件、排空已接收事件，再释放所有者；关闭返回实际诊断损失，不能把正常业务完成等同于完整日志。 |
| 强制终止、断电 | 可能丢失内存队列或留下不完整尾行，不提供零丢失承诺。重开将非空旧活动文件转入归档，读取旧保留窗口；不恢复原线程、执行句柄或未完成业务任务。 |
| 跨进程重开 | 新运行关联串，原资产按 L1-04 重读；保留日志能查询，原进程内丢失计数和首次故障不跨重启持久化。 |
| 缩小日志预算 | 原文件超出新单文件预算或旧归档超出新数量时拒绝，不自动删改历史来使启动成功。需由运维明确处理保留数据。 |

持久诊断不是执行账本。日志中的 Attempt 关联不能支撑进程重启后的续查或自动重交；L0-05 的内存恢复边界没有因此扩大。目录、配置、资源和 Docker 的可用性均不授予发布资格。

本轮环境为 VMware Debian 13、仓库所在 `/dev/sda1` 的 ext4、CPython 3.14.6、宿主 SQLite 3.53.1；SQLAlchemy 2.0.58、pydantic-settings 2.16.3、Pydantic 2.14.4、PyYAML 6.0.4。Docker Engine 29.5.3、Compose 5.1.4；官方 Debian trixie slim 镜像同为 Python 3.14.6，但链接 SQLite **3.46.1**，上述容器完整测试独立覆盖这个差异。生产实际 UID 10001、wheel 安装且无开发工具；开发 UID 1000 与挂载源码，两者只读配置及当前无外部网络均已核对。

**构建环境限制仍存在：** 当前 daemon 经已有代理正常拉取官方镜像超时。本轮通过宿主可用网络下载并逐件校验官方固定索引／清单／层摘要，以 OCI 导入本机缓存；构建时仅对该命令清空失效代理参数，未更换镜像源、未修改 daemon 或用户代理配置。正常 `docker pull` 路径尚未修复，不能由本次成功缓存构建推断新机器可直接拉取。具体固定制品身份由 Dockerfile 维护；本任务测试容器已清理。

官方文档只证明来源 API 或容器参数含义；配置解析、宿主测试和 Docker 实跑分别记录。Mock 只用于定位故障和机械协议，不作为权限隔离、LLM 理解、多轮收敛或动物质量证据。Blender、GPU、真实模型、远端网关、持久执行恢复及目标动物均未在本项实测。
