## 3. 输入、输出与权威状态

### 创建与查询

可信调用边界在首次创建前生成并保留现有 `WorkspaceId`，调用创建时提交该身份和显示名。身份类型本身不生成 UUID；回执丢失后沿用原身份，不以名称搜索后猜测，也不另造 CreationId、JobId 或 AttemptId。

显示名是非空白、可编码为 UTF-8 的字符串，原样保留，不静默裁剪或 Unicode 归一化。显示名不参与路径、权限或唯一性判断；不同身份可以同名。本期不定义重命名或删除协议。外部 API 的请求体大小、认证及 HTTP 幂等映射由后续接入确定，不在此提前创建配置项。

不可变 `WorkspaceRecord` 是唯一注册记录：

| 字段 | 当前语义 |
| --- | --- |
| `id: WorkspaceId` | 复用 L0 唯一身份；作为本地创建幂等键和注册主键。 |
| `display_name: str` | 原始创建字段；同身份再次提交时必须精确一致。 |
| `registered_at: datetime \| None` | 为空时仅登记创建意图；非空为首次注册事务写入并提交的带时区 UTC 时间，之后不改写。不是文件系统时间、活动选择或权限事实。 |

成功读取无记录，才表示没有登记过该身份；读取失败必须传播错误，不能返回“未登记”。以上三种情况从记录是否存在和提交时间是否为空单向判断，不新增状态枚举、`is_registered`、`ready` 或兼容投影。时间数值不用于生成身份、提交排序或并发判定。数据库唯一约束负责持久主键唯一性，不能只靠 L0 局部校验。

查询返回原记录或明确不存在，**不证明目录此刻可访问**。创建成功只在目录准备与注册提交完成后返回；相同身份、相同参数再次创建时读回或有限恢复；改参拒绝。已提交记录对应目录丢失或被替换时，保留登记事实并报访问错误，不自动创建空目录。

### 与既有身份的关联

| 既有权威关系 | 本项处理 |
| --- | --- |
| `TaskIdentity.workspace_id` | 后续任务服务核对真实登记及授权后引用；工作区创建不顺带创建 Task。 |
| `ArtifactIdentity.workspace_id`、`ModelFamilyIdentity.workspace_id` | 继续表达直接归属；本项不生成产物或模型家族。 |

| `AttemptOutput`、`Derivation`、`FileReference` | 执行来源、派生来源和字节身份继续独立；工作区注册不能替代这些记录。 |

关系的完整校验规则引用 [L0-02](L0-02.md)，不在本卡重写。`WorkspaceId`、文件路径和“已注册”都不是访问凭证。后续 BFF／Tool 的可信接入必须核实身份和资源授权，再装配任务范围；不得把调用方提供的 ID 直接变成全权文件端口。该接入尚未实现，本期创建／查询只供可信内部宿主使用。

## 4. IoC 与暴露方式

### 包、端口与装配

当前模块及依赖如下：

| 归属 | 内容与依赖 |
| --- | --- |
| `src/vet3d/workspaces/records.py` | 稳定的 WorkspaceRecord 及局部参数校验，依赖 identity 公共入口。 |
| `src/vet3d/workspaces/ports.py` | WorkspaceRepository、WorkspaceDirectories 两个真实 I/O 替换边界，由创建用例拥有。 |
| `src/vet3d/workspaces/service.py` | 具体 WorkspaceService；负责创建顺序与恢复，不额外包装一个同形服务 Protocol。 |
| `src/vet3d/adapters/workspace_tables.py`、`workspace_repository.py` | SQLAlchemy 表及 SQLite 仓储；字段有中文说明，仓储显式继承 Protocol。业务不得访问表／Session。 |
| `src/vet3d/adapters/workspace_directories.py` | ManagedWorkspaceRoot 持有根、固定锁和目录描述符；LocalWorkspaceDirectories 核对和准备身份目录。具体路径不进入业务记录。 |
| `src/vet3d/bootstrap/workspaces.py` | 接收部署端传入的 Path，显式初始化／打开存储，通过 WorkspaceRuntime 管理专用线程、准入、等待期限和关闭，并注入服务依赖。 |
| 各包 `__init__.py` | 公开必要入口；跨包只通过公共导出，导入不执行环境探测或 I/O。 |

| 公共入口 | 实际调用契约 |
| --- | --- |
| `WorkspaceService(repository=..., directories=...)` | 具体同步服务；依赖由调用方以关键字显式注入。线程封闭，不宣称任意直接跨线程调用安全。 |
| `WorkspaceService.create(*, workspace_id, display_name)` | 返回已提交的 WorkspaceRecord；先校验参数，按第 5 节创建或读回。 |
| `WorkspaceService.read(workspace_id)` | 返回 WorkspaceRecord 或 None；不检查目录可访问性。 |
| `WorkspaceRepository.get(workspace_id)` | 同步读取真实记录，只有确实缺行才返回 None。 |
| `WorkspaceRepository.record_intent(workspace_id, display_name)` | 短事务登记原字段，或核对并返回原记录；同身份改参拒绝。 |
| `WorkspaceRepository.confirm_registration(workspace_id)` | 缺少原意图时拒绝；首次写入 UTC 提交时间，重复确认保持原值。 |
| `WorkspaceDirectories.check_absent(workspace_id)` | 首次意图前核对目标不存在。 |
| `WorkspaceDirectories.prepare(workspace_id)` | 只用于待提交意图，创建或核对可接受的空目录残留并同步。 |
| `WorkspaceDirectories.require_existing(workspace_id)` | 核对已登记目录；不补建，也不要求为空。 |
| `bootstrap.initialize_workspaces(root: Path, *, max_file_operations=2)` | 异步显式初始化不存在或私有空根，返回 WorkspaceRuntime；不会认领非空残留。文件并行配置由 [L1-04 第 4 节](L1-04.md#4-ioc-与公开入口)维护。 |
| `bootstrap.open_workspaces(root: Path, *, max_file_operations=2)` | 异步打开既有根和库，返回 WorkspaceRuntime；缺库、缺锁、错误结构均报错。 |
| `WorkspaceRuntime.create/read` | 对应同步服务的异步入口；另接受 `timeout_seconds=5.0`，正有限秒数只限制等待，None 表示由调用方管理期限。 |
| `WorkspaceRuntime.aclose()`／异步上下文管理 | 停止准入，等实际操作结束，关闭原线程资源后释放根锁；取消关闭等待不会提前释放资源。 |

仓储和目录适配器显式继承所实现的 Protocol。目录端口不暴露任意文件读写、绝对路径或执行接口；表模型只在仓储内部消费。`WorkspaceRuntime` 应通过两个装配函数取得，不直接构造未初始化实例。

`WorkspaceContractError` 表示输入或回包违反契约，`WorkspaceConflict` 表示同身份改参。创建用例把其余端口异常包装为 `WorkspaceCreationError`，保留 `workspace_id`、`cause` 和异常链；查询错误原样传播。适配器另有 `WorkspaceStorageError` 和文件系统异常。宿主以 `WorkspaceBusyError` 表示本次未准入，以 `WorkspaceClosedError` 拒绝关闭后或跨事件循环调用，以 `WorkspaceTimeoutError` 表示等待超时；这些宿主错误不保存为业务状态。

Bootstrap 选择具体实现；服务不导入 adapters、Settings、SQLAlchemy 或宿主执行库。受管脚本、沙箱、租户和调度端口仍为后续 TODO，本期不建立空壳成功入口。不增加第三个产品 CLI，使用公开消费者和真实测试装配验收。

产品模块位于上述 src-layout 包，类型检查范围和产品依赖随本项更新；构建仍排除 `src/vet3d/infrastructure/` 的参考工具，不复制 Hi3D 库存模块。安装包核验在第 7 节记录。

### 存储与运行边界

首期使用 SQLAlchemy **2.0.58** 与 CPython 3.14 自带的 SQLite，依赖记录在 `pyproject.toml`、`uv.lock`。没有异步数据库框架、通用 Unit of Work、迁移平台或多数据库兼容层。每次仓储调用在所属线程内创建并关闭 Session；连接只打开既有库，采用 DELETE 日志、EXTRA 同步、1 秒数据库锁等待和显式事务。首次初始化独占创建数据库并建表；重开按当前唯一 SQLAlchemy 元数据核对结构，不补表、迁移或忽略额外结构。

Bootstrap 仍把整个同步 create／read 交给单个专用控制线程，数据库资源在该线程建立、使用和关闭。创建／查询的等待取消或超时不停止已提交的整次同步操作；内部保留 Future 并观察晚期结果，关闭等实际工作终结后才释放资源。文件 I/O 已由 L1-04 独立装配，当前控制调用与文件调用的准入、容量及关闭规则统一见 [L1-04 第 4 节](L1-04.md#4-ioc-与公开入口)。根级排他使用固定 `writer.lock` 的非阻塞 `flock`，在根打开期间持有；它是配合受信服务的本地写入锁，不是恶意进程隔离。该桥接不承担未来建模调度或自动重试。

受管根由部署端指定，子路径单向派生为 `.control/registry.sqlite3`、`.control/writer.lock` 和 `workspaces/<WorkspaceId>`，不作为外部路径协议。根及受管目录要求当前用户所有、0700，控制文件要求 0600 普通单链接文件。父路径必须已存在；逐段打开拒绝符号链接，访问目录通过保留的描述符并校验类型、属主、权限及可观察的设备／inode 替换。注册库的 SQLite 配套文件留在控制目录。目录与控制存储不能整体授权给未来执行器。

首次初始化与打开既有存储明确区分：根初始化失败后保留现场，只释放句柄；不会因下一次调用而自动清理、补建或认领残留。既有资产或残留存在而注册库缺失／不可读时不能静默建立空库。数据库事务不包含 mkdir，需按第 5、6 节对账；目录和初始化步骤执行 fsync，仍不宣称跨数据库和文件系统原子提交或任意断电恢复已验证。

环境探测、单写入实例管理、日志初始化归 Bootstrap／Operations。调用宿主使用现有 `configure_logging` 配置有界 stderr；工作区宿主记录固定操作、WorkspaceId、开始／终结、取消等待和边界异常，不记录完整显示名。晚期异常由宿主观察，避免取消等待后静默丢失。等待取消／超时的通知复用既有终态日志处理，日志失败附入原因链，原取消／超时继续传播。完成日志回调若输出失败，由事件循环异常处理器报告，已经提交的登记事实仍保留；不把日志失败回写为业务失败。本期不建设文件日志、集中治理或完整 readiness；后续若落地文件日志再验证轮转、并发与保留上限。资源可用性不定义业务动作或发布资格。

## 5. 正常流程与副作用

以下为当前创建流程。创建临界段覆盖本次短存储操作，不跨越模型调用或任何建模任务。

| 步骤 | 校验与分支 | 副作用及输出 |
| --- | --- | --- |
| 1 | 核对 WorkspaceId、显示名；在可信装配内进入创建临界段，读取原记录。 | 非法参数无创建副作用；读取错误不降级为不存在。 |
| 2 | 原记录存在且字段不同则拒绝；已注册且相同则核对其原目录。 | 成功读回原记录；不重写时间、不切换活动工作区。目录异常报错并保留记录。 |
| 3 | 新身份先确认目标不存在；文件、目录、符号链接及其他不明对象均不得认领。 | **先检查，再登记意图**，防止先写意图后在重试时误认既有目录。 |
| 4 | 原子持久登记原创建字段，提交时间保持空。 | 形成可读回的创建意图，不宣称工作区已创建完成。 |
| 5 | 准备固定身份目录；已有未提交记录仅允许续做缺失目录或核对可确认的本次受管残留。 | 本项只创建必要工作区目录，不部署脚本、资源、素材和执行输出树。陌生内容或所有权不明时停止。 |
| 6 | 核对目录并完成适用的文件系统同步，再提交首次注册时间。 | 注册记录提交；这是成功返回的必要条件，仍不授予执行、发布或访问权限。 |
| 7 | 返回同一身份及注册事实，记录关键诊断。 | 不创建 Task／Session，不激活工作区，不输出 BFF 状态或业务验收结论。 |

恢复依赖“根只由可信服务管理、同根写入实例互斥”的前提。实现仅在持久意图已经存在时接受身份相同、属主和私有权限正确的空目录残留；没有持久化目录 inode 或创建令牌，空目录本身不是独立所有权证据。已观察目录的替换只在当前根实例内通过设备／inode 比较检测；重启后或首次观察前，不保证识别属性合法的同权限替换。注册库同样不提供跨重启文件身份连续性证明。不能把这些校验宣称为抵御同 UID 恶意进程的隔离，不可信执行必须在后续取得实际不同权限边界。

已登记目录核对仅检查受管定位、目录类型／归属及访问，不要求目录为空，也不重验后续素材。陌生内容拒绝认领针对**未提交的创建残留**；L1-02 等后续消费者的合法写入不能令重复创建变成失败。

## 6. 失败、取消与恢复

| 情形 | 当前行为与恢复出口 |
| --- | --- |
| 参数无效、同身份改参、目标预先存在 | 拒绝，不覆盖、不改原记录、不递归清理。 |
| 意图未提交或提交回执不明 | 用原身份重读；读失败保留未知，不能改用新身份隐藏原操作。 |
| 意图已提交，目录尚未创建 | 在同根、同库、原参数及可信管理前提成立时，按原身份有限续做。 |
| 目录已创建，注册事务失败 | 保留意图和目录；返回原身份及原因，后续核对残留，不能直接宣布成功。 |
| 注册已提交，响应或日志输出失败 | 事实不回滚；按原身份读回，不能因调用报错重复创建。 |
| 已登记目录丢失、链接／权限异常或本实例已观察对象被替换 | 保留登记事实并报访问／一致性错误；不重建空目录冒充原工作区。跨重启合法属性替换不在当前识别能力内。 |
| 注册库缺失、损坏、不可读或根被替换 | 明确本期不能自动恢复／当前不可查询，停止自动初始化或认领；备份恢复与迁移不在本期。 |
| 提交到工作线程前取消 | 准入挂起点交付已有取消，不启动本次存储调用；没有内部排队任务。 |
| 已提交控制线程后取消／超时 | 只结束等待，整次同步 create／read 仍可能完成或提交；内部持有实际 Future，并延后资源关闭。用原身份对账；各类调用的在途准入规则见 [L1-04 第 4 节](L1-04.md#4-ioc-与公开入口)。 |
| 同实例控制调用并发、第二写入实例 | 本次未准入报 WorkspaceBusyError；原调用终结后显式同参重放才读回／续做，改参拒绝。第二写入实例被根锁拒绝；当前文件并发范围由 [L1-04 第 4 节](L1-04.md#4-ioc-与公开入口)维护。 |
| 进程退出后重启 | 新进程打开同根同库读取事实；只有显式同身份创建请求可触发有限恢复，不后台扫描认领所有目录。 |
| 外部生成、Blender 运行、发布或视窗回调 | 本项尚不产生这些副作用；恢复责任见第 8 节，不伪造处理成功。 |

取消等待没有步骤间停止协议；实际同步调用按正常流程运行至返回或异常，根锁持续到资源关闭。宿主关闭不承诺抢占阻塞的系统调用，也不承诺进程被强制杀死后完成清理；新进程只能依据已经落盘的事实按原身份显式恢复。

本地可核验的目录续做不放宽 [L0-05](L0-05.md) 的外部提交规则。创建登记和 ReconstructionRepository 的提交权不是同一概念；生成意图已记录但外部受理未知时仍不得盲目重提。

### 并行与资产修改

不同工作区可以并行。同区基于同一固定输入版本的候选使用独立具体执行意图、独立进程和输出；沿用当前重建契约时分别使用 Job／Attempt，不放宽同 Job 的旧尝试守卫。新内容使用新 ArtifactId，不覆盖已登记字节。多个 Agent 不同时写同一 `.blend`；候选提交由可信服务对账并处理基线冲突，不能最后写入者自动成为当前版本。

执行环境按一次独立候选或脚本任务需要分配，不预设每工作区／每 LLM 永久运行 Blender。池化预热是后续优化，跨任务复用必须有可验证清理，不默认保留上一任务的文件、内存场景或凭证。

### 开放不可信执行的必需条件

**拟定数据流：** 可信任务授权与固定输入 → 最小只读输入集 → 独立执行环境 → 不可信候选和报告 → 受信接收及隔离检查 → 登记候选、独立验收和受控发布。

1. **授权与最小输入。** 可信接入核实任务可用的具体内容和依赖，执行侧只取得相应字节或受限句柄。不传整个工作区、完整 ArtifactAccess、注册库或服务源码；输入只读且固定，不用可被执行侧改写的共享硬链接保护原件。
2. **真实执行权限。** 动态 Blender Python 按不可信代码处理，不能在控制面 Python 进程执行。不暴露宿主环境、凭证、容器管理接口、宿主 PID／网络空间或无关设备；代码限制由实际隔离实现承担，不靠模块黑名单、关键词扫描或提示词。
3. **稳定操作。** 预览、尺寸检查、导出优先用结构化参数与受管脚本，不透传任意 shell。受管脚本打开不可信 `.blend`／插件／复杂文件仍须经过适用隔离；禁自动脚本不约束显式动态代码。
4. **网络和资源。** 默认禁止执行侧网络，供应商调用由可信网关完成；确需联网另按真实用途授权，不能顺带开放内部网络或元数据服务。CPU、内存、进程数、临时盘、输出、日志和墙钟时间由外部机制限制，总并发资源也有界；GPU 显存、共享和回收另验。
5. **受信接收。** 可信的是接收过程，不是执行器产物。停止写入或形成不可变输出快照后，核对条目、位置、类型、链接、大小、摘要和原执行关联；不按脚本给出的任意路径递归复制。防止检查后替换；解析复杂文件和重新执行检查放在干净的隔离环境，不在控制进程直接加载。
6. **独立事实。** 输出报告是生产者声明；退出零、文件齐全、内容验收、登记及发布分别取得证据。生成脚本不能在同一可修改环境中自证通过并直接发布；自动流程消费 L0 的独立守卫，无需逐命令人工审核。
7. **取消和重启。** 原执行及启动意图须可追溯，完整停止派生进程／容器／VM 后确认终态再回收。断连和等待超时不等于停止；可信执行侧须有期限约束，控制面重启后对账原句柄。回执不明不得盲目启动，取消受理不等于已取消，不承诺恢复 Blender 内存场景。

不可信代码的首次开放须同时满足上述实际需要的 L1 文件／持久化、L2 最小执行与原尝试记录、L3 接收检查，不能因 L2-02 单项进程能启动就提前开放。无需先完成全部远端适配或整个运维平台；隔离未成立时明确不可执行，不回退到宿主裸执行，也不改变动作语义或降低发布条件。

这是联合放行条件，不是循环开工依赖：L2 执行器、账本与 L3 接收可按契约分别开发并集成验收，L2 开工不需要等待完整 L3。

实际选型后至少验证：固定版本 Blender 后台脚本、重开、预览及导出；跨任务／控制目录／凭证／管理接口和网络访问被拒绝；链接及输出替换；受控资源压力下其他任务与控制面可用；派生进程取消、超时、重启对账与残留写入；并行候选和过期提交。使用 GPU 时另测驱动、渲染后端、显存和设备回收。替身不证明隔离，真实测试也只覆盖所记录的威胁与配置。
