## 3. 输入、输出与权威状态

| 项目 | 当前约束 |
| --- | --- |
| 任务输入 | 任务目标、冻结的业务策略、授权资料与工作目录、必要 Skill／共享模块；运行时及环境配置由可信装配提供。任务文件可在授权范围内持续修改。 |
| 原生反馈 | 命令输出、错误、文件操作和实际图像沿原生工具进入同一模型会话；进度摘要仅给 BFF／业务消费者，不替代模型反馈。 |
| 对外输出 | 原生任务／会话关联、适用进度和终止信息、正式候选产物位置及接收结果；具体结构在阶段 A 后按真实消费者确定。 |
| 身份 | 关联已有任务／工作区与原生 thread、turn、item 等实际标识；保留原生标识语义，不强转为内部 UUID。需要 Session 时沿已有语义，不预造额外身份。 |
| 权威事实 | 运行时拥有模型工具循环、原生历史及工具执行事实；隔离设施按其职责报告实际环境与进程边界。Vet3D 拥有任务意图、授权、业务关联、验收与发布；同一生命周期操作只有一个控制路径。 |
| 工作文件 | 草稿、代码、日志、预览可以修改并跨轮接续，不自动登记为正式资产；并行任务／候选使用独立可写范围，不能同时覆盖同一模型或已登记资产。 |
| 正式交接 | 仅在实际业务交接时按 L1 的存储和资产契约接收，随后独立验收／发布；命令退出、图片产生或 Agent 自报成功均不替代业务结论。 |

当前 Agent 路径**不要求固定代码或输入，不要求输入快照、参数／脚本指纹、字节追溯或逐次执行内容复现**。不把这些要求转移至 L2-03、日志、资源摘要或后续条目。普通读文件、编辑、预览与诊断沿用原生调用记录；脚本变更或重复命令不因此创建业务 Job／Attempt。L0-05 对特定重建请求的幂等、原尝试恢复规则继续只约束该消费者。

受管资源的只读版本与安装完整性、正式资产身份及内容校验仍有效，作用域分别见 L1-03／L1-04；不扩张到全部可变工作文件。

## 4. IoC 与职责归属

- **成熟运行时**承担唯一模型与工具循环：模型请求、原生工具分派、代码和文件操作、执行反馈、图片输入与会话继续。使用其原生机制不等于任意开放宿主权限。
- **Vet3D 应用消费者**提交任务目标、业务约束及必要输入，消费进度与业务结果。只为实际可替换边界定义小型端口；不预设一套覆盖全部原生工具的中性协议。
- **运行时适配器**处理所选协议的任务接入、事件消费、原生关联与停止请求。优先直接使用原生结果，不重建工具路由、进程状态机、输出续读服务或镜像会话库。
- **Bootstrap／Operations**读取 Settings 并注入适配器、授权环境和业务策略；环境事实不决定业务动作协议或发布资格。权限、凭证、网络及资源限制必须匹配实际运行位置。
- **后续领域与编排模块**承担任务预算、节点迁移、质量判断、返工与正式交接，不再包裹一轮模型规划和工具反馈循环。需要领域工具时通过运行时支持的扩展点接入，不包装所有共享库函数。

跨包通过 `__init__.py` 公共导出。可能涉及的落点是现有 `adapters`、`bootstrap` 和具体任务消费方；阶段 A 后再决定文件与端口名称，不能先实现无独立消费者的 `ExecutionRequest → ExecutionBackend` 作为 Agent 主入口。若评估 Agents SDK，比较完整 `SandboxAgent + Runner` 路线，不将它与 Codex 循环互相嵌套。

## 5. 正常流程、实施顺序与副作用

### 阶段 A：选型前的最小真实闭环

1. **核对实际版本与接入条件。** 选择可实验的运行时版本及对应协议，明确支持工具与图片输入的模型连接、凭证来源和有限实验预算。核对文件、命令、图像工具如何进入同一授权环境；实际执行动态代码前落实必要隔离和限制。先使用运行时已有机制，缺口必须有具体依据。
2. **准备最小任务环境。** 授权一份合成模型、少量 Skill／参考和共享模块，并提供可写工作区。只适配必要的 Linux 路径与调用语义，不改 Hi3D 原件、不把归档提示词自动当指令，也不要求临时脚本预登记。
3. **真实 Agent 自主编程与报错修正。** Agent 阅读说明、检查模型、写代码并调用原生执行工具；设计一个可恢复的真实错误，让 Agent 从实际报错与日志修改代码。宿主不代写修复方案。
4. **实际看图并修订。** Agent 渲染 PNG，以原生图片工具将图像内容送入后续模型输入，根据可见问题修改并重渲染。使用文本未直接泄露的简单视觉差异；路径、事件名或 Agent 自称看过图片都不够。通过运行时支持的记录或有限实验观测确认图像输入，Code Mode 路线还须确认图像转发语义。
5. **跨轮继续并核对边界。** 同一原生会话及任务工作文件继续下一轮；实测取消、超时、断连、重启和跨任务访问限制。分别记录会话历史、文件和进程能恢复到什么程度。

阶段 A 产出本卡中的实际版本、闭环结果、边界与具体缺口。只有闭环和必要安全条件成立，才确定接入方式与公开接口；若失败，说明受影响能力、依据与最小调整，不能默认转为自研运行内核，也不能把候选未测试写成失败。不新增永久测试网关或完整日志转储框架来证明图片投递。

### 阶段 B：最小任务接入与正式产物交接

阶段 A 通过后，按实际消费实现并注入一个运行时适配器，接通任务提交／继续／停止、原生事件消费和必要关联。文件与图片工具继续作用于同一任务环境；BFF 进度消费不参与重建模型反馈。正式交接时关闭相应写入窗口或取得可安全接收的文件，再调用受信存储／资产能力；不为输出另设没有实际必要的保留容器。

需要的 L2-03 关联或 L3 接收部分随本条目联合验证，只补已确认缺口；不等待整层完工，也不为普通工具调用增加持久化事件镜像。新增、修改文件遵循既有 src-layout、类型、文档字符串和公共导出规范。

### 阶段 C：验证与文档交接

完成第 7 节适用验证，回填实际实现、使用入口、恢复限制与可放行消费者。同步分层清单和导航状态；领域能力、动物质量及生产规模不能从这个实验推导。

正常运行会产生可变工作文件、原生会话记录、模型调用消耗、执行进程和预览；正式资产只有在显式接收时才登记。任何新增配置或中间步骤须有实际使用方，不提前建设工具注册平台、调度服务或另一套 Agent 框架。

## 6. 失败、取消与恢复

| 情形 | 行为与待实测边界 |
| --- | --- |
| 模型连接、工具或权限不满足 | 返回具体缺口；不以替身成功、空反馈或扩张宿主权限掩盖失败。必要 Skill 调用方式若不同，只适配明确差异。 |
| 脚本错误、渲染失败 | 将实际输出和错误交回原生循环，允许预算内继续修订；普通修订不创建业务 Attempt。 |
| 图片读取／投递失败 | 保留原生失败反馈，不能把文件存在或业务摘要冒充模型已收到图像；恢复后通过原生机制继续。 |
| 用户停止或执行超时 | 向原运行时／实际生命周期所有者发送请求；受理不等于进程及子进程已退出。实际停止与排空前不提前回收仍在使用的环境。 |
| BFF 或接入连接断开 | 核对原生会话和运行事实，不默认重提任务；连接断开是否终止执行按所选接口实测，独立命令接口结论不能外推完整线程路线。 |
| Runtime／宿主重启 | 分别核对原生历史、任务工作文件、关联和进程；会话恢复不证明进程续接。没有原任务查询或存活证据时明确不确定，不启动新进程冒充恢复。 |
| 文件接收、登记或报告失败 | 保留可取得的工作文件／候选与必要关联，按存储契约对账；不因接收失败自动重复建模，不为所有工作文件增加快照。 |
| 执行完成但业务未通过 | 交由相应业务消费者判断与修订，不能自动发布；原生执行记录不替代验收报告。 |

日志是有限诊断窗口，不是原生会话备份或业务账本。清理规则按实际生命周期设施验证，不能增加第二个控制者同时取消、重试或回收同一次执行。

## 8. 完成与上层放行

阶段 A 通过仅允许确定本条目接入方式和公开接口，不等于条目完成。阶段 B 的实际接入及必要交接完成、第 7 节本期必需检查通过，并回填第 9 节后，才可将本条目标为已完成。首次开放不可信执行还须满足 [L1-01 交接条件](L1-01.md#开放不可信执行的必需条件)，可联合实现其必需部分，不以互相等待完整 L2-03／L3 形成循环前置。

向 L4／L5 放行的是已验证原生运行时及任务环境的领域扩展和业务上下文接入；向 L8 放行的是可消费的任务与反馈边界，不是另建模型工具循环。M1 仍须结合其他条目放行；M2、完整质量与生产就绪不由本卡自动放行。

仍待决定：具体运行时版本与协议、实验和生产模型连接、实际隔离及资源设施、凭证与网络接入方式、可支持的取消／重启语义，以及正式交接所需的最小适配。决策依据是阶段 A 的真实能力与缺口；不会仅因已有 Docker 镜像、命令接口或历史样例就认定选型完成。
