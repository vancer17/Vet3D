## 4. IoC 与职责归属

- **成熟运行时**直接承载 Vet3D Agent：原生 Agent 负责建模规划、工具选择、代码与文件操作、错误理解、视觉观察与修订，运行时管理模型工具循环和会话上下文；Vet3D 不另建建模控制循环，该边界不限制运行时自身已有能力。使用其原生机制不等于任意开放宿主权限。
- **Vet3D 应用消费者**提交任务目标、业务约束及必要输入，消费进度与业务结果，不据原生反馈生成细分建模任务。只为实际可替换边界定义小型端口；不预设一套覆盖全部原生工具的中性协议。
- **运行时适配器**负责协议连接、输入传递、事件消费、原生关联与停止请求；不解释代码错误或图像以制定修复方案。连接／协议异常处理不等于建模错误理解，不重建工具路由、进程状态机、输出续读服务或镜像会话库。
- **Bootstrap／Operations**读取 Settings 并注入适配器、授权环境和业务策略；环境事实不决定业务动作协议或发布资格。权限、凭证、网络及资源限制必须匹配实际运行位置。
- **后续领域与编排模块**中，领域服务提供固定职责的评估结果与证据，L8 管理业务节点、质量要求、验收、返工准入、预算、停止条件、交接和发布规则；具体如何检查、编程、调用工具和修订由原生 Agent 决定。需要领域工具时通过运行时支持的扩展点接入，不包装所有共享库函数。

跨包通过 `__init__.py` 公共导出。可能涉及的落点是现有 `adapters`、`bootstrap` 和具体任务消费方；阶段 A 后再决定文件与端口名称，不能先实现无独立消费者的 `ExecutionRequest → ExecutionBackend` 作为 Agent 主入口。若评估 Agents SDK，比较完整 `SandboxAgent + Runner` 路线，不将它与 Codex 循环互相嵌套。

当前阶段 A 落在独立的 [experiments 公共入口](../../../../src/vet3d/experiments/__init__.py)：具体 stdio 客户端、任务与原生线程关联、单轮实验消费者、材料准备及 Docker 实验装配。显式参数注入现有运行时发行目录、专用认证目录、镜像和模型，没有产品 `AgentPort`、第二套 Settings、执行后端或 Tool 路由。`NativeSessionBinding` 直接持有已有 `TaskIdentity`，原生 thread／turn／item 保留不透明字符串；实验生成的任务／工作区身份**尚未进入产品注册仓储**，不冒充持久关联。

### 继续输入与建模决策权

“继续”是将有效业务输入送入原生会话，不是接入层重新规划建模。允许传递用户追加要求、领域服务的明确评估结果与证据，以及预算、必保特征等业务约束；明确业务规则可以自动触发继续或停止，无需每次人工触发。例如，可自动反馈“尾部比例验收未过，测量值和阈值见报告，预算允许返工”；不能由宿主分析原生报错或渲染图，再连续追加“修改这个函数、运行那条命令、改这个参数”的补救指令。用户明确给出的操作要求仍作为用户输入传递，不由接入层自行推导。

固定职责的评估服务可以使用模型或确定性方法执行检查，返回指标、失败项与必要证据；L8 可以据此准入或拒绝返工、停止超预算任务及阻止发布。这些职责不自动构成第二个建模 Agent，具体修复方法、工具调用与建模修订推理由原生 Agent 决定。判断边界看实际决策权，不看组件叫“客户端”还是“适配器”，也不只看外层是否调用模型、启动进程或调用继续接口。业务事实投递不重建或挑选原生工具历史来指挥下一步。

## 5. 正常流程、实施顺序与副作用

### 阶段 A：选型前的最小真实闭环

提供初始目标和必要业务资料后，由原生 Agent 连续完成资源读取、编程、执行、错误修正、实际图像观察及修订；以下步骤是实验组织与核对顺序，不是宿主逐步下发给 Agent 的行动脚本。

1. **核对实际版本与接入条件。** 选择可实验的运行时版本及对应协议，明确支持工具与图片输入的模型连接、凭证来源和有限实验预算。核对文件、命令、图像工具如何进入同一授权环境；实际执行动态代码前落实必要隔离和限制。先使用运行时已有机制，缺口必须有具体依据。
2. **准备最小任务环境。** 授权一份合成模型、少量 Skill／参考和共享模块，并提供可写工作区。只适配必要的 Linux 路径与调用语义，不改 Hi3D 原件、不把归档提示词自动当指令，也不要求临时脚本预登记。
3. **真实 Agent 自主编程与报错修正。** Agent 阅读说明、检查模型、写代码并调用原生执行工具；设计一个可恢复的真实错误，让 Agent 从实际报错与日志自行判断并修改代码。宿主不代写修复方案，不逐步追加补救提示或指定修复命令。
4. **实际看图并修订。** Agent 自主选择所需观察、渲染 PNG，以原生图片工具将图像内容送入后续模型输入，根据可见问题修改并重渲染。使用文本未直接泄露的简单视觉差异；宿主不解读画面后追加修复步骤。路径、事件名或 Agent 自称看过图片都不够。通过运行时支持的记录或有限实验观测确认图像输入，Code Mode 路线还须确认图像转发语义。
5. **跨轮继续并核对边界。** 同一原生会话及任务工作文件接收新的用户要求或明确业务反馈后继续下一轮；这不用于补救前述自主修正用例。实测取消、超时、断连、重启和跨任务访问限制，分别记录会话历史、文件和进程能恢复到什么程度。

阶段 A 产出本卡中的实际版本、闭环结果、边界与具体缺口。通过已有会话与输入记录核对宿主干预：若错误修正或视觉修订依赖宿主代写方案、逐步补救提示，不能计为自主闭环通过。只有闭环和必要安全条件成立，才确定接入方式与公开接口；若失败，说明受影响能力、依据与最小调整，不能默认转为自研运行内核，也不能把候选未测试写成失败。不新增永久测试网关、干预登记体系或完整日志转储框架。

### 当前阶段 A 实验入口与具体取舍

[实验入口](../../../../src/vet3d/experiments/native_agent_stage_a.py)仅在显式运行时调用真实模型；默认单元测试和三个既有产品 CLI 均不启动它。以下路径须替换为已核对的本地目录；`run-root` 必须不存在，`control-home` 是专用私有目录，凭证不得放在任务材料、仓库或输出中。

```bash
uv run --locked --no-sync python -m vet3d.experiments.native_agent_stage_a \
  --repo-root "$PWD" \
  --run-root /path/to/new-experiment \
  --control-home /path/to/private-codex-home \
  --codex-package /path/to/native-codex-distribution \
  --blender /path/to/blender \
  --image-id sha256:7c581df61df4ac315ab5157a1ff2a436f316394a5a36c1bd27acff2b5b7c9844 \
  --model gpt-6-astra
```

- 原生 `environment/add` 直接连接 `exec-server`，`thread/start`／`thread/resume`／`turn/start` 使用同一任务环境；接入仅发送初始目标、独立追加要求及专门的边界／停止实验输入。没有将原生工具改成业务回执，也没有宿主分析日志或图片后下发补救步骤。
- 实验复用已缓存镜像和 Codex 发行目录，不构建或下载运行环境。控制容器独占认证及原生历史目录；执行容器仅有独立可变 `/work`、只读运行时和已有解释器。原生 `externalSandbox` 对应实际 Docker 边界，不能单凭该字段声称安全。执行侧只连接 `isolated` 内网、无默认路由；控制侧另接模型网络，禁止 IP 转发，不发布端口、不挂 Docker socket 或持久资产根。
- 两侧各限制 2 CPU、2 GiB 内存、无 swap、128 PID，根只读、移除 capabilities、禁止提权；`/work` 为 192 MiB tmpfs，`/tmp` 为 64 MiB。Docker local 日志单文件 1 MiB、保留 2 份。这是有限实验装配，不是新增第三套 Compose 或生产隔离设施；同内网原生 WebSocket 未配置独立认证，仅允许本实验拥有的两个容器，不能外推多租户环境。
- 早期第三轮实际暴露了独立授权缺口：账户 Apps 默认开放，Agent 经远程命令 App 在容器外的实验材料目录编写和运行了脚本。发现后停止控制容器，该轮不计隔离通过；已核对其可见调用及仓库差异，不能因此声称执行容器逃逸。当前装配用原生启动配置关闭 Apps、插件目录、浏览器／计算机及多 Agent 等本实验不需要的入口，并在首次和恢复后核对原生 MCP 清单为空才提交模型轮次。这是任务工具授权，不是关键词拦截或固定脚本清单。官方说明也明确 Apps 通路不受命令沙箱网络代理约束，见[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。关闭配置的实际效果仍以第 7 节重验为准。
- 曾尝试在受限容器内使用原生 bwrap，实际报命名空间权限不足。没有为此开启 privileged、放宽 seccomp 或增加 capabilities，而是验证原生远程环境与外部容器隔离。两个容器分别承载控制和执行职责，不是输出保留容器，也不产生第二个 Agent。
- [材料准备](../../../../src/vet3d/experiments/native_agent_resources.py)只复用六份已物化的 Hi3D 原始参考／模块：材质与预览各一份入口、一份引用和一个 Python 模块。原件及发行锁只读；临时 Skill 只说明实际提供的资源与 Linux 任务入口，不要求整套桌面 PCG／发布流程。合成工程、旧参数入口及目标图片用于真实反馈实验，目标参数不以文本给出；草稿可以修改，无执行内容冻结。
- 当前版本初始 `localImage` 未读到远端 `/work`，随后原生 `view_image` 能实际回传该目录的图片。入口因此提供任务图片位置，由原生 Agent 读取；尚未宣称 BFF 图片附件接入完成。原生 Code Mode 的 `image(...)` 结果在会话中实际包含图片，业务层不代为压缩或重投模型反馈。
- 当前 Docker `cp` 无法读取这次只读根容器的 tmpfs 工作目录，因此材料通过受信 tar 管道进入，结果通过固定 `outputs` 的有限管道取得。输出上限 32 MiB、128 成员，拒绝链接、特殊文件及越界路径；只用于实验观察，不承诺并发一致、正式资产接收或验收。失败也有限尝试接收已有输出，接收失败单独记录，随后按本次资源标签清理。
- 认证沿当前已登录 Codex 连接，模型显式指定且关闭模型 fallback。现有 SOCKS 代理曾使路由发现超时；本轮仅对实验进程使用同一网关的 HTTP 方式。未修改全局代理、Docker daemon、模型来源或生产配置；模型目录刷新仍出现过超时，真实推理成功不表示所有网络故障已修复。

### 阶段 B：最小任务接入与正式产物交接

阶段 A 通过后，按实际消费实现并注入一个运行时适配器，接通任务提交／继续／停止、原生事件消费和必要关联；继续输入遵循第 4 节的来源与决策边界。文件与图片工具继续作用于同一任务环境；BFF 进度消费不参与建模规划或重建模型反馈。正式交接时关闭相应写入窗口或取得可安全接收的文件，再调用受信存储／资产能力；不为输出另设没有实际必要的保留容器。

需要的 L2-03 关联或 L3 接收部分随本条目联合验证，只补已确认缺口；不等待整层完工，也不为普通工具调用增加持久化事件镜像。新增、修改文件遵循既有 src-layout、类型、文档字符串和公共导出规范。

### 阶段 C：验证与文档交接

完成第 7 节适用验证，回填实际实现、使用入口、恢复限制与可放行消费者。同步分层清单和导航状态；领域能力、动物质量及生产规模不能从这个实验推导。

正常运行会产生可变工作文件、原生会话记录、模型调用消耗、执行进程和预览；正式资产只有在显式接收时才登记。任何新增配置或中间步骤须有实际使用方，不提前建设工具注册平台、调度服务或另一套 Agent 框架。

## 6. 失败、取消与恢复

| 情形 | 行为与待实测边界 |
| --- | --- |
| 模型连接、工具或权限不满足 | 返回具体缺口；不以替身成功、空反馈或扩张宿主权限掩盖失败。必要 Skill 调用方式若不同，只适配明确差异。 |
| 脚本错误、渲染失败 | 实际输出和错误沿原生工具回到原生 Agent，由其理解并决定预算内修订；宿主不翻译成修复步骤，普通修订不创建业务 Attempt。 |
| 图片读取／投递失败 | 保留原生失败反馈，不能把文件存在或业务摘要冒充模型已收到图像；恢复后通过原生机制继续。 |
| 用户停止或执行超时 | 向原运行时／实际生命周期所有者发送请求；受理不等于进程及子进程已退出。实际停止与排空前不提前回收仍在使用的环境。 |
| BFF 或接入连接断开 | 核对原生会话和运行事实，不默认重提任务；连接断开是否终止执行按所选接口实测，独立命令接口结论不能外推完整线程路线。 |
| Runtime／宿主重启 | 分别核对原生历史、任务工作文件、关联和进程；会话恢复不证明进程续接。没有原任务查询或存活证据时明确不确定，不启动新进程冒充恢复。 |
| 文件接收、登记或报告失败 | 保留可取得的工作文件／候选与必要关联，按存储契约对账；不因接收失败自动重复建模，不为所有工作文件增加快照。 |
| 执行完成但业务未通过 | 领域服务提供评估结果与证据，业务守卫决定返工准入、预算及发布；允许时可自动回传反馈，由原生 Agent 决定具体修订，原生执行记录不替代验收报告。 |

日志是有限诊断窗口，不是原生会话备份或业务账本。清理规则按实际生命周期设施验证，不能增加第二个控制者同时取消、重试或回收同一次执行。

阶段 A 已实测的恢复范围：空闲轮次结束后关闭本地 stdio 连接，实际停止控制容器，保留原生历史目录与存活执行容器，重新连接原环境并按原 thread 恢复，可继续使用先前文件。该结果不包括宿主崩溃、执行容器重启或原运行进程续接。实验 `/work` 是 tmpfs，执行容器停止／删除后不可恢复；原生历史和已复制的实验输出仍在各自目录。请求断连或结果不明时客户端不重发，失败路径仅尝试取得已有输出后清理，不创建新线程冒充恢复。

实际 30 秒停止实验取得 `interrupted` 后，原生后台终端列表和 Docker 进程表中仍存在心跳 Python；随后 `thread/backgroundTerminals/clean` 才使该进程消失。该清理由原生运行时管理具体工具进程，Docker 仅在实验结束时停止和删除环境。后续不能把 turn 终态直接投影为“所有进程已停止”。本地连接客户端 PID 也不等于控制容器或工具 PID。

## 8. 完成与上层放行

阶段 A 通过仅允许确定本条目接入方式和公开接口，不等于条目完成。阶段 B 的实际接入及必要交接完成、第 7 节本期必需检查通过，并回填第 9 节后，才可将本条目标为已完成。首次开放不可信执行还须满足 [L1-01 交接条件](L1-01.md#开放不可信执行的必需条件)，可联合实现其必需部分，不以互相等待完整 L2-03／L3 形成循环前置。

本轮阶段 A 已取得继续设计最小接入所需的原生动态编程、错误／图片反馈、同环境接续及有限安全证据；可据此继续完整 app-server 路线，不能直接开放产品服务。前述外部工具授权缺口已通过关闭未授权入口重验，未来启用任何扩展须核对其实际权限位置。当前只证明单任务合成夹具和明确保留的执行环境；生产多任务授权、并发容量、持久工作文件、正式交接和崩溃恢复仍未放行。

向 L4／L5 放行的是已验证原生运行时及任务环境的领域扩展和业务事实接入；向 L8 放行的是业务验收、返工准入和任务预算所需的任务／反馈边界，不授予上层建模规划与逐步修复控制。M1 仍须结合其他条目放行；M2、完整质量与生产就绪不由本卡自动放行。

仍待决定：生产运行时／协议版本、模型连接、隔离及资源设施、凭证与网络接入方式、可支持的取消／重启语义，以及正式交接所需的最小适配。阶段 A 的临时实现不自动成为这些产品接口；特别是缓存镜像来源与构建可重复性、实验性 `environment/add` 的版本约束、正式环境认证与权限、可变工作文件持久接续及崩溃恢复均须按实际消费者确定。
