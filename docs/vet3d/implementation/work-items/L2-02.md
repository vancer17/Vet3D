## 4. IoC 与职责归属

- **成熟运行时**直接承载 Vet3D Agent：原生 Agent 负责建模规划、工具选择、代码与文件操作、错误理解、视觉观察与修订，运行时管理模型工具循环和会话上下文；Vet3D 不另建建模控制循环，该边界不限制运行时自身已有能力。使用其原生机制不等于任意开放宿主权限。
- **实验入口及具体协议消费者**提交初始目标、独立追加要求和必要资料，处理连接、通知、原生关联与停止请求；不理解代码错误或图像来制定修复方案，不重建工具路由、进程状态机、输出续读服务或镜像会话库。
- **实验装配**显式注入发行目录、模型连接、凭证来源及受限环境；权限、网络和资源限制必须匹配实际运行位置。没有新增产品 Settings 或环境发现层。
- **后续业务职责**仍由[分层清单](../layers.md)维护；产品 Bootstrap、业务端口、领域评估和编排不在阶段 A 实现。实验观察不能反向定义业务动作或发布资格。

跨包通过 `__init__.py` 公共导出。本阶段使用已有实际消费者所需的具体协议，不先建设无独立消费者的 `ExecutionRequest → ExecutionBackend`、中性工具平台或产品 Agent 端口。运行时比较方向与取舍见 ADR 0012。

阶段 A 从 [experiments 公共入口](../../../../src/vet3d/experiments/__init__.py)提供单轮实验消费者与材料准备；具体协议／关联及环境现由 [adapters 公共入口](../../../../src/vet3d/adapters/__init__.py)共用，其提取及有限宿主接入见 [阶段 B](L2-02-B.md)。当前重新运行会使用 B 的环境期限与降权装配，不声称复刻历史环境。显式参数注入现有运行时发行目录、专用控制目录、镜像和模型；直连可指定原生 provider 与控制侧 API key 环境变量名。没有产品 `AgentPort`、第二套 Settings、执行后端或 Tool 路由。`NativeSessionBinding` 直接持有已有 `TaskIdentity`，原生 thread／turn／item 保留不透明字符串；实验生成的任务／工作区身份**尚未进入产品注册仓储**，不冒充持久关联。

此前对 `dedb76e` 源码的核对未发现第二套自主建模循环；当前保留的实验消费者仍按该职责工作：`run_native_turn` 消费通知、核对关联并按期限中断，没有解释错误、选择修复方案或分派工具；入口只发送初始目标、独立追加要求和边界／停止实验输入。原生 thread／turn／后台终端是会话与工具事实来源，Docker 提供容器和实际进程观察，`observation.json` 是实验记录而非另一个权威状态机。连接可用标志、RPC 请求号和事件计数服务于具体协议消费者；CLI 正常退出不产生业务验收状态。

### 继续输入与建模决策权

阶段 A 的继续实验向原会话传递预先约定的独立追加目标，用于核对历史与工作文件接续，不补救已经结束的自主任务。接入可传递用户要求或来源明确的事实，但不能自行解释原生报错／图片、生成修复方案，再逐步追加行动指令；原生 Agent 决定如何检查、编程、执行和修订。

具体业务反馈和质量返工属于后续职责，不在本卡展开或建设。是否重复控制取决于实际决策权，不取决于组件名称、是否调用模型或是否存在继续接口。

## 5. 正常流程、实施顺序与副作用

### 阶段 A：选型前的最小真实闭环

主验收是 Agent 在明确目标、完成条件、权限与预算内，无执行期人工补救地完成小型实验任务；判定口径统一见[主验收定义](#主验收约束内的自主任务完成)。允许自主选择工具、代码和迭代路径。以下步骤是实验组织与能力核对顺序，不是要求复刻 GPT 的行动轨迹，也不是宿主逐步下发给 Agent 的行动脚本。

1. **核对实际版本与接入条件。** 选择可实验的运行时版本及对应协议，明确支持工具与图片输入的模型连接、凭证来源和有限实验预算。核对文件、命令、图像工具如何进入同一授权环境；实际执行动态代码前落实必要隔离和限制。先使用运行时已有机制，缺口必须有具体依据。
2. **准备最小任务环境。** 授权一份合成模型、少量 Skill／参考和共享模块，并提供可写工作区。只适配必要的 Linux 路径与调用语义，不改 Hi3D 原件、不把归档提示词自动当指令，也不要求临时脚本预登记。
3. **真实 Agent 自主编程与报错修正。** Agent 阅读说明、检查模型、写代码并调用原生执行工具；设计一个可恢复的真实错误，让 Agent 从实际报错与日志自行判断并修改代码。宿主不代写修复方案，不逐步追加补救提示或指定修复命令。
4. **实际看图并修订。** Agent 自主选择所需观察、渲染 PNG，以原生图片工具将图像内容送入后续模型输入，根据可见问题修改并重渲染。使用文本未直接泄露的简单视觉差异；宿主不解读画面后追加修复步骤。路径、事件名或 Agent 自称看过图片都不够。通过运行时支持的记录或有限实验观测确认图像输入，Code Mode 路线还须确认图像转发语义。
5. **跨轮继续并核对边界。** 同一原生会话及任务工作文件接收预先声明的独立追加要求后继续下一轮；这不用于补救前述自主修正用例。针对实验实际开放的路径与进程，核对取消、超时、断连、有限重开和访问限制，分别记录会话历史、文件和进程能恢复到什么程度，不扩展为生产多租户或完整崩溃恢复建设。

阶段 A 产出本卡中的实际版本、小型任务结果、边界与具体缺口，作为继续接入、限定支持范围或暂缓该组合的决策依据。通过已有会话与输入记录核对宿主干预：若错误修正或视觉修订依赖宿主代写方案、逐步补救提示，不能计为自主闭环通过。未通过项可以形成有效的接入结论，不要求先把所有建模问题修好才结束调查；但不得据此把失败组合写成可用。下一步只补会改变接入决定的具体证据，不默认转为自研运行内核或质量体系，也不把候选未测试写成失败。

#### 实例、配置与启动前提

本小节保留既有 ChatGPT 登录实验的部署事实；Qwen 独立控制目录与 API key 装配见第 7 节复验说明。两者不能互相代替模型或认证证据。

该命令中的模型是**历史实验连接**，不是 Qwen 直连示例。实验入口创建两个带本次标签的新容器，控制容器运行 `/opt/codex/bin/codex app-server --listen stdio://`；Python 客户端连接 `docker start -ia <control>` 的 stdio，再通过 `environment/add` 连接本次执行容器的 `exec-server`。它没有连接开发用 app-server 的 socket、线程或现存实例。实验装配管理容器／网络，原生运行时管理建模循环和工具进程；关闭本地 stdio 子进程不等于工具已经停止。

## 6. 失败、取消与恢复

| 情形 | 行为与待实测边界 |
| --- | --- |
| 模型连接、工具或权限不满足 | 返回具体缺口；不以替身成功、空反馈或扩张宿主权限掩盖失败。必要 Skill 调用方式若不同，只适配明确差异。 |
| 脚本错误、渲染失败 | 实际输出和错误沿原生工具回到原生 Agent，由其理解并决定预算内修订；宿主不翻译成修复步骤，普通修订不创建业务 Attempt。 |
| 图片读取／投递失败 | 保留原生失败反馈，不能把文件存在或业务摘要冒充模型已收到图像；恢复后通过原生机制继续。 |
| 用户停止或执行超时 | 向原运行时／实际生命周期所有者发送请求；受理不等于进程及子进程已退出。实际停止与排空前不提前回收仍在使用的环境。 |
| 实验接入连接断开 | 核对原生会话和运行事实，不默认重提任务；连接断开是否终止执行按所选接口实测，独立命令接口结论不能外推完整线程路线。 |
| 控制进程重开及未验证的崩溃情形 | 分别核对原生历史、任务工作文件、关联和进程；会话恢复不证明进程续接。当前有限实验不承诺宿主崩溃或执行环境丢失后的恢复，没有证据时明确不确定，不启动新进程冒充恢复。 |
| 实验输出接收失败 | 按有限接收路径保留可取得的文件和已有记录，单独说明接收失败，再清理实验环境；不自动重复建模，不为工作文件增加快照或正式登记。 |
| 原生轮次结束但小型目标未完成 | 根据终止时产物如实记录该次任务未完成；不自动续发补救，不建立外部质量返工循环，任务结论与原生终态分别保留。 |

日志是有限诊断窗口，不是原生会话备份或业务账本。清理规则按实际生命周期设施验证，不能增加第二个控制者同时取消、重试或回收同一次执行。

阶段 A 已实测的恢复范围：空闲轮次结束后关闭本地 stdio 连接，实际停止控制容器，保留原生历史目录与存活执行容器，重新连接原环境并按原 thread 恢复，可继续使用先前文件。该结果不包括宿主崩溃、执行容器重启或原运行进程续接。旧实验没有证明恢复后默认工具环境被限制到任务侧；本次 Qwen 暴露的缺口、原生重绑修正及实际拒绝证据见第 7 节。实验 `/work` 是 tmpfs，执行容器停止／删除后不可恢复；原生历史和已复制的实验输出仍在各自目录。请求断连或结果不明时客户端不重发，失败路径仅尝试取得已有输出后清理，不创建新线程冒充恢复。

既有 GPT 第 4 次的 30 秒停止实验取得 `interrupted` 后，原生后台终端列表和 Docker 进程表中仍存在心跳 Python；随后 `thread/backgroundTerminals/clean` 才使该进程消失。该清理由原生运行时管理具体工具进程，Docker 在实验结束时停止和删除环境。Qwen 复验出现了该接口未覆盖的脱离终端进程，见第 7 节；不能把 turn 终态或空终端列表直接投影为“所有进程已停止”。本地连接客户端 PID 也不等于控制容器或工具 PID。

既有 GPT 第 4 次记录仅覆盖其后台心跳进程：原生清理后进程表只剩 `exec-server`；没有用该取消实验覆盖运行中的 Blender、主动脱离终端的后代进程或容器强制退出期间的排空。资源探针中 Blender／子进程命名空间一致是位置证据，不能代替这些停止证据。

## 7. 验收计划与执行记录

### 主验收：约束内的自主任务完成

**迭代、重复实验和干预。** 一次原生 `turn` 可以包含多次模型与工具交互；这些观察、修改、重试及再检查属于该任务的自主迭代，不限制其次数。新建目录／thread 重新开始属于独立重复实验，改变接入配置后更不能当作原任务自行修复。组合实验入口中的 `continued_turn` 是首轮结束并做控制重启实验后的独立倒角要求，不是自动发现首轮不达标后的补救；也未证明自动评估反馈驱动的跨轮返工。

执行期间人工追加纠正提示、改脚本、修复环境或替做步骤，均不能计为无人工补救完成。预先准备夹具和授权环境、提供初始 Skill、事先约定的自动检查事实反馈不属于临时人工补救，但须明确来源；新要求与原任务返工分开记录。事后检查产物不改变执行期是否自主。计划内的控制重启、边界检查和停止故障实验分别取证，不纳入正常建模目标完成率；故障导致的中止不能反向改写此前已结束任务的产物结论。

**当前实现核查。** [实验入口](../../../../src/vet3d/experiments/native_agent_stage_a.py)及[轮次消费者](../../../../src/vet3d/experiments/native_agent_run.py)没有读取 GPT 轨迹或比较模型动作；事件计数仅作诊断。模型／provider 回执核对防止连接被静默替换，单测中的顺序／次数断言覆盖握手、不重交、单次中断等协议，不是 Agent 行动模板。首轮及追加轮次的 `completed` 分支只决定是否继续后续实验，没有产物语义自动断言或总体通过字段。上次口径核查仅澄清这两处异常文案；本轮新增的单任务选择跳过其后故障实验，并在初始输入中明确完成条件和期限，不增建验收控制循环。产物与能力结论继续按原生记录和实际交接文件复核。

阶段 A 的交付是有界实验及足以支持接入决定的证据，不是产品建模能力。应分别说明：实验实现／证据整理是否完成、该组合是否完成声明的小型任务、运行边界支持到哪里，以及据此继续接入、限定范围或暂缓的理由。取得负面结果也可完成一次调查，但不等于该组合通过；不以追加真实动物质量、正式资产或生产部署建设延长阶段 A。

当前实验实现和已执行记录可交付。Qwen 直连、真实工具／图片反馈和有限控制重启接续已有证据；旧三次及明示条件后的三次正常任务均未完整完成目标，不能宣称该组合已通过自主小型任务验证。独立用例已有受原生终端管理的父子进程清理证据，脱离终端进程等覆盖仍有限。环境重绑修正只对已测原生路径取得拒绝证据；原始 Hi3D 一次有权限确认的成功不替代 Qwen 或无人交互结论。范围收敛不改判这些结果。

后续规划可以消费上述事实及明确限制，但本卡不放行产品服务、正式资产交接或上层质量流程。首次实际开放不可信执行仍须满足 [L1-01 交接条件](L1-01.md#开放不可信执行的必需条件)；未验证路径不因此获得授权。M1／M2 状态不因实验材料交付而自动变化，生产多任务授权、持久工作文件、完整崩溃恢复与动物质量不作为阶段 A 必须实现的前置。

`qwen3.7-plus`／DashScope、Codex 0.165.0 和当前 Docker 装配是实验配置，不自动成为生产承诺。进一步补证仅在其结果会改变接入决定时安排，复用已有入口并在运行前限定问题、次数与结束条件：例如独立启动前提是否成立，或所需进程形态能否沿原生机制停止和回收。现有资料已能回答的问题不重跑；小型目标遗漏不自动派生布局研究、更多样例、模型替换或质量返工链建设任务。

有限宿主接入现由单独获准的 [阶段 B](L2-02-B.md)维护；正式交接与完整产品范围仍另行指定。此前撤下的原详细阶段 B／C 计划，不将其要求改名转移至 L2-03 或其他条目；既有分层清单中有独立用途的后续职责及 L0／L1 已实现契约仍有效。
