## 3. 输入、输出与权威事实

### 准备与单次调用

用户材料可以不完整；本期服务接收的是已经准备的资料，不是 BFF 上传入口。五向准备的完整性由 L0-03 校验；后续补图失败、证据不足或路线选择由对应业务节点处理。

| `modeling` 公共类型 | 当前契约 |
| --- | --- |
| `GenerationPlan(input_ids)` | 非空且唯一的 `tuple[ArtifactId, ...]`；首项为操作主参考。只引用准备图，顺序明确，不复制方向或数量。可表达单图、四图、五图。 |
| `ReconstructionRequest(task, job, attempt, references, prepared, plan, files)` | 全部使用已有具体身份和引用类型；核对父链与任务参考，计划只能引用 `prepared.views`。`files` 为冻结的 `tuple[FileReference, ...]`，服务解析后核对其精确范围和内容。这是一次意图登记输入，查询／取消仅传原 AttemptId，不逐轮重复业务策略。 |
| `GeneratedArtifact(artifact, file, origin)` | ArtifactIdentity、FileReference、AttemptOutput 的关联组合，产物 ID 必须一致；不表示文件已下载、发布或通过验收。 |
| `ReconstructionUpdate(observation, outputs=())` | 唯一 AttemptObservation 与零到多个已知产物；输出唯一且属于同一观察尝试。活动、失败或取消时也可保留部分产物；成功允许没有输出，但不能交接非空候选。 |
| `SubmissionCompatible()` | 本次计划符合已知输入规则；不证明环境、凭证、额度或模型质量。 |
| `CapabilityUnverified(reason)` | 适配语义尚不能证实；与已有 CapabilityUnavailable 表达的本次已知不匹配分开。 |

四图计划不修改五向准备目标；顶图仍保存在准备集合中。当前计划未使用哪些图从集合差单向派生，不另存布尔状态。网关必须只映射计划选中的图，不能自行删图或替换主参考。首期尚不实现自动路线选择；探针使用两个明确给定的计划。

### 三个实际消费端口

| 所有者／端口 | 方法与责任 |
| --- | --- |
| `artifacts.ArtifactAccess` | `resolve(ArtifactId) -> LocatedArtifact | None`；`observe(WorkspaceFileLocation) -> FileObservation`。均异步。None 仅表示未登记；访问故障不伪装成元数据缺失。 |
| `modeling.ReconstructionPort` | 同步、无 I/O 的 `check(request)` 返回匹配、不匹配或未证实；异步 `submit(request)` 返回更新或 SubmissionUnconfirmed；`query(AttemptId)` 返回更新或 QueryUnavailable；`cancel(AttemptId)` 返回取消回执或 CapabilityUnavailable。 |
| `application.ReconstructionRepository` | 异步 `claim(request) -> bool` 原子取得首次提交权；`get(AttemptId)` 读原记录；`record(AttemptId, event)` 原子归约并保存具体生成事件。没有通用表模型或全实体 CRUD。 |

`LocatedArtifact(artifact, reference, location)` 组合已有身份、内容与位置记录并复用其关联校验。文件观察必须对应请求的位置，存在观察与预期指纹一致才放行；这些检查仍不证明像素有效。

### 独立事实与记录

`execution.CancellationAcknowledged(attempt_id, reason)` 只确认取消请求已受理；`CancellationUnconfirmed(attempt_id, reason)` 表示未取得可信回执。`CancellationReceipt` 是这两者的联合。两者可以交给 `validate_attempt_fact`，但不属于 AttemptObservation，也不能交给 `reconcile_observation` 伪造终态。不支持发送取消时返回已有 CapabilityUnavailable，原记录保持不变。

`application.ReconstructionRecord` 保存：

- `request`：原冻结意图与预期内容，不能被后续回包改写。
- `observation`：最近可信执行观察，初始 None 不表示受理。
- `outputs`：累积已知产物；空更新不清除已有输出，同 ID 不允许内容或来源变化，不允许任何本次输入 ID 冒充新产出。
- `diagnostic`：**最近一次历史提交／查询诊断**，并非“当前阻塞状态”。后续成功可与旧诊断并存；本项不维护无界事件历史或重复状态字段。
- `cancellation`：最近取消请求回执，不替代执行观察。

`apply_reconstruction_event` 是唯一用例归约规则：复用执行观察对账、内容绑定及产出父链校验，返回新冻结记录。仓储必须完整校验后原子保存，不能先更新观察再因输出非法留下半次写入。

## 4. IoC 与装配

稳定的数据对象、校验器和 ReconstructionService 使用具体类；三处可替换边界使用 Protocol，适配器显式继承。跨包调用只使用各包 `__init__.py` 的公开入口。

`bootstrap.assemble_reconstruction(task=..., artifacts=..., generator=..., repository=...)` 注入固定任务范围及依赖。服务不导入 adapters、bootstrap、host、SDK、Settings 或数据库。请求携带待核对的身份记录，不能改变实例的任务作用域；同区的其他任务也不能查询或取消本实例的尝试。

具体替身：

- `SyntheticArtifactAccess`：显式元数据和显式观察；没有观察时返回 FileUnavailable，不凭元数据制造存在事实。
- `MemoryReconstructionRepository`：唯一记录字典，单事件循环内原子登记及归约。相同 Attempt 的相同请求只读回；改参拒绝。同 Job 的其他 Attempt 不能改变执行意图，且仅在全部旧尝试已确认失败或取消时允许显式登记。未知、活动或成功尝试不能通过换 Attempt 绕过重复执行守卫；此先决条件不提供自动重试或预算许可。
- `FiveViewGenerator`：接收有效的一至五张计划，首次提交即时返回合成成功及一个输出声明。
- `FourViewGenerator`：只接收四种侧向业务方向且首图为正面的计划；首次活动、第一次查询不可用、第二次查询成功。取消受理后可在后续查询确认取消；既有成功不会因取消请求变成取消终态。

两生成替身各自保存原 Attempt 绑定，没有绑定则不可查询／无法确认取消。它们不是供应商仿真，不宣称与任何品牌的完整参数或质量相同。没有 Mock 模式环境变量或新旧架构开关。

## 5. 正常流程与副作用

1. 核对实例任务与请求身份；相同已登记请求直接读回，避免文件后来不可用或能力变化触发重交。
2. 首次路径解析冻结的文件引用，核对完整准备集合、同区归属和独立内容，再检查对应位置的存在观察及指纹。
3. 对具体计划做语义匹配。未登记素材返回 InputInsufficient；能力不匹配／未证实返回对应声明；契约错误或不满足文件观察守卫抛明确异常。此时不取得提交权、不调用生成。
4. 原子 claim 成功后才调用一次 submit。登记只是保留意图，不能制造 AttemptActive。并发登记未取得提交权的调用读回原记录。
5. 核对回包并独立保存观察、诊断、取消回执或产物。查询／取消每次只调用一次，没有内部轮询或重试循环。
6. `read` 核对原任务范围；`candidate_references` 要求可信成功与非空输出。返回的只是候选引用，不是质量验收、版本发布、已下载文件或外部保存证明。

本期副作用仅为替身绑定及内存记录。探针创建两个不同 Job／Attempt，在同一任务上分别使用五图和四图，明确执行有限查询步骤，重新装配消费者读回记录。无模型费用；不实现产品成本预算或自动修订策略。

## 6. 失败、取消与恢复

| 情形 | 当前行为及恢复边界 |
| --- | --- |
| 预检或 claim 失败 | 不提交；仓储提交权未确认时也不得尝试调用生成。 |
| 已 claim、尚无观察 | 不知道是否受理；相同请求只读回，不能自动恢复提交权。进程在登记后提交前退出也不保证能自动补交。 |
| 提交异常／本地取消 | 尽力保存 SubmissionUnconfirmed 并继续抛原异常或 CancelledError；不生成执行失败／取消，不重提。 |
| 提交回包不合法 | 拒绝非法事实，保留原意图，后续只对账原尝试。 |
| 查询失败／中断 | 保存 QueryUnavailable，保留可信观察及已有输出；不创建新 Attempt。 |
| 取消请求受理／不明 | 独立记录回执；只有后续可信观察才可以确认 AttemptCancelled。取消请求后得到成功也允许保留。 |
| 不支持取消 | 返回 CapabilityUnavailable，不制造取消回执或更改原观察。 |
| 外部结果已取得但保存失败 | ReconstructionRecordingError 携带原 Attempt 和待对账事件，并保留底层原因；原意图不释放。结果记录期间本地取消仍传播 CancelledError，事件保留在异常原因链。 |
| 错任务／错尝试／冲突内容 | 作用域或归约校验拒绝；内存仓储不部分更新。 |
| 成功但无输出 | 保留成功事实，拒绝候选引用交接，可继续查询原尝试。 |
| 新消费者、原内存仓储及适配器仍在 | 可以读回并继续查询；这只证明同进程重装配。 |
| 仓储在、适配器绑定丢失 | 查询返回不可用，不按新默认供应商猜测原任务，也不重新提交。 |
| 进程重启 | 内存记录和绑定会丢失；本项不具备重启恢复。持久事实和原远端绑定的恢复留给 L1-04、L2-03／05。 |

本地等待期限与远端终态分别处理。探针由 Bootstrap 的真实 asyncio 期限限制；超时退出不声称执行端已停止。没有用轮询次数耗尽冒充时间期限到达。

## 7. 验收计划与执行记录

在仓库根目录复现：

```bash
uv sync --locked
uv run --locked python -m unittest discover -s tests/runtime
uv run --locked mypy
uv run --locked vet3d-contract-probe
uv run --locked vet3d-demo --text '中文装配核查'
uv build
git diff --check
```

探针 stdout 是一份 JSON，`evidence=synthetic_contract_probe`、`quality_assessment=not_run`；两次运行均保留五向准备，实际选择分别为五图和四图。字段从原记录派生，不反向参与业务判断。stderr 为关键事件。退出码为成功 0、CLI 参数错误 2、超时 124、取消 130、其他失败 1。首次同步可能下载已锁定的开发依赖；本次实际使用离线缓存完成同步与构建。

本次环境为 Debian、CPython 3.14.6、uv 0.11.25、mypy 2.4.1、Hatchling 1.33.0。旧条目的历史测试数量不作为本次新增覆盖证据。
