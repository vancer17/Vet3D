## 2. 前置与消费者

- L0 的 `TaskIdentity` 仍是任务到工作区的唯一直接关联；不把原生 thread、turn 转成内部 UUID，也不逐工具建立 Job／Attempt。
- L1-01 的真实工作区注册由宿主查询；UUID 和登记都不是外部调用者授权。有限 CLI 是受信操作入口，BFF 身份认证尚未接入。
- L1-03 的已安装资源可按原 `ResourceReference` 读取依赖闭包。资源内容校验仅用于资源交接，不冻结可变代码或任务输入。
- L1-05 的唯一 Settings、路径解析及诊断继续有效；L2-01 的有限环境检查与隔离授权不同，不新增同义 readiness 类型。
- 阶段 A 提供原生 provider、工具、图片反馈、环境重绑及有限恢复证据；未提供产品接口或持久任务关联。
- 本期具体消费者是 `vet3d-agent-probe` 及可信 Python 宿主。未来 L3／L8 真正需要业务端口时，由消费方定义所需边界，不预建万能 AgentPort。

## 3. 输入、输出与权威事实

可信宿主提交原 `TaskIdentity`、输入根内明确授权的资料目录、目标文本，以及可选受管资源／Skill。模型、provider、连接地址和凭证变量名只在专用原生 TOML 中维护；它们不在每轮 Command 重复声明。配置不定义业务动作或发布资格。

`NativeSessionBinding` 保存原任务和原生 thread 关联。会话所有者在内存持有授权环境；该记录不冒充产品任务登记或重启账本。原生轮次和工具事实以运行时为准，环境存活与停止以实际容器为准。没有同形状态枚举、镜像历史或逐工具业务回执。

会话返回原生轮次对象并向受信事件消费者交付原通知；已确认终态通过 `last_terminal` 保留，观察回调失败不能改写它。连接故障前已完整接收的通知仍可读，队列耗尽才报告故障，新请求始终拒绝。未知通知不压缩成成功／失败，命令输出、错误和图片继续在原生模型工具循环中反馈。CLI 只展示有限进度与技术终态；退出零不表示目标完成或业务验收。

首轮远端 `localImage` 路径未作为本期公开支持项。任务图片通过授权目录及已验证的原生 `view_image` 路线进入模型；Code Mode 必须实际调用 `image(...)` 交付图像，不能只打印路径或长度。

任务副本可修改，不记录脚本／参数指纹、输入快照或执行字节追溯。只读受管资源与正式资产的独立完整性约束仍按原卡有效。输出复制只服务有限诊断和集成验收，不登记资产，也不保证正在并发写入的多文件具有同一状态。

## 4. IoC、接口和装配

`adapters` 公开具体原生连接、会话和环境实现；`bootstrap.AgentRuntime` 注入已有工作区、资源、配置及任务关系。现有业务包不导入 Codex 协议。跨包只使用 `__init__.py` 公共导出，不增加只做同形转发的 Application 服务。

| 位置 | 当前职责 |
| --- | --- |
| `adapters/codex_protocol.py` | 单连接读取、RPC 回执关联、有界原生通知、明确协议失败；不调度工具。 |
| `adapters/codex_session.py` | 开始／恢复线程、提交或继续轮次、事件消费、原轮次取消与原生查询；不制定建模步骤。 |
| `adapters/codex_environment.py` | 本次 Docker 资源、任务环境期限、停止及清理；不管理每个工具的业务状态。 |
| `bootstrap/agent.py` | 可信资料和受管资源接入、真实工作区核对、环境准入与所有权、连接装配。 |
| `host/agent.py` | 有限非交互命令；不实现 BFF 服务。 |

当前可信 Python 消费入口如下，所有调用保留原对象与关系：

- `AgentRuntime.open_session(task, materials, resource=..., turn_timeout_seconds=...)`：核对已登记工作区并交付具体会话；同 TaskId 改工作区也不能重复准入。
- `CodexAgentSession.run(goal, on_event=..., skill_name=..., skill_path=...)`：一次原生轮次；前轮明确结束后可继续提交来源明确的新目标。`cancel()` 请求原轮次中断，`read()` 读取原线程，不能通过查询解除结果不明后的新提交禁令。
- `AgentRuntime.reconnect(session)`：仅在明确空闲的原会话重开控制面并返回替换对象，旧对象不能再用于环境操作。
- `copy_outputs(session, destination)`：有限诊断复制。`close_session(session)`／`aclose()`：排空原复制、重连及创建，收口实际环境。取消等待不会丢失实际 I/O 所有权。

原实验入口消费同一份协议／环境实现，合成材料和阶段 A 特有实验步骤继续留在 `experiments`。删除被迁移实现，不保留没有消费者的兼容类别名。历史执行证据不随源码提取而改变；当前重新运行实验会使用本期实现，不能声称复刻旧装配。

### 配置与运行入口

沿用 `load_settings` 的优先级和 YAML 相对路径规则，新增可选 `agent` 部署段。未配置时旧三个 CLI 不启动或依赖 Agent。`agent` 指定已有 Codex 发行目录、确切本地镜像、专用原生配置、私有控制根、同一 Docker context、环境寿命及最大会话数；不拉取镜像、复制开发认证或修改全局代理。

在既有 L1-05 YAML 中增加的可选部署段示例（路径相对 YAML 目录固定）：

```yaml
agent:
  codex_package: /path/to/codex-vendor-directory
  native_config: native.toml
  control_root: private-agent-control
  image_id: sha256:LOCAL_VERIFIED_IMAGE_ID
  docker_context: default
  lifetime_seconds: 1200
  max_sessions: 2
```

`model_http_proxy` 仅在实际模型网络需要时显式提供；默认不继承开发代理。环境期限为 1～86400 秒，另有 5 秒强停宽限；当前每容器固定 2 CPU、2 GiB 内存、128 PID，任务可写 tmpfs 为 192 MiB、临时目录 64 MiB，单文件限制 32 MiB。任务资料和诊断输出各限 128 成员／32 MiB；原生通知缓冲 128 条、装配单消息 4 MiB。它们限定本期资源使用，不定义业务能力或发布资格；未验证环境池、GPU或其他资源规格。

原生配置只支持本期消费者所需的单 Responses provider、模型及可选推理设置；凭证通过该 provider 的 `env_key` 在控制侧注入，不放入 argv、任务文件、执行侧或回包。额外工具／插件／hooks 等不由这份配置带入；扩大支持范围须验证其实际权限，而不是忽略未知配置。

有限调用使用已登记工作区，示意命令中的目录和身份须由可信调用方提供：

```bash
vet3d-agent-probe --config /path/to/config.yaml \
  --workspace-id WORKSPACE_UUID --task-id TASK_UUID \
  --materials /path/to/authorized-inputs/task \
  --goal-file /path/to/goal.txt
```

可显式增加 `--continue-file` 传递一次独立追加要求，以及 `--skill-name`／`--skill-path` 选择已提供的 Skill。普通业务继续可以自动来自领域事实，但本期 CLI 不解释反馈或循环生成补救输入。具体参数以安装后的 `--help` 为准。

## 5. 正常流程与副作用

1. 校验唯一配置和资料范围，查询原工作区注册；同任务重复或环境额度已满时直接拒绝，没有无界等待队列。
2. 创建本次私有控制状态及可变资料副本，按需从 L1-03 读取资源。准备不是任务输入冻结，也不以资源存在推导已被 Agent 使用。
3. 创建控制侧和任务执行侧环境；原生命令、文件与图片操作选择同一任务环境，控制凭证及管理接口不挂入执行侧。
4. 握手核对受支持版本，登记原环境，核对 thread/model/provider 及额外工具来源后才提交目标。
5. 原生 Agent 自主工作。每轮明确绑定授权环境；事件消费与 RPC 回执分离，读取通知不会锁住取消请求。
6. 已确认终态后才允许下一轮；请求不明不重发。结果／文件／目标完成／正式交付分别判断。
7. 关闭时先处理原生中断及终端清理，再由唯一环境所有者终止整个环境；实际清理完成才释放额度。

容器生命周期复用镜像现有 GNU `timeout` 和 `setpriv`，不新增常驻回收器。root 计时进程仅保留启动降权及跨 UID 发停止信号需要的能力，原生执行进程降为宿主数值 UID／GID、补充组及有效能力清空；已测身份、信号和子进程范围见第 7 节。环境期限不因轮次或控制重连重新延长；期限停止与容器／网络元数据删除分别判断。适用结果见第 7 节，不由启动参数推导隔离通过。

## 6. 失败、取消与恢复

| 情形 | 行为与边界 |
| --- | --- |
| 配置、工作区或素材范围错误 | 启动模型前拒绝；部分准备失败保留实际错误并清理本次拥有的资源。 |
| 创建期间取消 | 等待原创建交回确切资源后关闭；不遗失仍在运行的 I/O，也不重做创建。 |
| RPC 回执丢失、断连或缓冲超限 | 原连接不可继续提交；已完整收到的原通知仍可取得，其余受理／观察情况不明。不把错误当作未执行，不自动重发。 |
| 用户取消／轮次期限 | 对原 turn 请求中断；受理、`interrupted`、终端清理及实际环境停止分别处理。 |
| 原生终端之外的进程 | 原生 clean 不足以证明停止，最终由实际环境终止收口；不新增逐进程业务监督。 |
| 关闭失败 | 环境或暂存目录清理未完成时保留原关联和名额。仅原生 close 报错、但环境与目录均已清理时释放名额，同时报告原错误。 |
| 控制进程重开 | `AgentRuntime.reconnect` 只接收本实例拥有、无在途轮次且结果明确的原会话；恢复原 thread 并重绑仍存活环境。失败保留原清理所有权，不重建工作目录，不续接未知 Blender 内存场景。 |
| 整个宿主进程丢失 | 不承诺自动找回任务关联。环境期限限制残留运行；资源元数据可能需明确清理，不自动扫描并认领。 |
| 执行环境结束 | tmpfs 文件丢失；新空环境不冒充原任务恢复。 |
| 技术输出可用但目标遗漏 | 保留真实结果，不发布业务通过，也不由接入层启动外部修复循环。 |

控制状态仅供本次会话和有限诊断使用，不是长期产品账本；正常关闭清理本次私有目录。原生反馈和状态不能由诊断摘要恢复。正式资产持久化、任务持久关联及业务重启对账不在本期实现。

### 本次真实环境检查

使用已存在的本地镜像 `sha256:7c581df61df4ac315ab5157a1ff2a436f316394a5a36c1bd27acff2b5b7c9844`、明确 `default` context，所有创建均禁止自动拉取。本地记录根为 `~/.cache/vet3d-l2-02-stage-b/environment/`，不是产品账本或长期证据服务：

- `run-01` 的初版期限检查确认只读资源拒写、任务工作文件可改、`/control`／Docker socket／宿主仓库不可见、无外网路由。后续加入 root 计时器的跨 UID 停止信号权限；初版耗时不作为最终配置依据。
- `run-03` 使用最终配置，20 秒环境期限内强杀创建环境的 Python 宿主；没有其 `finally`，仍在原截止后约 0.93 秒观察到执行容器停止。所记录的 root init／timeout、exec-server 及脱离终端的子进程四个宿主 PID 全部消失。观察延迟不是所有机器的停止保证；配置允许另有 5 秒强制停止宽限。
- `run-04` 在同一 30 秒期限内关闭并重开控制进程，环境仍按原截止停止，没有重新计时。实际 exec-server UID／GID 为 1000，补充组空、有效／许可能力为空、`NoNewPrivs=1`；任务用户向 root 计时进程发 `SIGSTOP` 被拒绝。`run-02` 曾因本地验证脚本遗漏 `experimentalApi` 而失败，原记录保留，不能计为通过。
- `run-05-parallel` 同时启动两个环境：文件互不可见、两个内部网络互不通；停止 alpha 后 beta 仍能读取原文件、写入并取回输出。不是宿主压力测试或多租户隔离总验收。

环境期限负责实际停止；容器／网络元数据仍由明确所有者清理，宿主强退后不会自动清扫或认领。所有本次验证资源已清理。控制历史只有单文件上限和本次正常退出清理，没有宿主崩溃后的总占用配额或持久恢复能力。

原线程 `01a21286-f5d0-7fa2-ade5-19c417218ee2`：首轮在总开始后约 146 秒结束，控制重开后的追加轮次约 43 秒，包含清理的整体约 191 秒。原生握手及模型选择校验通过，恢复使用同一 thread 并显式选择原任务环境；没有复制原生推理历史构造新的会话。

原生记录证实合成 Skill 文本实际进入输入，Agent 读取六份已提供参考，调用 `material_nodes.principled_material`；`preview_scene` 文件被读取不等于其函数已调用。旧 `Specular` 接口出现真实 `KeyError`，Agent 自行修改代码并重渲染；随后根据实际预览再次调色。原生历史的 `function_call_output` 包含 5 次 `input_image` 实际图像内容（首轮3次、追加2次），不只记录路径或工具名。
