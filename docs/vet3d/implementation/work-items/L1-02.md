## 3. 输入、输出与权威事实

### 复用现有记录

| 记录 | 在本项中的角色 |
| --- | --- |
| ArtifactIdentity | 原产物身份及唯一工作区归属；固定实例作用域须与此记录一致。 |
| FileReference | 调用者保留的确切预期内容，实际复制后核对 SHA-256 和字节数。 |
| WorkspaceFileLocation | 同一产物的相对位置，不重复保存工作区。 |
| FilePresent | 真实读取所得位置和指纹；存储成功返回此观察，不自动构造 LocatedArtifact 或登记回执。 |
| FileMissing／FileUnavailable | 已确认缺失与访问未完成分别表达，访问错误不能降级为缺失。 |
| ImportOrigin／Derivation／AttemptOutput | 继续按原卡表达接入说明、派生和执行产出；本项不推断或持久保存这些关系。 |

类型字段和纯校验细节引用 [L0-03](L0-03.md#文件快照定位与出处)、[L0-04](L0-04.md)，不再建立 FileState、StoredArtifact、ContentVersionId 或“原件”布尔值。相同内容允许属于不同产物；内容变化必须使用新 ArtifactId。

`location_for` 只派生位置，没有读取磁盘或登记的副作用。当前适配器位置由 ArtifactId 单向生成 `files/<规范 ArtifactUUID>`，不把输入文件名、显示名、后缀或来源标签用于目标定位。物理布局不是外部 BFF 协议；上层保存返回的位置，不自行拼接根路径。

最终文件与临时文件有不同语义。最终位置对应调用方传入的 ArtifactId；复制中的随机技术文件名只用于独占临时写入，不能作为新产物、登记状态或恢复授权。目录中存在一个 UUID 文件不能证明此身份已登记，也不能证明它历来只绑定过这一份内容。

### 输入授权与源文件生命周期

低层 `store_new` 借用已打开的普通文件，从文件描述符的起点读取完整字节；不改变调用方文件游标、不关闭源。当前适配器要求源属于当前用户、仅有一个硬链接，权限为 0400 或 0600。调用者在实际操作终结前保持句柄有效，并保证无并发修改。它不是网络流、压缩包展开器或任意可调用对象的执行入口。

异步宿主固定输入暂存根，只接收该根中的单个 `input_name`。根由可信部署端配置，须与受管存储分开且不能互为父子路径；业务请求不能提交任意宿主绝对路径。绑定时只校验配置与工作区，实际保存时再打开暂存根，要求其已存在、属于当前用户且权限为 0700，父路径不能含链接。绑定成功不证明输入根或文件此刻可访问。

输入名须为非空、可编码 UTF-8 的单文件名，拒绝 `.`、`..`、斜杠、反斜杠和控制字符，不裁剪或展开路径。名字不作为产物身份或来源事实。工作线程打开并持有源到实际操作终结，因此取消等待不会由调用方提前关闭正在复制的源。

`max_file_bytes` 是装配时必填的正整数、排除 bool，限制一次真实文件读写的字节规模；不是图片格式、模型能力或业务验收阈值。通用文件允许零字节，具体图像／模型消费者另行检查有效内容。不增加基于 MIME 或后缀的多档兼容配置。

### 当前可证明与不可证明的事实

实际存储及重新观察只能证明本次取得的文件字节与指纹。预期 FileReference 由调用者保留，本项没有持久产物索引或全局历史绑定；不能证明文件被删除后同 ArtifactId 从未被重新使用，也不能在调用者丢失原引用后扫描目录推断来源。

原件保存不修改源字节、不生成 JPEG、不自动归一化 EXIF、不生成预览。后续需要转换时，使用新产物及现有 Derivation 关系；本期不执行转换或持久登记派生边。

## 4. IoC 与公开接口

### 接口与所有者

| 公共入口 | 语义 |
| --- | --- |
| `artifacts.ArtifactFileStore` | 同步 I/O Protocol，由真实文件消费者拥有；具体适配器显式继承。 |
| `location_for(artifact) -> WorkspaceFileLocation` | 校验固定工作区后纯派生位置，不查询、创建或登记文件。 |
| `store_new(artifact, reference, source: BinaryIO) -> FilePresent` | 对完整实际字节进行复制与指纹核对，最终无覆盖提交；已有目标一律拒绝，包括同内容重放。 |
| `observe(artifact, location) -> FileObservation` | 校验作用域和本实现的派生位置，再真实读取；不比较预期内容。 |
| `validate_file_scope(artifact, *, workspace_id, reference=None, location=None)` | 复用现有类型与关联校验；不访问磁盘或证明授权。 |
| `adapters.LocalArtifactFileStore(root, workspace_id, *, max_file_bytes)` | 绑定真实受管根、固定工作区和资源限额；具体路径及 OS 操作留在适配层。 |
| `await runtime.files(workspace_id, *, input_root, max_file_bytes)` | 在原工作区宿主中核对已提交登记及目录，装配固定输入暂存根，返回具体 WorkspaceFiles。 |
| `WorkspaceFiles.location_for(artifact)` | 同步派生位置；不因已有一个位置对象而宣称可以访问。 |
| `await WorkspaceFiles.store_new(artifact, reference, input_name, *, timeout_seconds=5.0)` | 受信宿主入口；在实际工作线程打开单文件名对应的输入，执行真实保存。 |
| `await WorkspaceFiles.observe(artifact, location, *, timeout_seconds=5.0)` | 在原工作区宿主中取得真实观察；观察的范围和时刻不自动扩大。 |

以上接口已接通源码并完成本项验证。通过 `runtime.files` 取得 WorkspaceFiles，不直接构造未核对的实例；配置根在装配时固定位置，不随后续 cwd 变化重新解释。本项提供字节存储，ArtifactAccess 的持久实现及登记查询由 [L1-04](L1-04.md)维护。

`WorkspaceFiles` 是稳定的具体装配对象，不额外建立同形服务 Protocol。它复用原根所有者的生命周期，不自行打开第二个写入实例。文件 I/O 与短元数据调用已分开装配，当前准入、容量、等待期限及关闭规则统一见 [L1-04 第 4 节](L1-04.md#4-ioc-与公开入口)；本项不承担分块抢占或模型调度。

### 实现位置与依赖

| 位置 | 职责 |
| --- | --- |
| `src/vet3d/artifacts/storage.py` | 同步端口与局部关联守卫，仅依赖 identity 公共入口及本包已有类型。 |
| `src/vet3d/adapters/artifact_files.py` | LocalArtifactFileStore 实现真实目录访问、复制、散列、限额和观察；`validate_file_byte_limit` 由装配复用校验唯一资源上限。 |
| `src/vet3d/adapters/file_commit.py` | Linux 无覆盖提交原语的集中封装；不参与业务身份、登记或验收。 |
| `src/vet3d/adapters/staged_inputs.py` | 受信输入暂存根和单文件名的实际打开边界；只返回由调用者持有的普通文件句柄。 |
| `src/vet3d/bootstrap/workspaces.py` | WorkspaceRuntime.files 与 WorkspaceFiles 固定输入范围和端口，管理源句柄生命周期、工作区登记核对及日志；当前线程装配由 L1-04 第 4 节维护。 |
| `src/vet3d/adapters/workspace_directories.py` | 增加受信适配内部所需的工作区目录句柄入口，复用既有根及对象检查，不把它作为外部权限凭证。 |
| 各包 `__init__.py` | 公开本期必要类型和装配入口；跨包只使用公共导出。 |

当前无覆盖提交采用 Linux `renameat2(RENAME_NOREPLACE)` 的适配层封装，通过标准库 ctypes 调用，不新增第三方依赖；不可用时明确失败，不回退到会覆盖目标的 rename／replace，也不以硬链接给源和最终文件建立可共同修改的字节。最终普通文件设为 0400；目录与文件的具体安全属性在适配器检查，不能因此宣称抵御同 UID 恶意写入者。

没有为测试更换业务架构的运行开关。真实字节观察和存储行为使用实际文件系统验证；持久目录接入消费链的证据由 [L1-04 第 7 节](L1-04.md#7-验收计划与执行记录)维护，不沿用本项历史登记替身结论。日志沿用 Bootstrap 的有界输出，文件操作关联 WorkspaceId 和 ArtifactId；FileUnavailable 记录明确诊断，不能仅因方法返回就记为文件存在。调用宿主负责用现有 configure_logging 初始化输出，输入名及文件内容不作为整块日志转储。

## 5. 正常流程与副作用

| 步骤 | 核对与处理 | 副作用及结果 |
| --- | --- | --- |
| 1 | 可信宿主打开 L1-01 根，核对工作区已登记，装配固定输入根和显式限额。 | 不改变工作区登记时间；不创建 Task、Session 或产物记录。 |
| 2 | 核对 ArtifactIdentity 与固定工作区并派生最终位置；输入打开入口校验单文件名。 | 非法范围不能借路径进入其他工作区或控制目录。 |
| 3 | 在实际工作线程安全打开输入；低层存储校验 FileReference 关联，再核对源的实际属性和大小。 | 取得由宿主持有的源句柄，不修改源内容；引用不合法时不进入复制。 |
| 4 | 独占创建技术临时文件，有限分块复制并计算 SHA-256／实际长度。 | 临时字节不是已提交文件，不能给上层补造登记或发布。 |
| 5 | 核对实际内容与预期引用，检查源及目标观察仍适用，同步完整文件。 | 指纹不匹配不进入最终提交；不自动更换预期内容或 ArtifactId。 |
| 6 | 以不覆盖已有目标的操作提交到派生位置并同步目录。 | 最终文件可见；同步或应答失败时可能已经存在最终字节，必须原引用对账。 |
| 7 | 返回 FilePresent，或另行 observe 后调用既有 require_matching_file。 | 文件观察、登记、业务验收和发布分别处理，不生成 pass。 |

`observe` 不遍历目录：在固定工作区核对精确位置，打开普通文件并从同一描述符计算指纹，核对读前／读后的设备、inode、大小、时间、链接数、属主和权限，并核对实际目录项。工作区存在且安全时，缺少 `files` 集合或精确最终目标返回 FileMissing；工作区不可访问、权限／类型／链接／限额异常或读取中变化返回 FileUnavailable。错类型、跨作用域或位置并非该身份的派生位置直接拒绝。生命周期与线程误用仍按宿主或适配器异常处理，不把它们伪装为磁盘缺失。

已有最终文件若在观察前被改为另一份内容，但当前文件属性仍合格，返回其真实 FilePresent 指纹；调用方再用原 FileReference 和 require_matching_file 判断是否满足交接。适配器不因为内容不符合预期而改写为“缺失”，也不持有另一份预期摘要。

## 6. 失败、取消与恢复

| 情形 | 当前范围及恢复出口 |
| --- | --- |
| 错类型、跨工作区、引用错配或位置非派生位置 | 拒绝，不把另一个身份／路径自动修正成本次目标；纯关联错误沿用 TypeError／ArtifactContractError。 |
| 源不合格、内容不匹配或超限 | 不提交最终目标，不重编码、不截断为合格内容；调用者保留原引用核对。 |
| 同身份目标已经存在 | 无条件拒绝覆盖，即使字节相同；调用者使用原引用显式 observe，不把重送 store_new 当作登记恢复。 |
| 复制或提交之前失败 | 普通异常只清理本次独占创建、且仍指向原 inode 的临时名；清理失败附加原因并保留现场。已创建的 files 集合不自动删除，强制退出可留下技术残留，不扫描或认领。 |
| 最终名字已提交，目录同步或应答失败 | 调用报错不等于最终文件不存在；原引用可重新观察，不能盲目覆盖或宣称未发生副作用。 |
| 等待被取消或超时 | 不能证明实际工作停止；源句柄与在途占用由宿主持有到操作终结，沿原 ArtifactIdentity／FileReference／位置核对。 |
| 工作区目录失效、根关闭或第二实例进入 | 沿用 L1-01 的拒绝及保留现场语义，不重建空目录承接新字节。 |
| 新进程打开同根 | 只按调用者保留的原身份、位置、指纹重新观察；不恢复内存输入根配置，不扫描、登记或自动续传。 |
| 临时残留、缺少原引用或历史绑定不明 | 本期没有自动恢复／回收入口，保留未知；[L1-04](L1-04.md)只提供已提交单资产记录的读回，不扫描认领残留。 |
| 文件已经可读但未登记、未验收或未发布 | 保留文件事实，不补造登记回执、模型版本或验收结果。 |

当前真实保护依赖受信服务独占管理根及源暂存区；进程中的属性核对不能证明同 UID 恶意进程不存在，0400 也不能阻止文件属主更改权限。后续不可信代码的输入投递及产物接收仍须满足 [L1-01 的联合放行门槛](L1-01.md#开放不可信执行的必需条件)。

## 7. 验收计划与执行记录

以下保留 2026-11-23 L1-02 的实施验证记录；后续真实目录消费及文件并发调整的实际验证由 [L1-04 第 7 节](L1-04.md#7-验收计划与执行记录)维护，不把当时的同根忙拒绝范围沿用为当前并发契约。

| 检查 | 必需覆盖 | 当前证据 |
| --- | --- | --- |
| 关联与作用域 | 固定工作区、引用／位置错产物、错误具体类型；派生位置不触发 I/O。 | 本轮通过，纯关联用例在 `test_file_storage_contract.py`，实际范围拒绝在适配器／宿主测试。 |
| 真实存储与原件 | 相同名称不同产物互不覆盖；源内容及游标不变；真实长度／摘要、空文件、显式限额和已有目标。 | 本轮真实文件测试通过，包括迟到目标／悬空链接的实际无覆盖提交及短写处理。 |
