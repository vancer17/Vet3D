## 3. 输入、输出与权威事实

### 唯一资源契约

| 对象 | 当前含义 |
| --- | --- |
| ResourceKey | 维护源中的规范小写 ASCII 逻辑名称；不是 UUID 产物或物理路径。 |
| ResourcePath | 包内规范相对 POSIX 路径；不接受绝对路径、URI、反斜杠、跳转段、空段和控制字符。 |
| ResourceFile | 文件路径与唯一 ContentFingerprint；每个路径在清单文件表中只出现一次。 |
| ResourceReference | 清单原始字节的 ContentFingerprint 加 ResourceKey，固定一个确切资源。 |
| ResourceMetadata | purpose、source、inputs、outputs、overwrite、failure、adoption、priority、evidence 九项明确文本说明；不作为运行时业务开关。 |
| DocumentResource／TemplateResource／ScriptResource | 各自冻结的具体声明；共同包含 key、entry、files、dependencies、metadata。脚本另含 InterpreterRequirement，文档／模板不携带可切换解释器字段。 |
| InterpreterRequirement | runtime、version、dependencies 的需求声明，不提供机器路径或当前环境满足证明。 |
| ResourceManifest | 唯一文件表和完整资源声明；不包含自身摘要、installed、ready 或业务验收字段。 |
| ResourceDescription | 确切 ResourceReference 与同键声明；不复制文件摘要或推断磁盘访问状态。 |

ResourceKey 的规范形式为小写字母起始、后续小写字母或数字，段之间允许单个点、短横线或下划线。不裁剪或转换大小写。ResourcePath 是资源域的位置，不复用带工作区语义的 WorkspaceFileLocation，也不产生兼容别名。

资源条目的 files 引用唯一文件表，entry 必须属于该资源直接文件集合；依赖仅引用同包 ResourceKey。拒绝重复键、重复路径、文件与目录前缀冲突、缺失入口、缺失依赖和环。全局文件表必须恰好等于各资源 files 的并集。多个资源可以显式共享同一个文件表项，不复制其权威摘要。

资源依赖只证明声明闭包完整，不证明 Python import、Blender 扩展或外部软件已经可用。文档里的普通引用不自动成为必执行依赖；解释器要求不会触发下载或宿主探测。

### 维护源与发布清单

维护源固定为 `resource-spec.json` 和 `payload/`。声明顶层只含 `schema_version: 1` 与 `resources`；不手写文件摘要或长度。构建器根据资源直接文件集合，从真实字节单向生成发布清单的 files 表。源码中的元数据是唯一维护源，安装副本不能回写源声明。

发布包固定为 `manifest.json` 和 `payload/`。清单顶层只含 `schema_version: 1`、`files`、`resources`。两种输入共用同一个资源条目解码器；kind 从具体资源类型单向生成，不另维护 Operations 枚举或状态投影。Schema 版本是输入协议，不是运行时架构开关。

解析拒绝 BOM、非 UTF-8、重复 JSON 键、未知或缺失字段、非规范值和不支持的 Schema。序列化以确定排序生成 UTF-8、无 BOM、LF。安装版本由收到的 **原始清单字节** 决定；不能先解析重编码再宣称仍是旧快照。上游版本保留在 source 说明中，不参与当前版本选择。

整个包是一个版本粒度。任何清单或文件变化都产生新快照，即使部分资源未变化；没有逐资源版本求解器或 latest 指针。

### 真实 I/O 与配置

ResourceLimits 是适配层唯一的部署预算对象：max_manifest_bytes、max_files、max_file_bytes、max_total_bytes，均为非布尔正整数。读取实际字节和扫描实际文件集合均受预算约束；目录允许集合从声明路径派生，不另加可漂移配置。max_readers 是 Bootstrap 的实际并行读取上限，不定义建模任务并发或业务能力。

构建源允许当前用户所有的普通 Git 权限：目录 0700／0755、文件 0400／0600／0644；不得含链接或组／其他用户可写对象。构建输出为私有目录和只读文件。安装来源必须是装配固定的私有根，其中资源包通过单段名称选择；请求不能给出任意路径、URL 或另一个来源根。

构建输出在操作期间由本次构建独占，消费方只能使用成功返回后的包。普通构建失败核对输出根仍为本次 inode 后清理整棵输出，不追踪每个子项的创建者；已有目标、根替换和强退残留不由下一次构建清理。安装暂存的清理另按本次逐对象身份核对，不能将两者描述为相同保证。

已发布快照中目录为 0500、文件为 0400；资源根、版本集合和技术暂存集合为 0700，固定安装锁为 0600。所有保护依赖可信服务管理和当前 UID；属主能够改权，因此这些权限与摘要核对不构成不可信代码执行沙箱。

## 4. IoC 与公开入口

| 公共入口 | 角色与结果 |
| --- | --- |
| resources.parse_resource_spec／parse_manifest／serialize_manifest | 唯一 Schema 解码、完整关联检查及确定性序列化；无磁盘或环境副作用。 |
| resources.fingerprint_bytes | 对实际 bytes 计算复用的 ContentFingerprint。 |
| resources.ResourceReader | 同步窄 Protocol：describe(key) 查询冻结声明，read_file(key, path) 返回该资源声明且实际匹配的字节。 |
| adapters.build_resource_bundle(source_root, output, *, limits) | 可信 Operations 的同步构建入口，输出必须不存在且与维护源不重叠；返回清单指纹，不是安装事实。 |
| adapters.LocalResourceStore.initialize／open(root, limits) | 显式初始化安全空根或核对既有完整布局；不建立数据库或安装资源。 |
| LocalResourceStore.install(source_root, bundle_name, expected) | 在实际操作期间取得同根安装锁，完整发布后返回原清单指纹；已有目标总拒绝覆盖。 |
| LocalResourceStore.pin(snapshot) | 完整核对原快照并交付 LocalResourceReader；读取实现显式继承 ResourceReader。 |
| bootstrap.initialize_resources／open_resources | 注入 root、source_root、limits、max_readers；返回 ResourceRuntime。 |
| await runtime.install(bundle_name, expected, *, timeout_seconds=5.0) | 可信部署入口；限额和来源根不在逐次命令重新定义。 |
| await runtime.pin(snapshot, *, timeout_seconds=5.0) | 返回 PinnedResources；不选择最新版本，不持久绑定会话。 |
| pinned.describe(key) | 同步查询冻结清单；即使返回描述，也不能证明当前文件仍可读。 |
| await pinned.read_file(key, path, *, timeout_seconds=5.0) | 在有界线程中读取实际字节，不把主机绝对路径交给业务。 |

resources 只依赖已有 ContentFingerprint 公共导出，不依赖工作区、数据库、Bootstrap 或执行器。具体文件实现留在 adapters，Bootstrap 显式装配；跨包仅通过 `__init__.py` 导出。安装器与 PinnedResources 是稳定具体类，不为其再建立同形包装。

安装使用单名额入口，读取使用独立的有限线程池；二者都没有内部等待队列。版本固定在读取实例，实际调用只传资源键和文件。一个安装者不会占住读取名额，也不会将所有建模任务串行化。线程与在途 Future 是运行资源事实，不映射到业务模式或资源清单状态。

日志初始化沿用 Bootstrap。记录安装／读取开始、实际完成、预期拒绝和异常边界，关联快照及资源键；等待取消后的晚期异常仍被观察一次。安装长任务进度限制频率，不转储资源内容或建立额外文件日志系统。

## 5. 正常流程与副作用

| 阶段 | 核对与副作用 |
| --- | --- |
| 构建 | 解析唯一维护源，核对精确 payload 树和预算，复制原件、计算实际指纹，最后写出 manifest；源字节与权限不修改，脚本不 import 或执行。 |
| 初始化／重开 | 根位置在装配时固定，拒绝路径跳转；初始化只接受安全空根，重开不补建缺失结构。 |
| 安装前检查 | 在原固定安装锁下打开私有来源包，核对预期清单原字节指纹、Schema、预算及精确文件集合。 |
| 暂存复制 | 在资源根 `.staging/` 独占建立技术目录，仅复制清单声明文件并逐项核对实际内容指纹，源句柄由实际操作持有。 |
| 完整发布 | 再核对暂存树，文件与内部目录先设为只读并同步，暂存根保留 0700 以允许跨父移动；用 Linux 无覆盖重命名提交到 `snapshots/<manifest-sha256>`，再将持有的最终根设为 0500 并同步，最后同步相关父目录。 |
| 固定读取 | 用原清单指纹打开快照并核对全部文件；后续 describe 只返回声明，read_file 重新验证该文件的实际内容和访问路径。 |

发布清单和 payload 同属一个完整目录，不分别对外更新；清单指纹不自引用。版本目录可见后，其他进程只能通过本项完整核对来取得读取实例。未知目录和旧临时文件不成为版本选择来源。

当前能力只返回有界 bytes，不把临时物化路径当作可永久使用的执行地址。未来 L2 需要按固定引用准备最小输入，并在执行交接时核对内容；不能把一次资源读取当作长期存在或可执行证明。

## 6. 失败、取消与恢复

| 情况 | 本期处理 |
| --- | --- |
| Schema、关联或路径无效 | 拒绝，不自动修剪、改写指纹、替换入口或跳过依赖。 |
| 构建源缺文件、额外文件或发生变化 | 构建失败，不返回可用资源包回执；普通失败在独占前提下核对输出根 inode 后清理本次输出，根被替换则保留。 |
| 安装已有最终目标 | 总是拒绝覆盖；另行 pin 原指纹核对当前完整字节，不以重复安装冒充原调用回执。 |
| 复制／校验失败或预算耗尽 | 不发布最终目录；仅清理本次可确认归属的暂存，清理失败附加诊断并保留现场。 |
| 目录重命名后、最终根收紧权限前退出 | 最终目录可能仍为 0700；pin 拒绝这个未完成目标，重复安装也拒绝覆盖。保留现场，不自动改权、修复或认领。 |
| 最终根收紧权限后同步或回包失败 | 可能已存在完整版本；保留目标并按原快照重查，不盲目删除、覆盖或自动重装。 |
| 等待取消／超时 | 只结束调用方等待；线程、源句柄及实际安装锁保留到操作终结，关闭排空真实任务。 |
| 进程退出／重启 | 重新注入部署配置，只能凭调用方保留的原清单指纹重新核对；不恢复丢失的会话 pin。 |
| 未知暂存、损坏快照或丢失原引用 | 不认领、修复、升级、降级或自动垃圾回收，不选择“最近”目录代替。 |
| 新版安装期间旧消费者读取 | 旧目录保持原样；旧固定引用不随新安装切换。 |
| 描述仍在而实际文件丢失／改变 | describe 仍是原声明；read_file 明确失败，不返回旧内容或改写声明。 |

资源包自身的完整目录发布是 L1-03 必需步骤，不等于提前实现 L1-04 的产物索引、报告、业务多文件事务或版本指针。目录重命名、普通进程退出测试和 fsync 不替代实际部署的断电恢复验证。
