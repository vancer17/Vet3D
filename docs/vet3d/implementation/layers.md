# 分层实施清单

本页展开[实施总纲](README.md)的 L0–L9 架构层级，为每层规定职责、开始依赖、稳定工作条目、对外契约与放行条件。编号表达默认开发顺序；源码依赖通过消费方或稳定内核拥有的接口反转，实际适配器由装配入口注入。接口归属不按供应商 SDK 的组织方式划分。

本清单是 **Vet3D 设计与待办基线**。当前 [L0-01](work-items/L0-01.md)、[L0-02](work-items/L0-02.md)、[L0-03](work-items/L0-03.md)、[L0-04](work-items/L0-04.md)、[L0-05](work-items/L0-05.md)、[L1-01](work-items/L1-01.md)及 [L1-02](work-items/L1-02.md)为 **已完成**（范围见各卡），其余条目为 **未实施**。已进入实施的接口和证据以对应实施卡为准。其他接口、状态与能力名称表达拟定语义，不宣告已有产品 API。仓库现有 Hi3D 库存、抽离、归档脚本及其测试不代表 Vet3D 工作区、Agent 或建模运行链路已实现。每次开工以[工作包模板](work-item-template.md)记录实际范围、实现、检查及剩余缺口。

每层先交付同一条最小链路所需的能力，再扩展覆盖。进入上层前验证所需下层条目，不要求整层所有能力全部完成。L4–L6 共享能力发现与上下文契约，可在最小契约确定后交叉实施；最小宿主与装配入口从 L0 开始，L9 完成产品化。

## L0 公共语义与接口契约层

**职责与边界。** 定义各层共同使用的身份、引用、状态和能力端口。先明确“需要提供什么”，再选择存储、解释器和模型适配器。公共内核只承载稳定语义；供应商参数、模型提示词、桌面组件及具体数据库类型由各自适配层维护。

**开始依赖。** 明确首条验证链的用户输入与交付目标；利用已有逆向材料列出需要借鉴的边界。LLM、生图、3D 模型及持久化产品仍可待选；首期宿主与包布局见 [ADR 0001](../adr/0001-service-host-and-composition.md)。

**完成与恢复。** 同一假任务经两种替身实现可得到等价业务结果，且消费方无需修改。失败、取消、未知结果有不同可观察状态。尚未选择供应商时，能力缺失应可明确表达；不能为了让替身成功而宣称真实图片、生成或恢复能力可用。

**参考与待定。** [Hi3D 实现交接](../../hi3d/README.md#vet3d-实现交接)用于提取文件身份与交接语义；[工具分类与注册](../../hi3d/tools/README.md)用于区分工具、动作、能力枚举与脚本。已接受的宿主决策及本项接口分别见 [ADR 0001](../adr/0001-service-host-and-composition.md)与 [L0-01](work-items/L0-01.md)，后续身份及领域接口按条目确定。

## L2 执行与外部适配层

**职责与边界。** 将抽象执行请求交给实际解释器、进程或外部服务，记录可关联的执行状态与输出。负责运行与恢复机制，不选择动物建模路线或代替内容验收。LLM 推理、本地图像处理、远端生图与 3D 生成可以有不同的专用请求契约。

**开始依赖。** L1-02 至 L1-05 提供实际文件、资源、持久记录和诊断；L0-05 提供本期重建消费边界，其他执行或模型端口随对应消费者补足。真实远端适配在供应商确定后接入。

## L3 通用能力服务层

**职责与边界。** 将底层存储与执行组合为可复用应用能力，供宿主、业务节点及 Tool 适配器调用。同一能力不因调用入口不同而绕过必要前提。服务表达明确操作及结果，不携带模型提示词或某个业务节点的专属调用顺序。

**开始依赖。** 所需 L1、L2 条目已经以实际实现或替身满足契约；普通查询和登记能力可以先于全部外部适配完成。

## L4 Tool 契约与能力暴露层

**职责与边界。** 将选定服务暴露为当前调用方可用的工具，维护名称、模型描述、参数与结果、作用域及可用目录。Tool 负责调用适配与治理；底层脚本、Skill 和内部宿主接口保留各自身份。工具页保持独立，业务专属调用时机由节点文档维护。

环境或资源可用性可以限制本轮暴露范围并说明缺口，不改变既有业务动作、参数和结果语义；环境事实由宿主与运维边界管理。产品调用边界见[总纲](README.md#产品调用边界)。

**开始依赖。** L0-05 的端口和结果语义稳定；至少一组 L3 服务可由最小宿主调用。与 L5、L6 共同确定工具与 Skill 目录契约后可并行推进。

| 条目 | 实施与交付 | 前置 |
| --- | --- | --- |
| L4-01 | 定义 Tool 声明、名称与版本、description、参数／结果契约及单一维护来源；记录注册、当前可见和实际调用三个层次。 | L0-05、L3-01 |
| L4-02 | 实现参数结构、线程／轮次／工作区作用域和调用有效性检查，路由至服务并规范化错误；业务必要门槛仍由服务或节点执行。 | L4-01、L3-02 |
| L4-03 | 按环境、有效资源、供应商能力及任务范围生成当前目录，工具不可用时提供明确缺口，支持目录版本与失效处理。 | L2-01、L2-04、L4-01 |

| L4-05 | 实现可续接执行结果和文件／图像交付的模型侧适配，保留原执行关联；区分 Tool 回包、进程状态和业务质量结论。 | L2-03、L3-03、L4-02 |

**向上接口与注入。** 工具注册表依赖通用能力接口，不拥有具体存储或 SDK。不同 Agent Runtime 可通过适配器消费同一工具契约。动态暴露只改变本轮可调用范围，不改变服务的持久身份与前提。

**完成与恢复。** 替身模型或工具协议夹具能验证声明、实际路由与回包一致；非法参数、过期调用、跨工作区参数、工具下线和长执行续查有可观察结果。工具结果丢失时按执行记录对账，不能以重新发起新调用冒充原任务续查。

**参考与待定。** [LLM Tool 索引](../../hi3d/tools/README.md)、[本地命令](../../hi3d/tools/exec-command.md)、[模型登记 Tool](../../hi3d/tools/workspace-commit-model.md)、[Studio 状态](../../hi3d/tools/studio-get-state.md)。Vet3D Tool 名称、描述、schema 和 Runtime 路由待确定；不把 Hi3D 动态工具目录当作 Vet3D 必须全部开放的集合。

## L5 LLM 上下文与状态感知层

**职责与边界。** 为当前任务和轮次组装可追溯、受能力约束的输入，使模型获得所需事实、图片及工具。上下文是工作区与运行状态的投影视图，不成为另一份可以独立漂移的权威资产库。

**开始依赖。** L3-02 查询服务、L4-01 至 L4-04 目录契约可用；会话与轮次归属由 L3-01 确认。最小查询和上下文探针随下层能力同步接通，不等本层全部完成。

**开始依赖。** L4-04 提供资源与 Skill 发现契约，L5 能投递所选资料及必要素材，L0-03 提供方向和文件语义。领域内容可与 L4、L5 的最小实现并行。

**开始依赖。** 该节点所需的 L3 服务、L4 调用契约、L5 上下文和 L6 策略已经可用。可从一个最小节点接通，无需等待全部建模与后处理能力齐备。

## L8 Agent 决策与流程编排层

**开始依赖。** 至少一组 L7 节点可通过替身输入输出运行；L4 工具、L5 上下文、L6 选用规则及 L2 模型端口具备最小闭环。编排与节点骨架早期即可用于集成探针。

## L9 产品宿主与整体交付层

**职责与边界。** 完成可使用产品的宿主界面、真实适配器装配、安装升级、诊断和交付。宿主通过服务与编排接口启动任务和呈现事实；生产装配集中提供具体实现。它沿用 L0 的最小宿主骨架，不反过来成为下层接口定义的前置条件。

首期目标为[供 BFF 调用的后端服务](README.md#产品调用边界)；桌面窗口、编辑器及其安装体验按实际产品范围扩展。下列界面条目不构成 L0-01 装配验收或正常自主业务链的前置。

**开始依赖。** M1 所需底层能力先在最小宿主验收，产品界面可并行开发；完整产品放行依赖选定的 L8 业务链及真实环境验证。

## 条目开工与放行

实施时为选定条目建立工作包，引用本页 ID、实际前置条目及[总纲](README.md)中的阶段目标。先确定首条闭环需要的子集，未进入当期的条目继续保持未实施；同层未完成的可选扩展不会阻断已满足契约的上层集成。

一个条目可放行的依据是：接口及依赖归属明确、实际实现已接入装配、正常与必要失败路径已验证、产物和恢复结果可核对、剩余缺口已记录。文档完成、替身完成、真实集成及目标动物验收是不同证据状态，不能互相替代。
