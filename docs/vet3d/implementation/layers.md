# 分层实施清单

本页展开[实施总纲](README.md)的 L0–L9 架构层级，为每层规定职责、开始依赖、稳定工作条目、对外契约与放行条件。编号表达默认开发顺序；源码依赖通过消费方或稳定内核拥有的接口反转，实际适配器由装配入口注入。接口归属不按供应商 SDK 的组织方式划分。

本清单是 **Vet3D 设计与待办基线**。当前 [L0-01](work-items/L0-01.md)、[L0-02](work-items/L0-02.md)、[L0-03](work-items/L0-03.md)、[L0-04](work-items/L0-04.md)、[L0-05](work-items/L0-05.md)、[L1-01](work-items/L1-01.md)、[L1-02](work-items/L1-02.md)、[L1-03](work-items/L1-03.md)、[L1-04](work-items/L1-04.md)及 [L1-05](work-items/L1-05.md)为 **已完成本期范围**（范围见各卡）；[L2-01](work-items/L2-01.md)也已完成本期范围；[L2-02](work-items/L2-02.md)为 **阶段 A 已开展，产品接入未完成**，具体证据与限制见该卡；其余条目为 **未实施**。已进入实施的接口和证据以对应实施卡为准。其他接口、状态与能力名称表达拟定语义，不宣告已有产品 API。仓库现有 Hi3D 库存、抽离、归档脚本及其测试不代表 Vet3D 工作区、Agent 或建模运行链路已实现。每次开工以[工作包模板](work-item-template.md)记录实际范围、实现、检查及剩余缺口。

每层先交付同一条最小链路所需的能力，再扩展覆盖。进入上层前验证所需下层条目，不要求整层所有能力全部完成。L4–L6 共享能力发现与上下文契约，可在最小契约确定后交叉实施；最小宿主与装配入口从 L0 开始，L9 完成产品化。

Agent 接入方向按 [ADR 0012](../adr/0012-native-agent-runtime-integration.md)收敛：Vet3D Agent 由成熟运行时直接承载，原生 Agent 拥有唯一的建模规划、工具选择、错误理解、视觉修订及会话上下文管理，Vet3D 接入层保留业务接入和协议连接。[L2-02](work-items/L2-02.md)当前仅实施阶段 A，核查小型自主任务及接入证据；产品接入另行规划，领域质量与业务流程仍归其所属条目，不成为阶段 A 的实施前置。

## L0 公共语义与接口契约层

**职责与边界。** 定义各层共同使用的身份、引用、状态和能力端口。先明确“需要提供什么”，再选择存储、解释器和模型适配器。公共内核只承载稳定语义；供应商参数、模型提示词、桌面组件及具体数据库类型由各自适配层维护。

**开始依赖。** 明确首条验证链的用户输入与交付目标；利用已有逆向材料列出需要借鉴的边界。LLM 具体型号与连接、生图、3D 模型及持久化产品随对应消费者确定；首期宿主与包布局见 [ADR 0001](../adr/0001-service-host-and-composition.md)。

**向上接口与注入。** 消费方只接收稳定引用和端口，不持有具体 SDK 客户端、数据库连接或 Blender 安装路径。端口可分域声明，不要求建立包含全部功能的全局接口。装配骨架先注入替身，后续逐个替换为真实实现。

**后续端口。** 资源读取端口已在 [L1-03](work-items/L1-03.md)接通，当前契约及验证记录由该卡维护。Agent 运行时接入、独立模型能力和视觉状态边界仍随 L2-02、L2-04、L3-05 的真实消费者确定；这些接口不属于 L0-05 当前完成范围。没有独立消费者的通用执行端口不作为 Agent 主入口，也不提前建立万能端口。

**完成与恢复。** 同一假任务经两种替身实现可得到等价业务结果，且消费方无需修改。失败、取消、未知结果有不同可观察状态。尚未选择供应商时，能力缺失应可明确表达；不能为了让替身成功而宣称真实图片、生成或恢复能力可用。

**参考与待定。** [Hi3D 实现交接](../../hi3d/README.md#vet3d-实现交接)用于提取文件身份与交接语义；[工具分类与注册](../../hi3d/tools/README.md)用于区分工具、动作、能力枚举与脚本。已接受的宿主决策及本项接口分别见 [ADR 0001](../adr/0001-service-host-and-composition.md)与 [L0-01](work-items/L0-01.md)，后续身份及领域接口按条目确定。

## L2 执行与外部适配层

**职责与边界。** 接入直接承载 Vet3D Agent 的成熟运行时及独立外部能力。原生 Agent 根据目标和反馈自主规划建模、选择工具、理解错误、观察图片并修订；接入层负责协议连接、授权配置、任务关联、进度消费与正式产物交接，不据原生反馈另行编排细分修复指令。独立生图／3D 生成等业务能力保留专用契约，不将所有原生工具操作转换成业务执行请求或另一套状态机。

**开始依赖。** L1-02 至 L1-05 提供实际文件、资源、持久记录和诊断；L0-05 提供本期重建消费边界，其他执行或模型端口随对应消费者补足。真实远端适配在供应商确定后接入。

## L3 通用能力服务层

**职责与边界。** 将底层存储与执行组合为可复用应用能力，供宿主、业务节点及 Tool 适配器调用。同一能力不因调用入口不同而绕过必要前提。服务表达明确操作及结果，不携带模型提示词或某个业务节点的专属调用顺序。

**开始依赖。** 所需 L1、L2 条目已经以实际实现或替身满足契约；普通查询和登记能力可以先于全部外部适配完成。

| 条目 | 实施与交付 | 前置 |
| --- | --- | --- |
| L3-01 | 组合工作区创建、打开和切换，按需要关联运行时原生会话并消费其恢复结果；活动选择、持久归属与异步响应代次分别管理，不复制会话历史或进程生命周期。 | L1-01、L1-04、L0-04；原生会话关联另接 L2-02 |
| L3-02 | 提供素材导入、文件目录、模型版本和资源能力查询，按确切身份返回当前可用项及缺失原因。 | L1-02、L1-03、L3-01 |
| L3-03 | 沉淀可复用的重开、尺寸检查、显式对象导出和固定方向预览模块及必要报告适配；Agent 可通过原生工具动态调用和组合，不要求每个库函数包装为 Tool。独立业务消费者才建立服务入口与关联记录；保留每个资源的实际检查范围，执行边界见[交接要求](work-items/L1-01.md#开放不可信执行的必需条件)。 | L2-02、L3-02；需要持久业务执行关联的消费者另接 L2-03 |

**向上接口与注入。** 服务依赖其实际需要的文件、资源、运行时接入、视窗及通知等端口，具体实现由装配入口提供。宿主与业务 Tool 接收同样的服务接口。独立业务 API 回包按契约适配；原生工具的 stdout、错误和图像继续由运行时反馈给模型，不经业务摘要替换。

**完成与恢复。** 不经过 LLM 即能调用服务完成导入、查询、执行及登记。覆盖文件已写但登记失败、返回复用版本与候选字节不同、报告缺失／覆盖、加载请求过期、保存取消及部分目标等情形。服务成功不自动更新业务节点为验收通过；文件、版本与证据的实际身份可核对。

**参考与待定。** [版本目录查询](../../hi3d/infrastructure/workspace/query-assets-and-model-versions.md)、[普通文件登记](../../hi3d/infrastructure/workspace/register-file-artifact.md)、[模型版本登记](../../hi3d/infrastructure/workspace/import-or-register-model-version.md)、[视觉证据](../../hi3d/infrastructure/workspace/acquire-model-visual-evidence.md)、[预览与交付](../../hi3d/infrastructure/workspace/preview-and-deliver-files.md)。具体服务签名和视窗后端待选；通用服务不要求照搬 Hi3D RPC 名称。

## L4 Tool 契约与能力暴露层

**职责与边界。** 将确有业务消费者的 Vet3D 服务接入所选运行时的扩展工具机制，并验证原生工具的授权和可用范围。Vet3D 维护自有领域工具的说明、参数、结果和业务门槛；原生工具的定义、分派、执行反馈和调用记录由运行时负责，不复制通用工具注册表或路由。底层库、动态脚本、Skill 和宿主接口保留各自身份。

环境或资源可用性可以限制本轮暴露范围并说明缺口，不改变既有业务动作、参数和结果语义；环境事实由宿主与运维边界管理。产品调用边界见[总纲](README.md#产品调用边界)。

**开始依赖。** L2-02 已验证所选运行时的原生工具与反馈链；L0-05 的业务端口和结果语义稳定，至少一组 L3 服务有实际工具消费者。与 L5、L6 共同接通所需领域工具和 Skill，不把本层完成作为 L2-02 最小原生闭环的前置。

| 条目 | 实施与交付 | 前置 |
| --- | --- | --- |
| L4-01 | 为确需暴露的领域服务定义 Tool 名称、description、参数／结果及单一维护来源，接入运行时已有扩展机制；原生工具不重复声明。 | L2-02、L0-05、对应 L3 服务 |
| L4-02 | 在领域工具进入业务服务的边界校验参数与任务授权，返回明确业务结果；原生工具的路由和机械协议由运行时处理，不增设全工具转发层。 | L4-01、L3-02 |

**向上接口与注入。** 领域工具适配器依赖业务能力接口，由装配入口绑定到选定运行时；具体 SDK 类型止于适配边界，不为假设的多运行时兼容增设通用工具平台。动态暴露只改变授权内的可调用范围，不改变业务服务的身份与前提。

**完成与恢复。** 协议夹具验证领域工具参数与交接，真实模型验证新增领域结果的理解和使用；原生反馈闭环证据始于 L2-02，不能以本层替身代替。非法参数、跨工作区调用和失效权限有明确结果。恢复消费运行时原记录与业务权威事实，不能以重新发起调用冒充原任务续查。

**参考与待定。** [LLM Tool 索引](../../hi3d/tools/README.md)、[本地命令](../../hi3d/tools/exec-command.md)、[模型登记 Tool](../../hi3d/tools/workspace-commit-model.md)、[Studio 状态](../../hi3d/tools/studio-get-state.md)。Vet3D 领域 Tool 名称、描述和 schema 按真实消费者确定；不把 Hi3D 动态工具目录当作必须全部开放的集合，也不把桌面专属工具误认为原生运行时能力。

## L5 LLM 上下文与状态感知层

**职责与边界。** 向原生 Agent 提供当前业务目标、约束、素材角色及权威业务事实，验证其与原生会话和模型输入正确关联。会话上下文、消息历史、工具反馈及压缩由成熟运行时管理；业务输入接入不分析原生反馈并重组为下一步建模指令。业务上下文是工作区与业务状态的投影视图，不成为另一份权威资产库，也不是执行输入快照。

**开始依赖。** L3-02 查询服务、L4-01 至 L4-04 目录契约可用；会话与轮次归属由 L3-01 确认。最小查询和上下文探针随下层能力同步接通，不等本层全部完成。

| 条目 | 实施与交付 | 前置 |
| --- | --- | --- |
| L5-01 | 按消费者需要提供当前业务事实投影，关联工作区、原生会话／轮次、实际产物／版本及缺失或陈旧信息；不复制原生会话状态或逐工具执行状态。 | L3-01、L3-02、L4-03 |
| L5-02 | 通过运行时原生输入机制提交用户指令、附件和图片，区分原件、预览、主图与补充参考，并核对实际图片投递；外部素材保持数据身份。原生工具产生的图像反馈继续沿运行时内部通路，不转成业务摘要再投递。 | L0-03、L3-02、L2-02；新增领域 Tool 文件／图像结果按需接 L4-05 |
| L5-03 | 明确文件目录、选中版本、实际加载身份与视觉证据的读模型，按确切文件及加载代次关联截图和机位。 | L3-05、L5-01 |
| L5-04 | 在首轮、业务事实变化、任务环境切换和恢复时刷新预算内的必要业务输入；会话继续、历史压缩与工具反馈沿用运行时机制，不通过筛选错误、图片或逐步补救提示替原生 Agent 规划修订。 | L5-01、L5-02、L4-04 |
| L5-05 | 验证业务素材角色、权威状态和原生上下文正确关联；夹具覆盖机械交接，真实 LLM 验证新增领域信息的理解和使用。L2-02 的最小真实图像与连续会话验证不延后到本项。 | L5-01 至 L5-04 |

**向上接口与注入。** 业务输入消费者通过查询接口取得任务事实，由运行时接入适配器映射到其实际输入机制；只有真实业务语义需要独立表示，不重建通用消息或多模态框架。图片角色和视角不绑定为供应商字段。可访问文件不等于图片已进入模型输入，读过目录也不等于完成视觉判断。

**完成与恢复。** 同名文件在两工作区不会混入同轮；旧加载回调、过期业务投影和恢复前状态不能冒充当前事实。验证实际图片投递与业务关联，原生历史压缩和恢复后仍能接续当前任务；不要求逐次执行内容精确复现。静态夹具只证明机械交接，真实模型的主体识别及使用能力须另验。

**参考与待定。** [本轮上下文](../../hi3d/infrastructure/workspace/llm-context.md)、[会话绑定与恢复](../../hi3d/infrastructure/workspace/bind-and-restore-workspace-session.md)、[实际 Studio 状态](../../hi3d/infrastructure/workspace/read-studio-state.md)、[版本加载](../../hi3d/infrastructure/workspace/load-studio-revision.md)。上下文窗口、图像限制、预算策略和恢复协议依实际 LLM／Runtime 验证。

**开始依赖。** L4-04 提供资源与 Skill 发现契约，L5 能投递所选资料及必要素材，L0-03 提供方向和文件语义。领域内容可与 L4、L5 的最小实现并行。

## L7 原子业务节点层

**职责与边界。** 实现具有独立输入、输出、完成条件和恢复出口的业务单元。节点声明业务目标、能力和验收依据，领域服务按固定职责提供评估结果与证据；原生 Agent 决定如何检查、编程、调用工具和修订。业务交接采用确切版本与验收记录，不把节点拆成由宿主逐步指挥的建模动作；节点不自行构造供应商客户端或读写底层注册表。

**开始依赖。** 该节点所需的 L3 服务、L4 调用契约、L5 上下文和 L6 策略已经可用。可从一个最小节点接通，无需等待全部建模与后处理能力齐备。

## L8 Agent 决策与流程编排层

**职责与边界。** 管理业务节点、质量要求、验收、返工准入、任务预算、停止条件、发布规则、交接与按需用户交互。领域服务提供职责明确的质量评估与证据；L8 据此决定业务是否放行、是否允许继续返工，不决定具体建模修复步骤。Vet3D Agent 由 L2-02 接入的成熟运行时直接承载，建模规划、工具选择、错误理解、视觉观察和修订归原生 Agent。边界以实际决策权判断，不仅检查外层是否调用模型；固定职责的评估即使使用模型，也不自动成为父 Agent，预算与自动业务反馈同样可以保留。此处约束 Vet3D 另建控制循环，不限制成熟运行时自身已有能力，详见 [ADR 0012](../adr/0012-native-agent-runtime-integration.md)。LLM 文本不替代执行事实、正式产物或验收记录。

**开始依赖。** 至少一组 L7 节点可通过替身输入输出运行；L4 领域工具、L5 业务上下文、L6 选用规则及 L2-02 原生运行时接入具备所需能力。早期最小原生 Agent 验证在 L2-02 完成，本层接入完整业务流程。

| --- | --- | --- |
| L8-01 | 定义流程状态、节点依赖和交接守卫，明确流程进度、执行作业、验收记录及实际文件各自的权威来源。 | L7-01、L0-04 |
| L8-02 | 向原生 Agent 传递业务目标、约束及领域评估结果／证据，消费业务结果并执行验收与交接守卫；不得把原生错误或图片分析成修复计划，再反复发送细分建模指令。继续输入遵循 L2-02 的边界。 | L2-02、L4-05、L5-05、L8-01 |
| L8-03 | 按显式交互场景扩展用户澄清、参数选择、确认、取消和继续，记录等待意图与实际答复；明确拒绝、取消和超时各自出口。正常自主链路不以持续人工审查为前置，见[产品调用边界](README.md#产品调用边界)。 | L8-01、L0-04、L5-04 |

| L8-05 | 集成首条真实业务链，关联业务任务、原生会话、正式产物和验收，独立业务作业按需关联原 Job／Attempt；普通原生工具操作不逐项业务化。按场景扩展修订与后处理分支。 | L8-02、L8-04、按需 L8-03，以及 L7-02 至 L7-05 中本期所需部分 |

**向上接口与注入。** 业务编排接收运行时任务接入、业务事实查询、节点、持久业务状态及交互等必要接口。启动进程或调用继续接口不自动形成父子 Agent；若编排据原生反馈持续制定建模步骤，即使不调用模型，也越过本层边界。运行时、数据存储及按需视窗组件由宿主装配；运行时或模型连接变更后需重验受影响的原生反馈和恢复边界。

**完成与恢复。** 使用替身验证正常、取消、受理不明、部分产物、验收失败和重启路径；随后用真实模型与目标样本验证效果。流程完成、图节点完成、作业成功和内容验收分别取证。存在待核对提交时不得静默新建作业，用户待答状态不得因时间流逝自动当作同意。

**参考与待定。** [工作流状态](../../hi3d/infrastructure/workspace/workflow-graph-state.md)、[工作流 Tool](../../hi3d/tools/workflow-report.md)、[宿主交互](../../hi3d/tools/user-interaction.md)、[原作业定位与恢复](../../hi3d/atomic-nodes/locate-job-and-qualify-resume.md)。业务流程表示和具体交互按需要确定，Agent 运行时接入与验证沿 L2-02；不另行选择并嵌套第二个 Agent 引擎，也不要求复制 Hi3D 的图数据或内存行为。

## L9 产品宿主与整体交付层

**职责与边界。** 完成可使用产品的宿主界面、真实适配器装配、安装升级、诊断和交付。宿主通过服务与编排接口启动任务和呈现事实；生产装配集中提供具体实现。它沿用 L0 的最小宿主骨架，不反过来成为下层接口定义的前置条件。

首期目标为[供 BFF 调用的后端服务](README.md#产品调用边界)；桌面窗口、编辑器及其安装体验按实际产品范围扩展。下列界面条目不构成 L0-01 装配验收或正常自主业务链的前置。

**开始依赖。** M1 所需底层能力先在最小宿主验收，产品界面可并行开发；完整产品放行依赖选定的 L8 业务链及真实环境验证。

| 条目 | 实施与交付 | 前置 |
| --- | --- | --- |
| L9-01 | 完成生产装配、配置与启动检查，明确真实／替身适配器、资源版本和可用能力；诊断缺失依赖且不虚报就绪。 | L0-01、L1-05、L2-01、L4-03 |
| L9-02 | 完成工作区、会话、任务与产物界面，展示实际版本、进度、失败和恢复入口；避免界面选择替代底层事实。 | L3-01、L3-04、L5-01、L8-01 |
| L9-03 | 完成真实视窗、截图与文件交付集成，核对快速切换、加载代次、实际输出及取消／部分保存等终态。基础视窗和普通文件交付可先行，具体业务交付再接对应节点。 | L3-05、L5-03；涉及绑定／动作交付时另接 L7-05 |
| L9-04 | 完成安装、受管资源更新、数据迁移、会话归档和清理规则；任务所用受管资源版本按既有资源契约管理，更新失败可识别并恢复，不延伸为动态代码或执行输入冻结。 | L1-03、L1-04、L2-03、L3-05 |
| L9-05 | 执行产品验收矩阵，分别记录基础设施可靠性、真实模型效果、四足质量、目标加载器及交付结果，形成已支持范围。 | L8-05、L9-01 至 L9-04 |

**向上接口与注入。** 产品入口是具体实现的装配位置；业务节点、Skill 和上下文服务不导入宿主组件。桌面、命令行或其他宿主可以采用不同装配，是否提供这些产品形态另作决策。

**完成与恢复。** 安装后从真实素材到所需交付范围可完成一条链，依赖缺失和中断有可用入口。升级、模型替换、视窗切换和用户保存都可按确切版本与回执核对。归档、注销、目录清理和外部文件保存具有独立完成条件，失败保留足够诊断。

**参考与待定。** [工作区打开](../../hi3d/infrastructure/workspace/open-workspace.md)、[会话恢复与归档](../../hi3d/infrastructure/workspace/bind-and-restore-workspace-session.md)、[工作区移除](../../hi3d/infrastructure/workspace/remove-workspace.md)、[视窗加载 Tool](../../hi3d/tools/studio-load-revision.md)、[导出回读与交付](../../hi3d/atomic-nodes/export-readback-and-deliver.md)。产品形态、界面技术、打包升级和目标引擎待选；既有静态 GLB 与留存会话只作参考样本。

## 条目开工与放行

实施时为选定条目建立工作包，引用本页 ID、实际前置条目及[总纲](README.md)中的阶段目标。先确定首条闭环需要的子集，未进入当期的条目继续保持未实施；同层未完成的可选扩展不会阻断已满足契约的上层集成。

一个条目可放行的依据是：接口及依赖归属明确、实际实现已接入装配、正常与必要失败路径已验证、产物和恢复结果可核对、剩余缺口已记录。文档完成、替身完成、真实集成及目标动物验收是不同证据状态，不能互相替代。
