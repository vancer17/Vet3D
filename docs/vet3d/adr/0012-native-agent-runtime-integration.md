## 背景与问题

Vet3D 面向 BFF，正常建模链需要 Agent 自主编程、观察与预算内修订，不能依靠持续人工审查。已完成的 L0／L1 及 L2-01 提供业务契约、存储、资源、配置和有限环境探测，没有实现模型与工具循环，也没有接入不可信代码执行环境。

此前 L2-02 讨论主要按“执行请求 → 隔离后端 → 结果”组织；分层清单还要求 L2-03 保存输入／参数／脚本指纹，并在 L4、L5、L8 规划通用工具暴露、反馈与模型循环。任务关联、隔离与正式产物交接本有实际用途，但若由此推导每次工具操作的冻结、执行账本和统一转发，就会增加尚无消费者的协议与状态，并可能重新建设运行时已有的文件、图像、会话和进程机制。

Hi3D 的参考说明显示：原生命令、续读、图片工具与模型反馈循环来自运行内核，Skill、共享模块和会话生成脚本可以并存。仅复用底层命令执行不能证明这些能力仍可被 Agent 使用；将错误、输出和图片压缩成业务回执也不能保留建模反馈。该判断不表示 Hi3D 机制存在缺陷，更不表示未经实测的候选已失败。

用户在本轮进一步明确：当前 Agent 工程不要求固定代码和输入，也不要求字节追溯。因此此次撤销是需求调整，不以延后实现或改名替代。

2026-11-24 补充本决定的职责边界，保留初次收敛的方向和历史理由：随着业务增加，“继续”“质量判断”和“返工”可能推动接入层承担任务拆解、原生结果解释、修复策略、上下文重组和逐步行动控制，使运行时退化为下级执行者。这是需要防止的设计风险；该次核对时源码尚未接入真实建模 Agent，不能写成已经发生的越界实现。后端服务的自动化、并发和验收要求本身不足以推出需要父 Agent。

判断是否重复控制应看建模决策权与反馈循环归属，不能只看组件名称或外层是否调用模型，也不能仅因存在适配器、运行时进程或继续接口就认定父子 Agent。必要的宿主协议接入、固定职责的领域评估、预算控制和自动业务反馈有独立用途，应与重复建模规划分别判断。

## 决定与范围

1. **由成熟运行时直接承载 Vet3D Agent。** 运行时中的原生 Agent 负责建模规划、原生工具选择、代码与文件操作、错误理解、视觉观察与修订，运行时管理其模型工具循环及会话上下文。Vet3D 不在外部另建建模控制循环；这约束 Vet3D 重复建设运行内核，不禁止成熟运行时自身已有的能力。优先验证完整 Codex app-server 线程／轮次接入；其与 Hi3D 原生能力的来源接近，是优先验证的依据，不是生产选型或验收结论。OpenAI Agents SDK 若进入比较，应比较其完整 Agent／Runner 与沙箱能力，而非仅比较 `session.exec`。
2. **Vet3D 接入层负责输入与协议连接。** 阶段 A 的具体消费者提交实验目标、配置授权、关联任务与原生会话、传递继续／取消请求、消费事件并保存实验输出；不解释建模错误或图像以逐步指挥修复，也不重组完整工具历史。继续可以传递来源明确的新要求或事实，无需把所有继续限制为人工触发；固定职责的业务评估与预算规则不自动构成父 Agent。产品业务分工见[分层清单](../implementation/layers.md)，其质量返工和正式交接不成为阶段 A 建设任务。不默认创建通用 `ExecutionRequest → ExecutionBackend` 主入口。
3. **动态建模是正常运行方式。** Agent 可阅读 Skill／共享模块、检查模型、写改脚本、执行、读日志、看图及继续修订。动态脚本无需预发布、登记为固定工具或修改装配；稳定库可由脚本直接调用。原生反馈保留在模型循环内，BFF 摘要仅用于业务呈现。
4. **撤销 Agent 执行内容冻结与字节追溯。** 不要求代码冻结、输入快照、参数／脚本指纹或逐次精确内容复现，不转移至 L2-03 或后续待办。普通读取、编辑、预览和诊断沿用原生记录，不逐项建立业务 Job／Attempt。已有特定业务消费者的身份、幂等和恢复语义不推广为原生工具协议。
5. **保留独立用途的约束。** 阶段 A 核对实际开放的原生文件、命令、Blender 及子进程的授权、资源、取消、回收与实验输出保存边界，未测能力不承诺支持。受管资源版本、安装摘要与正式资产完整性仍按已有消费者的契约生效；正式资产接收和生产隔离另行实施，不作为阶段 A 新增建设任务。执行终态、实验产物核查、业务验收与发布分别判断，不反向要求所有工具操作冻结。
6. **阶段 A 提供接入决策依据。** 验证“选定模型＋成熟 Agent 运行时＋实际任务环境”在预先明确的目标、权限和预算内，能否由原生 Agent 自主完成小型建模任务，并取得代码—日志—图片反馈、连续性与运行边界证据。小任务结果依据最终产物，失败也作为接入判断的证据，不通过增加质量机制制造成功。产品接入方式和公开接口根据这些结果另行规划；完整领域质量和生产规模不在本阶段验收。

## 考虑过的方案与取舍

| 方向 | 收益与成本 | 本次选择 |
| --- | --- | --- |
| 完整成熟运行时直接承载 Agent | 可复用建模决策与反馈循环、文件、执行、图片与会话；受其模型适配、协议版本、权限和部署方式约束，仍需验证完整环境。 | 优先方向；先验证完整 app-server 路线，允许据具体缺口调整候选。 |
| 外层解释反馈并逐步指挥运行时 | 即使外层没有模型调用，也可能通过错误分类、修复分支和补救提示接管建模决策，使原生 Agent 退化为下级执行者。 | 不采用；业务评估和准入规则可以自动反馈事实与约束，但不规划工具序列或修复步骤。 |
| 另加监督 Agent、通用调度或重复状态系统来约束接入层 | 增加新的控制者、同步关系和维护成本，没有补足当前已确认的业务缺口。 | 不采用；通过清晰职责和现有阶段 A 闭环核对边界，不再建设一套监督循环。 |
| 仅复用 `command/exec` 或沙箱执行接口 | 可减少部分进程管理，但不包含完整模型工具循环、文件图片反馈及会话接续；作为主入口会留下大量接入工作。 | 不作为当前 Agent 主方案；只有独立确定性消费者确有需要时，才讨论对应局部接口。 |
| 自建执行管理、工具路由与反馈适配 | 可以完全控制协议，但须承担进程、输出、取消、恢复及模型反馈等长期成本，容易与既有运行时重复。 | 当前没有证据证明需要整体自建；只补验证后明确且必要的业务缺口。 |
| 固定脚本清单或每次脚本预登记 | 便于枚举入口，却限制动态组合，还引入发布与装配步骤。 | 不满足当前 Agent 动态编程需求；受管共享模块与临时脚本并存。 |

以上为职责和接入成本判断，不是候选性能、安全性或真实任务的实测排名。Codex app-server 的独立命令接口与完整线程工具执行也不能互相代替恢复证据。

## 接受的代价与后果

- 完整复用减少自研通用机制，但需要接受并验证运行时支持的模型协议、多模态输入、原生工具语义、版本变化、权限与部署限制；不承诺任意兼容网关均可直接使用。
- 保留必要的宿主接入代码和有独立消费者的业务状态。业务扩展优先使用运行时支持的配置、Skill、共享模块和领域能力接入方式，接受这些扩展点的实际限制；不为扩展方便转由宿主规划建模动作或复制原生历史、工具状态和进程控制。
- 取消执行内容冻结后，原生记录可能只保留命令、路径和输出，工作文件也会变化。当前能力不承诺逐次执行的精确内容复现，不以新增指纹或快照弥补这一已接受的范围选择。
- 会话历史可恢复不代表原进程可续接；轮次结束也不自动证明后台进程已经停止。真实恢复与生命周期由原生机制及隔离设施的实际能力决定，Vet3D 只保存必要业务关联，不镜像原生状态机。
- 不能只因工具是原生的就放开宿主权限，也不能只因服务端部署就默认替换原生工具。若无法满足授权、资源或反馈要求，须明确具体缺口及最小调整，不持续扩大适配层来维持某个候选。
- 最小真实 Agent 验证被提前，会更早需要明确实验模型连接、凭证来源与有限预算；这不是提前绑定生产模型，也不是提前完成整个 Agent 产品。
- 宿主不通过逐步补救提示弥补原生 Agent 的建模能力不足。小型自主任务无法完成时如实记录缺口；不能把宿主编排完成的结果计为原生闭环通过。已有业务契约继续按其消费者生效，不扩展为阶段 A 的产品建设义务。

## 旧决定的局部修订

- [ADR 0006](0006-workspace-storage-and-execution-boundaries.md)：保留持久工作区、隔离环境、产物接收、并行与业务验收的分离。后续执行交接改为授权任务环境与原生工具，不解释为逐调用固定输入；原隔离候选比较保留为历史判断，当前先验证完整运行时接入。
- [ADR 0007](0007-managed-file-storage-boundaries.md)：保留固定授权根、无覆盖文件保存与正式文件完整性。其未来执行器的“固定输入”不再作为 Agent 内容冻结要求，后续按授权范围交接可变工作文件。
- [ADR 0011](0011-bounded-environment-probes.md)：已完成的受信探针和历史验证不变；后续实际环境复用已有检查定义，不按此探针实现推导自建通用执行器、第二套探测规则或持久进程管理。

## 2026-11-25 阶段 A 实验与决定补充

本日先后开展既有登录模型、Qwen 直连、明示条件后的自主任务及原始 Hi3D 对照。`experiments` 中的具体协议消费者、共享资源夹具和任务环境装配已用于有限实验，未形成产品 Agent 端口；当前源码未见第二套自主建模或工具分派循环。各次条件、结果、原始记录位置和恢复限制只维护在 [L2-02 实施卡](../implementation/work-items/L2-02.md)，以下保留影响架构决定的发现与取舍。

- **实例独立与授权独立分别判断。** 早期实验启动独立 app-server，却复用开发账号的 ChatGPT 登录；其中一次通过账户 Apps 操作了任务容器之外的目录。该轮不计隔离通过，不能把授权范围未收敛认定为容器逃逸。随后使用原生配置关闭未授权扩展，取得有限路径拒绝证据；不新增工具代理或监督 Agent，也不据此推断所有扩展或生产隔离已通过。程序、状态目录、认证和工具授权须分别说明，见[启动前提](../implementation/work-items/L2-02.md#实例配置与启动前提)。
- **直连和恢复复用原生协议。** Qwen 实验使用独立控制目录和 DashScope API key，不复制 ChatGPT 登录；沿用原生 provider 和工具模式，接受模型元数据、默认提示词与工具使用行为差异。控制重启暴露了只恢复 thread 而未重绑任务环境的接入遗漏，后续采用已有 `turn/start.environments` 修正并取得所测路径的拒绝证据。未增加模型网关、工具转发器或会话状态镜像，见[Qwen 直连记录](../implementation/work-items/L2-02.md#qwen-直连复验2026-11-25)。停止请求、轮次终态、原生终端清理与容器回收仍分别取证，有限修正不承诺所有进程形态或崩溃恢复。
- **以小型任务完成取代含糊的“模型行为一致”。** 此前核对未发现比较 GPT 工具顺序、代码结构或尝试次数的验收实现；问题是表述和归因混淆，不是已建成行动对齐系统。保留最终产物核查，允许预算内自主试错；原生 `completed`、成功退出或少量成功操作不能替代目标完成。图片输入、接入与生命周期缺口单独报告，主动停止实验不混入正常任务完成率。当前定义见[主验收](../implementation/work-items/L2-02.md#主验收约束内的自主任务完成)。

历史结果保持不变：旧三次 Qwen 初始任务未完成；随后明确600秒期限、图片工具用法及完成条件的三次正常任务仍未完成全部目标，均没有执行期人工补救，不以新条件覆盖旧记录。原始 Hi3D 一次对照在不同模型、配置和授权条件下完成小任务，但用户点击过权限确认，不能记为完全无人交互通过；一次成功也不能据以认定 Qwen 能力必然不足、迁移已无缺口或应新增质量返工循环。详情见[独立自主任务复验](../implementation/work-items/L2-02.md#明示条件后的独立自主任务复验2026-11-25)与[Hi3D 整体对照](../implementation/work-items/L2-02.md#原始-hi3d-整体对照2026-11-25)。

## 2026-11-25 阶段 A 范围收敛

在上述实验之后复核，源码没有真实动物质量评估、自动返工系统或产品发布实现；但实施卡同时展开阶段 B 产品接入、正式资产联合建设、L8 质量返工细则及持续布局诊断，容易使小型接入实验演变为完整建模质量工程。本次撤回这些超出阶段 A 的详细实施承诺，不将它们改名后保留为本阶段待办，也不因没有相关代码而继续保留含糊计划。

当前交付限于阶段 A 实验实现、必要机械测试、真实结果及接入决策所需的边界证据。产品适配器、公开接口、正式资产交接和领域质量机制须由后续明确条目另行规划；已有上层职责及 L0／L1 契约不因此废除。必要的小任务最终产物检查、真实图像反馈、授权与清理核对仍保留，否则无法回答所选组合能否自主完成已声明目标。

接受的代价是：阶段 A 可以形成对接入方向、限制和未决项的有据判断，却不能提供真实宠物质量、生产部署或正式交付承诺；已取得失败证据不因此改判为成功。后续补充实验只为解决能改变接入决定的明确疑点，不默认以该样例继续扩展质量研究、通用评测或外部返工控制循环。本次通过局部修订本 ADR 保留原有决策沿革，撤回详细后续计划；不增加新的 ADR、质量平台或过程管理机制。

## 受影响文档与后续验证

阶段 A 实施步骤、运行入口、实验完成条件和证据唯一维护在 [L2-02 实施卡](../implementation/work-items/L2-02.md)。核对原生 Agent 在宿主未代写方案或逐步补救时的自主任务结果，并区分反馈、连续性与实际运行边界；产品接口和后续建设不在此卡预先展开。2026-11-24 文档决定时尚未执行，2026-11-25 起的观察以该卡实际记录为准，本次范围收敛没有增加模型实验或通过结论。

[分层清单](../implementation/layers.md)同步 L2-02／03／04、L3 相关消费者、L4 原生与领域工具分工、L5 业务上下文接入和 L8 业务编排；[实施总纲](../implementation/README.md)同步装配、选型时点和里程碑，[模板](../implementation/work-item-template.md)不再默认要求执行内容追溯。L1-01、L2-01 等已完成卡仅更新后续交接解释，完成状态与历史证据保留。根导航链接本决定及当前实施卡，不新增重复规范或报告流程。
