# ADR 0012：复用原生 Agent 运行时，收敛执行适配职责

## 背景与问题

Vet3D 面向 BFF，正常建模链需要 Agent 自主编程、观察与预算内修订，不能依靠持续人工审查。已完成的 L0／L1 及 L2-01 提供业务契约、存储、资源、配置和有限环境探测，没有实现模型与工具循环，也没有接入不可信代码执行环境。

此前 L2-02 讨论主要按“执行请求 → 隔离后端 → 结果”组织；分层清单还要求 L2-03 保存输入／参数／脚本指纹，并在 L4、L5、L8 规划通用工具暴露、反馈与模型循环。任务关联、隔离与正式产物交接本有实际用途，但若由此推导每次工具操作的冻结、执行账本和统一转发，就会增加尚无消费者的协议与状态，并可能重新建设运行时已有的文件、图像、会话和进程机制。

Hi3D 的参考说明显示：原生命令、续读、图片工具与模型反馈循环来自运行内核，Skill、共享模块和会话生成脚本可以并存。仅复用底层命令执行不能证明这些能力仍可被 Agent 使用；将错误、输出和图片压缩成业务回执也不能保留建模反馈。该判断不表示 Hi3D 机制存在缺陷，更不表示未经实测的候选已失败。

用户在本轮进一步明确：当前 Agent 工程不要求固定代码和输入，也不要求字节追溯。因此此次撤销是需求调整，不以延后实现或改名替代。

## 决定与范围

1. **优先复用完整成熟运行时。** 由选定运行时承担唯一模型与工具循环，优先验证完整 Codex app-server 线程／轮次接入。其与 Hi3D 原生能力的来源接近，是优先验证的依据，不是生产选型或验收结论。OpenAI Agents SDK 若进入比较，应比较其完整 Agent／Runner 与沙箱能力，而非仅比较 `session.exec`。
2. **Vet3D 保留实际业务边界。** 负责任务目标、业务约束、授权配置、任务与原生会话关联、进度消费及正式产物交接；模型调用、原生工具分派、代码和文件操作、错误与输出、图像送入模型及会话继续优先沿用运行时。不在已有循环之外嵌套另一个规划和工具分发 Agent，也不默认创建通用 `ExecutionRequest → ExecutionBackend` 主入口。
3. **动态建模是正常运行方式。** Agent 可阅读 Skill／共享模块、检查模型、写改脚本、执行、读日志、看图及继续修订。动态脚本无需预发布、登记为固定工具或修改装配；稳定库可由脚本直接调用。原生反馈保留在模型循环内，BFF 摘要仅用于业务呈现。
4. **撤销 Agent 执行内容冻结与字节追溯。** 不要求代码冻结、输入快照、参数／脚本指纹或逐次精确内容复现，不转移至 L2-03 或后续待办。普通读取、编辑、预览和诊断沿用原生记录，不逐项建立业务 Job／Attempt。已有特定业务消费者的身份、幂等和恢复语义不推广为原生工具协议。
5. **保留独立用途的约束。** 授权隔离覆盖原生文件、命令、Blender 及子进程；资源限制、取消、回收和正式产物接收仍须实测。受管资源版本、安装摘要与正式资产完整性有现有消费者，继续有效，但不反向要求所有工具操作冻结。执行终态、产物接收、业务验收与发布分别判断。
6. **选型依据前移。** 在确定接入方式及公开接口前，先完成最小真实 Agent 的代码—日志—图片反馈与跨轮工作区接续验证。后续 L4／L5／L8 接领域工具、业务上下文与流程策略，不重复建设通用运行内核；完整领域质量和生产规模仍按后续范围验收。

## 考虑过的方案与取舍

| 方向 | 收益与成本 | 本次选择 |
| --- | --- | --- |
| 完整成熟运行时与原生工具 | 可复用模型循环、文件、执行、图片与会话；受其模型适配、协议版本、权限和部署方式约束，仍需验证完整环境。 | 优先方向；先验证完整 app-server 路线，允许据具体缺口调整候选。 |
| 仅复用 `command/exec` 或沙箱执行接口 | 可减少部分进程管理，但不包含完整模型工具循环、文件图片反馈及会话接续；作为主入口会留下大量接入工作。 | 不作为当前 Agent 主方案；只有独立确定性消费者确有需要时，才讨论对应局部接口。 |
| 自建执行管理、工具路由与反馈适配 | 可以完全控制协议，但须承担进程、输出、取消、恢复及模型反馈等长期成本，容易与既有运行时重复。 | 当前没有证据证明需要整体自建；只补验证后明确且必要的业务缺口。 |
| 固定脚本清单或每次脚本预登记 | 便于枚举入口，却限制动态组合，还引入发布与装配步骤。 | 不满足当前 Agent 动态编程需求；受管共享模块与临时脚本并存。 |

以上为职责和接入成本判断，不是候选性能、安全性或真实任务的实测排名。Codex app-server 的独立命令接口与完整线程工具执行也不能互相代替恢复证据。

## 接受的代价与后果

- 完整复用减少自研通用机制，但需要接受并验证运行时支持的模型协议、多模态输入、原生工具语义、版本变化、权限与部署限制；不承诺任意兼容网关均可直接使用。
- 取消执行内容冻结后，原生记录可能只保留命令、路径和输出，工作文件也会变化。当前能力不承诺逐次执行的精确内容复现，不以新增指纹或快照弥补这一已接受的范围选择。
- 会话历史可恢复不代表原进程可续接；轮次结束也不自动证明后台进程已经停止。真实恢复与生命周期由原生机制及隔离设施的实际能力决定，Vet3D 只保存必要业务关联，不镜像原生状态机。
- 不能只因工具是原生的就放开宿主权限，也不能只因服务端部署就默认替换原生工具。若无法满足授权、资源或反馈要求，须明确具体缺口及最小调整，不持续扩大适配层来维持某个候选。
- 最小真实 Agent 验证被提前，会更早需要明确实验模型连接、凭证来源与有限预算；这不是提前绑定生产模型，也不是提前完成整个 Agent 产品。

## 旧决定的局部修订

- [ADR 0006](0006-workspace-storage-and-execution-boundaries.md)：保留持久工作区、隔离环境、产物接收、并行与业务验收的分离。后续执行交接改为授权任务环境与原生工具，不解释为逐调用固定输入；原隔离候选比较保留为历史判断，当前先验证完整运行时接入。
- [ADR 0007](0007-managed-file-storage-boundaries.md)：保留固定授权根、无覆盖文件保存与正式文件完整性。其未来执行器的“固定输入”不再作为 Agent 内容冻结要求，后续按授权范围交接可变工作文件。
- [ADR 0011](0011-bounded-environment-probes.md)：已完成的受信探针和历史验证不变；后续实际环境复用已有检查定义，不按此探针实现推导自建通用执行器、第二套探测规则或持久进程管理。
