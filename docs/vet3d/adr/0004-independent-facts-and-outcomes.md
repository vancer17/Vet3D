# ADR 0004：独立事实与局部交接守卫

| 字段 | 内容 |
| --- | --- |
| 状态 | 已接受；实现与验证状态见 [L0-04](../implementation/work-items/L0-04.md)。 |
| 日期 | 2026-11-23。 |
| 范围 | L0-04 的状态、错误、事实所有权、操作关联和恢复边界。 |

## 背景

身份和内容契约已经交付，但记录存在不证明执行、验收或交付发生。Hi3D 固定版本材料显示：查询失败时可能仍有可信旧结果，版本文件可能先于元数据刷新落盘，加载超时后也可能收到有效确认，保存失败可能留下部分目标。

Vet3D 面向 BFF 的自主后端不应依赖持续人工审查。部署资格、资源配置或回包投影也不能反向决定业务动作。把所有阶段合成一个状态对象，既容易丢失部分副作用，也会产生靠测试维护的大量重复字段和非法组合。

## 决定与理由

1. 按事实所有者区分确认观察、诊断、检查结论和交接回执。需要不同数据的结果使用具体变体；稳定同形结论使用单一枚举，不另存同义标签和成功布尔值。
2. 允许真实存在的部分结果和不一致观察。守卫约束具体交接声明，不阻止记录“执行失败但文件存在”或“验收失败但候选已发布”。
3. 将已有身份、归属、目标和内容留在原权威类型。新增记录引用它们，不复制父链、预期摘要或验收证据集合。
4. 将等待期限、取消请求、查询失败和提交未确认与可信执行终态分开。没有可依赖的受理或幂等保证时，不从错误类型产生自动重交许可。
5. 本期发布、加载和保存只覆盖任务内发起的实际操作，使用已有作业及尝试关联。查询和重复通知不是新执行；无任务的独立桌面操作以后按真实消费者决定，不提前增加身份或兼容路径。
6. 报告完整性从固定契约要求和生产者声明单向计算；验收结果必须由生产者明确给出，守卫只验证必要声明和关联，不承担动物质量评审。
7. 纯契约不装配存储、执行器、BFF 或模型。真实事实产生、顺序判断、持久化和恢复留给对应服务；现有异常和 Demo 行为不统一包裹。

准确类型、字段、结果分支、错误和放行规则只在 [L0-04 实施卡](../implementation/work-items/L0-04.md)维护，本 ADR 不复制当前接口。

## 未采用的方案

| 方案 | 原因 |
| --- | --- |
| 一个含七组状态和大量可空字段的 TaskStatus | 各事实的对象、生产者和时间范围不同；总状态会掩盖未确认及部分副作用。 |
| 执行成功后自动将文件、报告、验收和发布置为成功 | 缺少独立证据，错误扩大了一个阶段的完成含义。 |
| 把阶段间不一致一律判为非法组合 | 会拒绝真实失败残留和已登记候选，破坏诊断与恢复。 |
| 全局 retryable、recoverable 或 safe_to_resubmit 字段 | 重交需要真实幂等、受理事实和业务预算；静态分类无法提供这些保证。 |
| 新建一套发布、加载及保存操作身份 | 当前任务内实际执行可以复用既有身份；无任务消费者尚未实现，不为假设中的场景扩大范围。 |
| 为所有观察强制创建作业和尝试 | 文件观察、报告声明和验收各有自己的对象，不应为了使用契约而伪造执行关系。 |
| 将内容登记/发布绑定完整业务验收 | 候选和诊断仍需要留存；最终合格交付由业务用途和策略约束。 |
| 把原有异常改成统一 Result 并增加兼容开关 | 当前没有外部旧消费者或持久状态需要迁移，只会制造两套内部表示。 |
| 本项建立完整恢复服务、BFF Schema 或验收策略引擎 | 超出公共语义范围，并会提前绑定尚未选定的存储、服务和模型。 |

## 后果与限制

消费者必须明确自己需要哪项事实，不能只读取一个总成功标记。报告和验收的要求、实际声明可以不同；当前匹配由具体守卫决定，不把要求写成另一份可任意切换的环境配置。

生产者声明并不是本包实际完成观察的证明。调用方负责提供有依据的结果、先后顺序、正确组件范围及冻结业务契约；真实集成必须在对应层验收。

普通 RGB 动物质量、模型语义、多轮收敛和受预算约束的自动修订仍待实际模型及动物样本验证。没有真实接收端回执时，后端只能交付可追溯资产引用，不能声称用户已经保存文件。
