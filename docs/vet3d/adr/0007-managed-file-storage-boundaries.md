# ADR 0007：固定范围的文件保存与登记分离

| 字段 | 内容 |
| --- | --- |
| 状态 | 已接受并用于本项实现；第 6 项的后续固定执行输入要求由 [ADR 0012](0012-native-agent-runtime-integration.md)撤销。实际契约和验证状态见 [L1-02](../implementation/work-items/L1-02.md)。 |
| 日期 | 2026-11-23。 |
| 范围 | 在 L1-01 基础上建立真实字节保存和观察，不前移 L1-04 的资产数据库、导入账本及版本提交。 |

## 背景

L0 已有产物身份、内容指纹、相对位置、出处及文件观察，L1-01 已有真实工作区登记。现有 ArtifactAccess 同时表达登记解析和文件观察，但真实产物索引尚未实现。若因为需要读写文件就直接扫描目录生成登记记录，会混淆“字节存在”和“业务登记”；若新增一个侧车数据库，又会在后续持久化条目之外提前创造另一处权威事实。

Vet3D 面向 BFF，普通业务应自主完成。文件输入不能照搬桌面进程接收任意用户路径的模型，也不应借频繁人工确认补足范围约束。Hi3D [素材接入](../../hi3d/infrastructure/workspace/import-reference-materials.md)保留原件并独占写入，[产物登记](../../hi3d/infrastructure/workspace/register-file-artifact.md)在消费时复核路径和摘要；这些机制值得借鉴，登记模型、Windows 路径和桌面授权不直接移植。

## 决定与理由

1. **只交付字节保存和真实观察。** 使用现有产物关联与 FileObservation，不增加 FileState、StoredArtifact、OriginalFlag 或新的内容身份。实际文件结果可以被后续持久化消费者记录；它本身不构成登记回执。现有 ArtifactAccess.resolve 不变，也不增加返回伪成功的生产空壳。
2. **固定范围由可信装配建立。** 工作区、输入暂存根及单文件限额在装配时固定，请求只引用已知产物和输入单文件名。输入路径、内容出处和工作区身份是不同概念；不让来源标签变成读文件能力。这样能接入后续 BFF 上传暂存，同时不预先建设 HTTP 协议或多租户权限框架。
3. **低层借用普通文件，高层拥有句柄生命周期。** 低层从打开的普通文件描述符读取，不依赖当前游标；异步宿主在实际工作线程打开和关闭源。等待取消可能早于实际复制终结，若让调用者的短期文件上下文持有唯一源句柄，容易在取消后提前关闭正在使用的资源。
4. **目标由产物身份确定并禁止覆盖。** 不将用户显示名、扩展名、MIME 或摘要作为路径唯一键；相同名称和相同内容都可以属于不同产物。文件提交使用 Linux 的无覆盖原语，不能以“先检查目标不存在，再允许覆盖式重命名”替代最后一次原子拒绝覆盖，也不回退为源文件硬链接。
5. **临时名不进入业务身份。** 技术随机名仅解决复制中的独占写入；它不是导入 ID、版本或运行状态。没有产物账本时，不认领残留、不自动续传，不从 UUID 文件名反推曾登记的内容。新进程只能用调用者保留的原引用重观察。
6. **保护目标但不宣称沙箱成立。** 私有目录、只读最终文件、描述符访问和访问中属性核对缩小误操作及替换窗口；它们依赖受信服务管理，不抵御能改权或改写目录的同权限主体。当时要求未来执行器取得独立权限下的最小固定输入，不能直接获得整个工作区文件服务；其中固定执行输入要求已由 [ADR 0012](0012-native-agent-runtime-integration.md)撤销，最小授权和正式存储保护仍有效。
7. **复用现有单根所有者。** 文件存储沿用根写入所有权和专用线程，不在同一根上再创建竞争宿主，不把存储准入扩张为模型执行调度。取消等待不会反向改变业务内容身份或文件提交条件。

Linux man-pages 的 `rename(2)` 说明普通重命名允许覆盖已有目标，而 `RENAME_NOREPLACE` 在目标存在时返回错误，并要求底层文件系统支持；这是选择明确无覆盖原语、拒绝静默降级的依据。[rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html) 文件 fsync 并不单独保证包含该文件的目录项已同步，需要对目录描述符另行同步；这也是将文件提交可见与完整同步回执分开的原因，不能从一次进程中断测试推导任意断电保证。[fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html)

## 未采用的方案

| 方案 | 未采用原因 |
| --- | --- |
| 为完成真实读取，在本项增加完整产物表、导入状态机和历史绑定 | 超过当前条目；已有 L1-04 承担持久登记和恢复，不通过提前扩展掩盖边界。 |
| 用旁置 JSON／目录扫描实现 resolve | 形成隐式第二仓储，或把陌生字节自动认领为登记记录。 |
| 将现有 ArtifactAccess 直接改成同步文件读写接口 | 它已有异步消费者，登记与观察语义仍有效；新增窄文件 I/O 边界不需要破坏该契约。 |
| 同内容重放 store_new 自动返回成功 | 没有持久意图与历史绑定时无法等同于同一次导入，显式观察更准确。 |
| 复制前 realpath 一次，此后按可变字符串重开 | 预检不保证实际读取仍指向同一对象，实际访问要在受管描述符边界核对。 |
| 直接使用来源字符串、允许请求更改暂存根或任意子树 | 在服务端授予过宽的读取权限，与业务来源说明无关。 |
| 自动按图片后缀压缩、生成预览或修改 EXIF | 修改原件并跨入图像处理／业务验收，不属于字节存储。 |
| 为未来平台或架构加入多个存储模式开关 | 当前没有真实消费者或迁移要求；支持其他平台时在适配层独立选型验证。 |

## 后果与后续决定

本项能产生实际字节观察，但在 L1-04 接通之前，没有完整产物生命周期。调用者必须保留原关联与预期指纹；丢失后不能靠文件存在恢复业务身份。执行产物接收、发布和 BFF 授权继续由对应条目实现，首次开放不可信代码仍受 [L1-01 的联合放行条件](../implementation/work-items/L1-01.md#开放不可信执行的必需条件)约束。

当前仅采用 Debian／Linux 路线。OS 无覆盖提交原语不可用时明确失败，不暗中换成更宽松行为；本轮实际环境与失败验证由 L1-02 维护。存储平台、供应商、Agent SDK 和用户 API 没有因此被静默选定。
