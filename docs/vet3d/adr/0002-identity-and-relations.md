# ADR 0002：独立身份类型与显式关联

| 字段 | 内容 |
| --- | --- |
| 状态 | 已接受；实现与验证状态由 [L0-02](../implementation/work-items/L0-02.md)维护。 |
| 日期 | 2026-11-23。 |
| 范围 | L0-02 的身份类型、关联边界、校验职责及公开包归属。 |

## 背景

L0-01 已经提供独立应用入口和显式装配。接下来各层需要用稳定身份关联工作区、任务、可选会话、产物、模型版本、执行与验收依据；日志关联串、显示名称、文件路径或供应商 ID 不能自动承担这些不同职责。

Vet3D 面向供 BFF 调用的自主后端。业务任务可以在没有会话时成立；后续接入 LLM 时，也不能把用户消息、模型采样、工具调用或供应商线程当成同一个概念。原件、派生文件与执行结果需要明确来源关系，缺失某条关系则保留证据缺口。

Hi3D 的固定版本分析提供了可借鉴的归属、文件对账和原作业续查机制，也揭示了文件名编号、登记重复和桌面缓存的边界。这些证据支持划分职责，不决定 Vet3D 的类型或字段。

## 决定

1. 建立范围受限的 `identity` 包，用具体、冻结的 UUID4 身份类型表达不同概念。UUID 由调用边界提供；本项不建立生成服务、序号分配器或跨进程唯一性服务。
2. 把身份与已知关系分别表达。工作区作为任务及资产归属范围；会话可选，业务任务不依赖人工交互。文件集合与模型版本使用明确的目标类型，不采用无约束的 `kind + id` 组合。
3. 将已知派生关系与执行产出关系分开，避免从“由什么产生”自动推导“经过哪次执行”，或反向推导。完整文件来源、内容版本及摘要规则由 L0-03 继续定义。
4. 证据观察对象与验收对象显式关联；记录存在或引用了证据，不等于验收通过。本项不建立质量状态、阈值、自动验收策略或失败重试机制。
5. 使用纯同步校验检查调用方提供的数据。稳定类型与校验逻辑直接使用具体实现，不新增 Protocol、存储适配器、数据库模型或日志初始化。
6. 通过 `vet3d.identity` 公共导出供后续消费者使用，保持 L0-01 演示契约及行为不变。HTTP 输入、供应商映射、业务状态和持久化机制在对应条目实施。

当前类型、字段、关联约束与错误语义只在 [L0-02 实施卡](../implementation/work-items/L0-02.md)维护；本 ADR 记录选择及原因，不复制接口定义。

## 评估过的替代方案

| 替代方案 | 本次未采用的原因 |
| --- | --- |
| 全部使用裸字符串，靠变量名区分身份 | 不同概念可以被误传，运行时缺少明确边界；类型名无法承担实际校验。 |
| 通用 ID 对象加可任意组合的类型标签 | 容易把未知标签、错误配对和分支处理散落到消费者；当前稳定概念可以直接使用具体类型。 |
| 名称、路径、内容摘要或供应商引用直接作为内部身份 | 同名、迁移、重复导入、内容相同及供应商变化具有不同语义；这些属性与关系不应反向决定业务身份。 |
| 所有任务必须从会话或人工消息开始 | 会使自主后端依赖交互形态，并混淆任务、会话和模型执行轮次。 |
| 把原件和派生件设为互斥身份类别 | 缺少来源边并不能证明是原件；一个产物还可能参与后续派生。显式关系能保留已知事实和缺口。 |
| 用一次执行或单个文件概括全部验收对象 | 检查可能针对尚未发布的多个产物，也可能针对完整模型版本；任务成功不能代表这些对象的质量。 |
| 同时接入仓储、完整状态机、来源清单和 ID 生成服务 | 超出 L0-02 的身份与关联职责，并预先决定后续存储、状态及文件接口。本项先验证无外部依赖的关系语义。 |
| 为已有 Demo 请求追加身份字段以展示集成 | Demo 仍只承担装配验证，追加无实际消费者的字段会混淆演示协议与产品 API。 |

## 后果与边界

消费者必须明确区分身份及关联，并为校验提供相关记录。成功校验只说明提交的关联满足本项规则，不证明文件存在、来源真实、外部对象可访问、执行已发生或质量合格。

本项不自动补齐缺失关系，也不依据零条派生边或产出边补造原件、未执行等结论。已知事实的完整度、内容证据及后续状态变化由拥有这些事实的服务继续维护。

具体冻结类型与同步校验可以独立测试；生成 UUID、解析请求、持久化、鉴权、并发和恢复仍由实际调用及存储边界负责。采用 UUID4 不代表已经建立这些机制。后续扩展共享内容必须有实际消费者，避免把 `identity` 演变成全局业务对象容器。
