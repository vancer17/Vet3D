# ADR 0010：统一配置、有限诊断与两套 Docker 编排

| 字段 | 内容 |
| --- | --- |
| 状态 | 已接受并实施；当前契约和验收由 [L1-05](../implementation/work-items/L1-05.md)维护。 |
| 日期 | 2026-11-24。 |
| 范围 | 环境配置、现有基础设施装配、诊断存储和 Docker 打包。 |

## 背景与决定

L1-01～04 已有真实存储和端口，但宿主仍逐项传入路径和预算，日志仅由有限 CLI 同步输出。下一层需要可追溯的环境声明与关联诊断。Vet3D 面向 BFF 自主执行，不能让部署资格、资源限额或日志是否完整决定业务动作和发布结果。

用户明确选择 pydantic-settings 统一环境变量、dotenv 与 YAML，并要求 Docker 默认托管、根目录 docker/ 集中维护且仅保留开发／生产两套编排。此前候选中的标准库 TOML 解析没有实施，本决定取代该建议；不保留两套配置入口。

1. 使用标准来源合并，不手动把 YAML 字典当最高优先级构造参数。每次加载固定来源文件，冻结其路径和部署预算；复用现有 ResourceLimits 与唯一 DiagnosticLimits，避免复制模型后测试防漂移。尚无消费者的供应商凭据、业务能力开关和热更新不预建。
2. Settings 只留在 Bootstrap，Operations 拥有可替换的诊断读取契约，适配器负责文件。稳定装配直接实现，不增加插件注册表或万能宿主端口。环境值不反向定义动作参数、能力枚举、验收或发布条件。
3. 选择单写入者、有界 JSONL 和有限队列，满足当前按身份读取保留窗口的消费者。日志输出错误显式交给 Operations，同时避免在提交之前由日志异常阻断业务。诊断不是业务审计，不复制任务状态，也不建立执行恢复账本。
4. 真实文件 I/O 在后台线程，关闭保持所有权直到实际工作结束。应用文件与 Docker stdout/stderr 各自只有一个轮转者。使用现有 Unix 文件安全原语，不将私有目录当作不可信代码沙箱。
5. 一份 Dockerfile、两个构建阶段和两套 Compose 足以覆盖当前开发与运行。生产安装 wheel、非 root 用户，明确绑定目录所有权；不在启动时递归修复未知数据。镜像身份和资源限制由部署管理，不进入业务策略。
6. 当前只有有限宿主，新增有限装配探针以消费真实配置与存储。没有真实 BFF 入口时不创建假健康接口或睡眠循环；未来常驻服务在对应条目接入真实生命周期。

## 未采用的扩展与后果

| 候选 | 原因与触发条件 |
| --- | --- |
| 自建配置平台、多格式框架、动态配置中心 | 标准来源已经满足当前消费者；未来实际部署需求出现后另评估。 |
| 配置化业务能力和发布资格、dev/prod 业务模式 | 环境只能影响资源供给，业务契约由内核和输入 Schema 定义。 |
| 数据库日志、分布式追踪、全量审计及多进程共享轮转 | 当前只需单实例有限诊断；真实多副本或外部收集需求出现时替换读取／输出适配。 |
| 日志全内容扫描或重复脱敏框架 | 本期无供应商凭据输入；不转储 Settings 和任意对象即可覆盖实际输出，敏感字段按真实接入处理。 |
| 第三套 Compose、平行 deploy/、集群部署 | 用户明确限定两套编排；不会为了复用少量参数建立部署框架。 |
| 把应用容器用作动态脚本沙箱 | 应用持有存储及运行配置，目录和容器配置不能证明任意代码隔离；继续遵循 L1-01 交接。 |
| 跨根事务、自动初始化修复、日志驱动业务恢复 | 当前消费者不需要；保留部分实际结果并使用原入口核对，不预建恢复子系统。 |

代价是单实例诊断根不能由多个进程同时写入，保留窗口和进程内故障计数不构成完整历史；强制终止可能丢失记录。任何更强恢复或生产可用性结论须由后续真实消费者与实测支撑。

## 依据

Hi3D 的[配置模板](../../hi3d/resources/codex-config-template.md)和[阶段计时](../../hi3d/resources/stage-timing.md)提供职责分离参考，不能证明 Debian 服务端权限或并发保障。

官方 [pydantic-settings 文档](https://docs.pydantic.dev/latest/concepts/pydantic_settings/)说明 YAML 标准来源和自定义来源顺序；本次锁定版本的真实来源合并由配置测试确认。[Python 日志文档](https://docs.python.org/3.14/library/logging.handlers.html#queuehandler)的默认队列错误与停止行为不足以直接代表本项损失可见和取消后排空语义，因此实际生命周期显式维护。[Docker Compose 环境插值](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)与应用 dotenv 是不同入口；[Docker local 驱动](https://docs.docker.com/engine/logging/drivers/local/)提供独立容器输出轮转，不能替代按工作区读取的应用诊断。
