# ADR 0005：分开五向准备与单次生成输入，按消费方建立最小端口

| 字段 | 内容 |
| --- | --- |
| 状态 | 已接受；实施与验证状态见 [L0-05](../implementation/work-items/L0-05.md)。 |
| 日期 | 2026-11-23。 |
| 范围 | 修订 ADR 0003 的五向参与假设，建立 L0-05 首条生成交接所需端口与装配。 |

## 背景与依据

用户明确：首期处理前、后、左、右、顶五向，不要求底视，也不要求用户上传完整五向照片；后续 Agent 根据已有材料准备所需视图。Vet3D 是面向 BFF 的后端，正常路线选择与候选审查由受控策略完成，不要求持续人工确认。

ADR 0003 及原 L0-03 将必需方向定义为必须参与重建，并要求全部出现在重建输入中。将这一要求直接复用为单次模型调用门槛，会排除只接收四图或单图的接口。此次明确修订该业务语义，不通过绕过校验器或改变环境配置实现。

用户提供的《3D 生成模型 API 接入文档总览》及分册（2026-11-23，仓库外资料）描述了以下差异：主图与具名附图、固定方向槽位、重复表单与位图、有序图像列表、首图用于正面或材质，以及尚未说明完整方向编码的托管接口。这些资料只做过静态核查，未证明真实调用或动物质量。它们不是仓库运行依赖，也不是当前供应商能力注册表。

对应公开文档入口包括 [Hunyuan Pro](https://cloud.tencent.com/document/api/1804/123447)、[Tripo 多视图](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard)、[Hi3D](https://docs.hi3d.ai/en/api/getting-started/introduction)、[Meshy](https://docs.meshy.ai/en/api)、[Rodin](https://docs.hyper3d.ai/en/get-started/quick-start)。未来实现具体网关时应按目标端点、API 版本和模型版本重新核实，不能把这些设计资料当成已完成集成。

## 决定

1. **任务准备与调用选图分开。** 任务拥有主体基准、必保要求及五向准备目标；一次生成拥有具体有序选择，首项为本次操作主参考。选择引用准备图身份，方向从准备记录单向解析。未被选择的图仍在原准备集合中，不额外存一份“忽略视图”或参与标志。
2. **直接修订现有局部契约。** 原五向重建字段和类型改为准备语义。当前仓库只有契约测试消费这些旧名称，没有已知产品消费者或持久数据要求兼容，因此不保留别名、旧模式或双套枚举。变更后的权威定义见 [L0-03](../implementation/work-items/L0-03.md)。
3. **匹配针对具体调用计划。** 适配器检查能否表达整个计划，不能静默丢图或改主参考。计划不匹配并不直接宣判整个任务失败；未来领域策略可明确选择其他组合或路线，但不得降低任务验收标准。未知适配规则与已知不匹配分开。首期不建立品牌级最大图数配置或通用规则语言。
4. **只建立实际消费的端口。** 文件访问归 artifacts；生成语义归 modeling；生成用例记录仓储归 application。通用 execution 只维护执行事实及取消回执，不反向依赖建模请求。具体实现由 Bootstrap 注入，并显式继承 Protocol。
5. **登记意图与外部受理分开。** 首次原子登记才取得一次提交权；登记后出现异常、取消或结果保存失败都不能重新取得提交权。旧尝试未知、活动或成功时，不能通过同作业的新尝试绕过守卫；只有旧尝试全部确认失败或取消后，调用方才可显式登记相同意图的新尝试。该先决条件不批准自动重试或成本预算，原尝试查询也不生成新身份。请求冻结文件内容引用，真实上传时仍需再次核对实际字节。
6. **取消回执独立于执行观察。** 取消请求已受理不表示执行已取消；不支持发送取消则明确拒绝该动作。最终结果仍由查询原执行得到的可信观察决定。
7. **替身验证真实装配和内存读写。** 两个具体替身分别接收五图、四图计划，消费代码保持相同。内存仓储保留独立观察、最新历史诊断与取消回执，不用诊断覆盖执行状态。保存不明时保留原意图和可获得的事件。

## 未采用的方案

| 方案 | 原因 |
| --- | --- |
| 所有模型都必须一次接收五图 | 把业务准备目标绑定到供应商单次输入上，排除实际可用的输入形态。 |
| 网关自行删掉顶图让请求通过 | 掩盖真正提交内容，无法追溯未使用的视图与选择原因。 |
| 放弃五向准备或让资源配置改任务要求 | 部署能力反向定义业务标准，不符合当前产品决定。 |
| 为各供应商建立 OpenAI 兼容请求或通用参数字典 | 当前所需的是图像语义与原任务交接，供应商传输格式不具有统一依据。 |
| 再增加 mode、计数、参与标志与兼容投影 | 可以从准备集合、实际选择和既有执行事实确定性派生，重复表示会扩大非法组合。 |
| 通用执行仓储直接导入建模输入 | 造成下层事实包反向依赖专属业务；由当前消费用例拥有窄仓储端口即可。 |
| 预建资源、脚本、LLM、视觉状态等全部空端口 | 没有具体消费者和验证，容易形成悬空接口；随对应条目建立。 |
| 当前引入数据库、调度器和供应商网关服务 | 超出 L0 骨架范围，不能用内存测试证明持久恢复和真实调用。 |

## 后果与待办

本次允许下游依赖经过验证的最小契约和装配，不宣称已具备视图补全、自动路线规划或质量评审。合成视图不是原始观测，文件引用不是文件已下载，供应商返回成功不是业务验收通过。

真实网关必须固定实际使用的接口与模型，并保存足以恢复原任务的供应商关联。新的适配器实例若缺少绑定，必须返回不可查询，不能重新提交来冒充恢复。持久化、跨进程并发、文件读取安全、真实上传、成本预算及自动修订仍由后续条目承担。

上层可以使用本项表达单图计划；是否将单图纳入产品自动路线、如何选择四图、如何完成五向补全及评价缺乏观测的部位，由 L6–L8 依据实际模型验证决定。本项不引入开关代替这些领域规则。
