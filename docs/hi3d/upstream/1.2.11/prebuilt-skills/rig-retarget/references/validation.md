# 绑定与动作验收

在与输入分离的候选中验证，最后重新打开实际保存的工程。记录原始模型、服务 GLB、源动作、缓存、配置和候选的身份；不把候选保存成功或进程 exit 0 等同于业务通过。

## 不变量与动作范围

- 纯骨轴/动作修改：原静止网格坐标、顶点/面索引、面角 UV、材质及打包贴图、权重与 shape keys 保持。既有文件/其他角色/未选动作不覆盖。rig_adapter 自动比较几何/UV/材质槽/权重/shape keys/对象局部变换/父级关系与图片内容；不声称覆盖任意节点图/驱动。
- 局部权重修改：仅目标皮肤域改变、非骨骼组保留；检查非负、归一化、未绑定点和皮肤接缝。模型包含独立壳体时按语义分域，不能统一完全重合但不相连的衣层。
- 骨轴校准保留关节头，记录新旧 rest 指纹。原曲线对应旧 rest 时重新烘焙，不只改显示骨尾。
- 核对真实 fps、Action/NLA、首末帧及实际求值变形；先烘焙 Action 再建 NLA。新非循环动作检查全部整数帧，循环检查完整周期及拼接姿态/速度。抽查用于定位，不能把抽查报告叫全帧通过。

## 数值与视觉

单高模/任意骨名用 `service_rig inspect`，准备过的三角部件集合用 `validate_blend`；两者共享 `skin_weights.stretch_metrics`。前者只读三角化多边形，后者要求三角网格，均要求求值后索引对应。Solidify/动态拓扑等需另建求值静止基准，不能用旧索引强行比较。

```bash
"$BLENDER" --background --factory-startup --python-exit-code 1 \
  --python "$SKILL_DIR/scripts/run.py" -- service_rig inspect \
  --input "$RUN_DIR/candidate.blend" --body "$BODY" \
  --frames "$START:$END" --height "$HEIGHT_IN_MESH_UNITS" \
  --report "$RUN_DIR/full-range.json"
```

范围包含两端。检查时启用骨架、皮肤和 Armature 修改器视口求值；`motion_observed:false` 不能宣称动画通过。发现拉伸仍保存报告并非零退出，输入前提失败则停止，不能用旧报告代替。

保留原阈值：边长倍率 >3 且增加 >H/120；双面积倍率 >8 且增加 >H²/81000。H 与静止网格使用相同单位。极短边/针状面的大倍率需同时看绝对位移；报告原始最大值和严重异常，不靠删面、细分或放宽阈值变绿。修前修后用同动作/帧范围/阈值；平滑扩大异常时撤回并重新归因。

视口检查肩腋、掌腕、逐指、髋膝、跨步与抬腿、脚底滑动和穿插。手指要能独立运动，不能以整掌转动代替；掌面/指根应清晰可见，遮挡时换机位。脚高修正不能证明地面脚锁，腿链求解的可达误差应与模型尺度和实际接触一起判断。数值检查不证明衣物碰撞、连续时间无穿插或自然动作；必要时检查半帧/接触切换。

用户不渲染时只用视口和数值检查。需要图像时来自最终候选并带文件身份/帧号，不能把原源动作视频或旧版本画面作为本角色通过证据。头发和布料物理未制作时直接说明，不从身体动作推断已完成次级运动。

## 高模与加速边界

对百万顶点模型按实际组成员读取权重，避免逐骨重复扫描整个网格；评估缓存/权重表内存。分块、向量化或自定义 GPU 计算可以加速，但必须包含最终高模全拓扑和实际帧范围。

自行实现蒙皮加速器前，确认修改器实际采用线性或保体积双四元数、对象/骨架空间、顶点组、额外修改器与求值可见性。双四元数须保留每个顶点的实际成员遍历顺序，并按对应 Blender 实现的累计旋转符号选择半球，不能排序后假定结果不变。在多个普通与极端姿态和修复区域对照 Blender 求值坐标，记录最大误差；不匹配即停用加速器。此为加速实现验收契约，本包未捆绑某平台的 GPU 扫描器。

## 交付状态

区分结构保护通过、已检查的数值通过、视口审看、导出/引擎回读。数值不通过时列出失败帧/部位、阈值、修复与残留问题，不能称完全适配；保留最佳候选供审看。修改绑定/动作后旧检查失效，重新检查受影响范围。

目标为游戏 GLB 时还要用其实际线性蒙皮/影响数/导入器回读，不能以 Blender 保体积结果代替。单纯 Blender 交付不自动追加引擎、LOD、布料、渲染或导出任务。记录按 [阶段计时](timing.md)随产物交付。
