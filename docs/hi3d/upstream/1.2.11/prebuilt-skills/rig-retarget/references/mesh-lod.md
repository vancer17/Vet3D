# LOD 减面与动画交接

## 推荐方法与边界

带纹理角色需要降低动画网格面数时，优先通过独立 `$mdf-call` 调用 `mesh-lod`。它在减面时强制启用严格自交保护，并重烘纹理/法线，适合保留高模表面细节。该保护针对减面过程；不修复输入已有的全部自交，也不保证蒙皮后身体、衣物或角色之间无穿模。最终仍按 [验收](validation.md) 检查动作和接触。

已有合格 LOD 时直接复用。用户明确选择本地离线或临时预览减面时，可使用 `prepare_mesh --faces` 的 Blender Decimate，但须说明它没有上述严格自交保护，不作为等价替代；远端不可用时不静默切换。面数、角色数量、贴图预算和是否渲染沿用本次任务，下面的 100 万面仅为调用示例。

## 显式提供依赖

需要实际调用时，另外提供完整 `mdf-call/` 文件夹（本仓库源码位置 `tools/mdf-call/`），安装到宿主技能目录或由上下文显式给出路径并读取其 `SKILL.md`。`MDF_DIR` 指该包的实际目录，`SKILL_DIR` 指本 rig-retarget 包，`RUN_DIR` 指包外业务目录。无需复制整个仓库，不从相邻目录导入客户端；缺少依赖时说明所需工具或已有 LOD 输入，继续可独立完成的阶段。

文件型调用默认使用 mdf-call 的 HTTP 中控，无需完整 SDK 或 worker 回连本机；仅显式 SDK 模式使用 ServiceInvokeSession、队列配置和回连网络。两者均须有可信可达的 mesh-lod 部署，入口、配置与超时沿用工具说明，不使用 Hi3D AK/SK。完整服务契约由当前环境另行提供；需要查完整字段时可显式提供独立 service-select 包并读取其 `references/mdf/mesh-lod.md`，不以仓库相邻文件作为隐式运行依赖。

## 输入、调用与产物

1. 保留原始带纹理 GLB，以单角色静止姿态网格为输入。已有绑定工程优先使用与骨架休止姿态匹配的原始模型；不能把当前舞蹈姿态烘成新的 rest mesh，也不上传整座舞台或无关资产。记录输入内容摘要、实际坐标变换和本次目标面数。
2. 在 `RUN_DIR/lod-request.json` 写业务参数，`$file` 相对该 JSON 所在目录解析。仅引用已授权的模型。最小示例：

   ```json
   {
     "input_mesh_glb": {"$file": "original.glb"},
     "target_face_num_list": [1000000],
     "simplify_self_intersection": true
   }
   ```

   显式使用正整数目标列表；服务拒绝关闭自交保护。不把本地 API 的 `output_dir`、`overwrite` 或 `max_ray_distance` 塞进 MDF 参数。未指定的烘焙设置按已核对部署契约处理；如需改变贴图预算，先确认 `normal_map_resolution_ratio`、`normal_map_max_long_edge` 等真实字段和任务规格。
3. 先运行本地预检和配置检查，再在已有业务授权范围内单次提交：

   ```bash
   "$PYTHON" "$MDF_DIR/scripts/check_runtime.py"
   "$PYTHON" "$MDF_DIR/scripts/mdf_endpoint.py"
   "$PYTHON" "$MDF_DIR/scripts/mdf_call.py" \
     --service mesh-lod --input "$RUN_DIR/lod-request.json" \
     --run-dir "$RUN_DIR/lod-call"
   ```

   输出目录必须不存在。超时预算应覆盖当前部署的排队和烘焙时间；超时或断连后保留原 trace 和调用目录，核对原请求，不换目录盲目重提。维护本工作流时只做离线验证，不调用线上服务。
4. 业务成功条件为 `success` 严格等于布尔 `true`，本服务不返回 `status`。通过 `invocation.json` 的 `files` 列表定位 `field_path == ["mesh_lod_glbs", "1000000"]` 对应的文件，路径相对调用目录下的 `artifacts/`；多目标按各自目标字符串查找，不猜序号或文件名。元数据位于响应的 `mesh_lod_metadata`，区分 `requested_faces`、`actual_faces` 和 `skipped`。CLI 的 `result.summary.json` 是有长度限制的脱敏摘要；缺失字段不能凭猜测补齐，需完整元数据时复用工具适配器保存必要业务字段。
5. 核实返回 GLB 可解析、目标产物齐全、贴图/法线实际存在，再记录实际三角面数和文件摘要。目标预算不保证恰好等于最终面数，Blender 导入还可能剔除退化面。不能把 CLI 成功或 GLB 非空等同于动画验收。

## 准备与替换网格

新身体绑定推荐将已核实的 LOD 交给 [auto-rig 流程](service-rig.md)，已有绑定直接保留。选择本地校准/图求权重时交给 `prepare_mesh --input`，**省略 `--faces`**，避免重复 Decimate。依据模型设置身高与旋转；LOD 重烘可能改变 UV 和顶点布局，保留返回模型的面角 UV、材质和法线贴图，不按旧索引复制原 UV。

本地求权重路径在统一空间后，按同一连续皮肤域焊接、求权重、最后拆件。`prepare_mesh` 会合并输入中的全部 Mesh 并按距离焊接，不识别衣物语义；不同衣物层、相接壳体或需独立变换的部件，应由执行者按 [几何与绑定](geometry-and-binding.md) 分域处理，不能把自动焊接当作安全语义分割。焊接后检查新自交、接缝和有效面数，服务保护不覆盖后续任意拓扑修改。

已有绑定工程替换网格时另存候选，保留原骨架、rest 变换、Action/NLA、帧范围、fps、相机、灯光及舞台。不要在该工程直接运行会清空场景的 `prepare_mesh`；在独立准备工程中处理，再按已记录变换对齐到原角色空间，不能按舞蹈姿态重新居中或归一化。

LOD 顶点索引、UV 与拓扑已变化，旧索引权重、语义标签、布料/形变缓存和验收基准不能直接复用。由执行者在同一休止空间按连续表面与部件语义转移权重，或在最终拓扑重算；最近表面匹配须限制同侧肢体和相应衣物层，不能跨腿、跨衣层。`service_rig bind` 仅处理单服务皮肤到未绑定目标的回迁；已有绑定的 LOD 替换仍需按上述骨架、空间和语义约束单独处理。检查权重归一化、未绑定点、共享皮肤接缝，并恢复已校准的面部刚性区域、关节过渡等约束；用户要求面部刚性时保持该区域头骨 100% 权重，并确认其他修改器不再使其形变。不能将刚性面部固化为所有角色默认配置。

## 验收与记录

在重开的候选工程核对骨架和舞台不变量，按新静止拓扑建立数值基准，再检查全段动作、深屈关节、脸部和衣物接触；采样三角相交检查不证明连续时间无穿模。对比中性光与既有舞台光下的材质、UV 接缝、法线、轮廓及黑点；用户未要求渲染时使用视口，不新增渲染任务。

随业务产物记录原始与 LOD 文件摘要、请求/返回/导入面数、坐标与权重交接、实际检查范围及未解决问题。LOD 调用/排队等待和本地准备/绑定/验收分别按入口的阶段统计要求计时，服务计算耗时有来源才另列；返回 LOD、元数据及报告留在包外任务目录，不写回 skill。
